# Brief 06 · Decoding & the KV cache

- File: `pages/06-decoding-kv-cache.html` · Part I · Foundations · P0 · ~55 min · body 5,000–7,500 words
- Prereqs: 01, 03, 04. Drill module names: `sampling` and `kv_cache`

## Purpose
Everything about turning a trained model into text: decoding strategies (a staple of
interviews), the KV cache mechanics, and the performance model of inference (prefill vs
decode, why decode is memory-bound, latency vs throughput). Page 07 goes deep on shrinking the
cache and page 17 on serving systems; this page builds the foundations they rely on.

## Must cover
1. **The generation loop**: prompt → prefill → repeated (forward one token → logits →
   choose next token → append) until EOS, stop sequence or max length. Chinese: 解码, 采样,
   键值缓存, 预填充.
2. **Decoding strategies** with math and code:
   - Greedy; why it produces repetitive, degenerate text for open-ended generation
     (Holtzman et al. 2019).
   - **Temperature**: \(p_i \propto \exp(z_i/\tau)\); limits \(\tau \to 0\) and \(\tau \to \infty\).
   - **Top-k**, **top-p / nucleus** (Holtzman et al.: smallest set with cumulative
     probability ≥ p), **min-p** (Nguyen et al. 2024: keep tokens with
     \(p_i \ge p_{\min} \cdot p_{\max}\)); order of operations in common implementations
     (temperature before or after filtering; verify what Hugging Face does and say so).
   - Repetition / frequency / presence penalties (what they do to logits).
   - **Beam search**: algorithm, length normalization, why it helps translation/summarization
     but is rarely used for chat (blandness, the "beam search curse").
   - Determinism: seeds, and why batched GPU inference can still be non-deterministic
     (floating-point reduction order); keep brief.
3. **The KV cache** derived from first principles: in causal attention, keys/values of past
   tokens never change, so cache them per layer; what is cached (K and V after projection
   and after RoPE), the size formula \(2 \cdot L \cdot n_{kv} \cdot d_h \cdot b\) bytes per
   token (link 07 for MQA/GQA/MLA), and per-step cost without a cache vs with one.
   Implementation with preallocated buffers vs concatenation.
4. **Prefill vs decode** (the core performance model):
   - Prefill processes the whole prompt in parallel: compute-bound, large matmuls.
   - Decode processes one token per sequence: every weight is read once per step to do 2 FLOPs
     per parameter, so at batch 1 the arithmetic intensity is about 1 FLOP/byte in bf16; time
     per token ≈ (weight bytes + KV bytes read) / HBM bandwidth.
   - Batching raises intensity for the weight matmuls (weights reused across the batch) but
     not for attention over each sequence's own cache (link 07).
   - Metrics: time to first token (TTFT), time per output token (TPOT / inter-token latency),
     throughput; the latency–throughput trade-off as batch grows.
5. **Serving teasers** (one paragraph each, link to page 17): continuous batching,
   PagedAttention (paging the KV cache like virtual memory), prefix caching, speculative
   decoding (draft then verify; why it helps a memory-bound decoder).

## Required worked numbers (show every assumption)
- Llama-3-8B, bf16, one H100 SXM (~3.35 TB/s, ~989 dense bf16 TFLOP/s; cite NVIDIA's datasheet
  or mark unverified): weights ≈ 16.06 GB → lower bound ≈ 4.8 ms per decode step at batch 1,
  about 200 tokens/s; how that changes at batch 32 with 4K contexts once the KV cache
  (128 KiB/token) is added to the bytes read.
- Prefill of a 2,048-token prompt: \(2 \cdot N \cdot T\) FLOPs ≈ 3.3e13 → ~33 ms at 100% of
  peak; realistic time at 50% MFU.
- KV cache for Llama-3-8B: 128 KiB/token; batch 32 × 4K tokens = 16 GiB.

- `apply_temperature(logits, tau)`, `top_k_filter(logits, k)`, `top_p_filter(logits, p)`,
  `min_p_filter(logits, p_min)` (filters return logits with removed entries set to −inf; keep

- `KVCache` class (preallocated per-layer K/V buffers of shape (B, n_kv, S_max, d_h), `append`,
  `get`, `length`) and `attend_with_cache(q_t, k_t, v_t, cache, layer)`: one decode step of
  causal multi-head attention for one layer.
- `generate_greedy(step_fn, prompt_ids, max_new_tokens, eos_id)` where `step_fn(ids, cache)`
  returns logits for the last position (tests provide a tiny deterministic model).
- Tests: incremental attention over a cache equals full causal attention on the whole
  sequence; cache length bookkeeping; greedy generation stops at EOS.
