# Brief 16 · GPUs, kernels & FlashAttention

- File: `pages/16-gpus-kernels.html` · Part III · Pretraining & systems · P1 · ~60 min · body 5,000–7,000 words
- Prereqs: 03, 06, 15. Drill module name: `flash`

## Purpose
Enough GPU architecture to reason about performance from first principles, and FlashAttention in
full detail (online softmax, tiling, recomputation), which is a common deep-dive question. This
also sets up the reader's optional CUDA side project.

## Must cover
1. **GPU architecture** for ML: SMs, warps, tensor cores, register file / shared memory (SRAM) /
   L2 / HBM hierarchy with sizes and bandwidths for H100 (verify from NVIDIA docs); why tensor
   cores need specific shapes and dtypes. Chinese: 显存带宽, 算子融合, 计算强度.
2. **Roofline model**: arithmetic intensity, ridge point (~295 FLOP/B for H100 bf16 dense;
   consistent with page 07), memory-bound vs compute-bound ops; classify matmul (by shape),
   softmax, layernorm, elementwise ops.
3. **Kernel fusion**: why fusing elementwise chains removes HBM round-trips; torch.compile and
   Triton as the practical tools; a Triton fused-softmax or RMSNorm example (conceptual code is
   fine; mark it as not tested on GPU here).
4. **FlashAttention v1**: the IO-aware argument (standard attention writes the T×T matrix to
   HBM); tiling over K/V blocks; **online softmax** (running max and running sum with rescaling;
   derive exactly); recomputation in the backward pass instead of storing P; FLOPs unchanged,
   HBM traffic reduced; memory O(T).
5. **FlashAttention-2** (better parallelism over sequence, fewer non-matmul FLOPs, work
   partitioning between warps) and **FlashAttention-3** (Hopper: asynchrony with TMA/warp
   specialization, pingpong scheduling, FP8 with incoherent processing); verify the headline
   speedups/utilization numbers.
6. **Decode-time kernels**: FlashDecoding (split-KV across the sequence for batch-1 decode),
   paged attention kernels (link 17), MLA decode kernels (FlashMLA; link 07).
7. **Profiling mindset**: measuring achieved bandwidth/FLOPs, typical bottlenecks, what to
   optimize first.

## Required worked numbers
- Roofline classification: intensity of a (4096 × 4096) × (4096 × B) matmul for B = 1, 16, 256,
  1024 in bf16 vs the ridge point.
- HBM traffic of naive attention vs FlashAttention for T = 8192, d_h = 128, 32 heads (orders of
  magnitude; state assumptions).

## Required interview questions (12–14; include these)
- What is the roofline model? Is a batch-1 decode matmul compute- or memory-bound?
- Derive the online softmax update used in FlashAttention.
- Why does FlashAttention speed up attention without changing FLOPs?
- What changed in FlashAttention-2 and -3?
- Why does decode need a different attention kernel (FlashDecoding)?
- How would you speed up a slow LayerNorm → matmul → GELU sequence?

## Drill: `exercises/drills/flash.py` (NumPy/PyTorch on CPU)
- `online_softmax(x_blocks)` returning the final softmax via running max/sum.
- `flash_attention_forward(q, k, v, block_q, block_k, causal)` implemented with explicit tiling
  and online softmax, never materializing the full T×T matrix per head; returns output and
  logsumexp. Tests compare against dense attention for several block sizes and causal/non-causal.
