# Brief 25 · RL systems & agentic RL

- File: `pages/25-rl-systems-agentic.html` · Part V · Reinforcement learning · P1 · ~50 min · body 4,500–6,500 words
- Prereqs: 17, 22, 24. Drill module name: `rl_systems`

## Purpose
Large-scale RL for LLMs is mostly a systems problem (rollout generation dominates), and agentic
RL (multi-turn tool use in environments) is where frontier post-training is heading. Cover the
architecture of RL training systems, the off-policy problems they create, and how agentic RL is
set up, with verified examples from 2025–2026 reports.

## Must cover
1. **Anatomy of an RL step**: rollout (inference engine), reward (verifiers, sandboxes, RMs),
   training (FSDP/Megatron), weight sync; time breakdown and why generation dominates; long-tail
   response lengths. Chinese: 智能体, 工具调用, 异步训练.
2. **System designs**: colocated (time-sharing GPUs between engine and trainer) vs disaggregated;
   synchronous vs asynchronous (one-step-off or fully async); partial rollouts (Kimi k1.5);
   frameworks (OpenRLHF, veRL/HybridFlow, AReaL; verify what each claims).
3. **Off-policy issues**: staleness from async training; **training–inference mismatch**
   (the inference engine's token log-probs differ from the trainer's even for identical weights
   due to kernels/precision), its effects (instability, collapse) and fixes (truncated importance
   sampling on the rollout/trainer ratio; recomputing logprobs; cite the primary source, verify);
   MoE routing mismatch (link 24's GSPO; any routing-replay method, verify).
4. **Agentic RL**: multi-turn trajectories with tool calls; masking environment/tool tokens from
   the loss; turn-level vs trajectory-level rewards; environment design (sandboxes, simulated
   users, synthetic tasks); context management over long trajectories. Verified examples:
   DeepSeek-V3.2 (cold start + large-scale agentic task synthesis, 1,800+ environments, 85,000
   prompts; context management strategies), Kimi K2 (agentic data synthesis + joint RL,
   self-critique rubric reward), SWE-style RL (e.g. SWE-RL; verify).
5. **Rewards beyond verifiers**: generative reward models with per-prompt rubrics; pairwise
   judging; reward hacking in agentic settings (tests modified, environment exploits).
6. **What to monitor** in an RL run: reward, response length, entropy, KL, clip fraction,
   logprob mismatch between engine and trainer, per-task pass rates, eval on held-out tasks.
