## Purpose
DeepSeek-V3 is the most discussed open-model technical report of the era. Walk through it end to
end (architecture, infrastructure, FP8 training, data, hyperparameters, long context,
post-training, cost), explaining the reason for each decision, so the reader can field any
question about it. Link back to mechanism pages instead of re-deriving MLA or MoE.

## Must cover (verify every number in the V3 report; the coordinator has already verified the
config, §2.1.1, §3.2 PP16/EP64/ZeRO-1, §3.2.2 NVLink 160 GB/s vs IB 50 GB/s and 4-node limit,
§3.3.2 tile sizes 1×128 and 128×128, §3.3.3 BF16 moments and E5M6, §3.4 deployment, §4.2 batch
ramp and balance settings, §4.3 YaRN)
1. **Architecture recap** with the verified config (link 07/08): 61 layers, MLA, 3 dense then
   58 MoE layers, 1 shared + 256 routed experts, 8 active, sigmoid gating with normalization,
   group/node-limited routing, auxiliary-loss-free balancing plus a tiny sequence-wise loss, no
   token dropping. Chinese: 多词元预测, 流水线并行, 细粒度量化.
2. **Multi-token prediction**: sequential MTP modules (shared embedding and output head, one
   transformer block per depth, RMSNorm + projection combining the previous depth's
   representation with the next token's embedding), loss weight λ schedule, MTP discarded or
   used for speculative decoding at inference (acceptance rate reported; verify), ablation gains.
3. **Infrastructure**: 2,048 H800 GPUs; DualPipe (bidirectional pipeline, overlapping forward
   and backward chunks with all-to-all and PP communication; bubble formula vs 1F1B and ZB1P from
   Table 2; the 2× parameter copy cost); cross-node all-to-all kernels (IB then NVLink
   forwarding, 20 of 132 SMs for communication, warp specialization); memory savings
   (recomputing RMSNorm and MLA up-projections, EMA in CPU memory, shared embedding/head between
   MTP and main model via PP placement); no tensor parallelism.
4. **FP8 mixed-precision training**: which GEMMs run in FP8 (Fprop, Dgrad, Wgrad) and which
   operators stay in BF16/FP32 (embedding, output head, MoE gating, normalization, attention);
   fine-grained quantization (1×128 activation tiles, 128×128 weight blocks) and why
   (outliers); increased accumulation precision (promotion to FP32 on CUDA cores every N_C
   elements because Hopper tensor cores accumulate with limited precision; the ~2% error
   example; verify); E4M3 everywhere instead of E4M3/E5M2 split; online scaling; relative loss
   error vs BF16 in validation experiments (verify value).
5. **Pretraining**: 14.8T tokens (more math/code, multilingual), tokenizer changes
   (verify: 128K BBPE, tokens combining punctuation and line breaks, random splitting to reduce
   token-boundary bias), FIM at 0.1 rate (PSM), document packing; hyperparameters: AdamW
   (β1 0.9, β2 0.95, wd 0.1), LR schedule (warmup, constant, cosine decay, final phases; verify
   the exact values and token counts), batch-size ramp 3072 → 15360 sequences over 469B tokens,
   node-limited routing M = 4, bias update speed γ, MTP λ = 0.3 then 0.1 (verified §4.2).
   Stability: no irrecoverable loss spikes or rollbacks (as reported).
6. **Long context**: YaRN on the decoupled key only, 4K → 32K → 128K in two 1,000-step phases
   (verified §4.3); NIAH results.
7. **Post-training**: 1.5M SFT instances; reasoning data distilled from an internal R1 model
   with expert models and system prompts to control style/length; RL with GRPO using rule-based
   and model-based rewards; self-rewarding/constitutional notes if present (verify).
8. **Cost accounting**: GPU-hours by phase (pretraining, context extension, post-training;
   total 2.788M H800 hours) and the $2/GPU-hour assumption, what this excludes (prior research,
   ablations, data, salaries), and how to discuss the "$5.6M" headline responsibly. Compare with
   6ND at 37B activated params over 14.8T tokens and back out implied MFU (compute; state
   assumptions, and note that MoE and FP8 complicate MFU accounting).
9. **Inference deployment** (verified §3.4) and **hardware suggestions** (§3.5) in brief.
10. **What V3 changed in the field** (aux-loss-free MoE and fine-grained experts adopted by
    others, FP8 training at scale, MLA adoption by Kimi K2): sourced statements only.

  the choice) plus scales; `dequantize(...)`.
