The big picture: language modeling

P0 ~45 min Prereqs: none. Next: 02 Tokenization

A language model is a function from a token prefix to a probability distribution over the next token. Everything else in this course (tokenizers, attention, scaling laws, RLHF, KV caches) refines that one sentence. This page gives you the whole picture first: what the model computes, how it generates, how it is trained and scored, why almost every frontier model is decoder-only, and the three-stage pipeline (pretrain, SFT, RL) that turns a next-token predictor into an assistant.

What a language model computes

A language model 语言模型 is a probability distribution over sequences of tokens 词元. A token is a subword unit from a fixed vocabulary of \(V\) entries (typically 32K to 256K; how the vocabulary is built is the subject of page 02). For a sequence \(x_{1:T}\), the chain rule of probability gives an identity that holds for any distribution:

\[ p(x_{1:T}) = \prod_{t=1}^{T} p(x_t \mid x_{<t}) \]
Autoregressive factorization: exact, no independence assumption

A model is autoregressive 自回归 when it represents every factor with one shared network \(f_\theta\) that reads a prefix and returns a score (a logit) for each vocabulary entry. We index so that position \(t\) reads \(x_{\le t}\) and predicts \(x_{t+1}\), with a start token \(x_0\) (BOS) so that the very first token also has a prefix:

\[ z_t = f_\theta(x_{\le t}) \in \R^{V}, \qquad p_\theta(x_{t+1} = v \mid x_{\le t}) = \softmax(z_t)_v = \frac{e^{z_{t,v}}}{\sum_{u=1}^{V} e^{z_{t,u}}} \]

In a transformer, one forward pass over a whole sequence returns all \(T\) logit vectors at once, a tensor of shape \((B, T, V)\) (batch, position, vocabulary entry), because the causal mask (page 03) makes row \(t\) a function of \(x_{\le t}\) only. Softmax is over the last axis, the vocabulary.

Key idea

The factorization is a theorem; the network is the modeling assumption. All modeling content sits in how well \(f_\theta\) represents the conditionals. Because \(z_t\) never depends on \(x_{>t}\), the product is a properly normalized distribution over sequences of a given length (for variable lengths, add an end-of-sequence token that is reached with probability 1). Two consequences drive everything below: you can sample exactly by drawing one token at a time (next section), and you can score any text exactly, since \(\log p(x_{1:T})\) is a sum of log-probabilities read off the softmax. That exact likelihood is what makes perplexity and bits per byte well defined.

def sequence_logprob(logits, ids):
    # logits: (T, V) from one forward pass, row t predicts ids[t]; ids: (T,) target token ids
    logp = logits.log_softmax(-1)                          # (T, V) log p(. | prefix)
    return logp.gather(-1, ids[:, None]).sum()             # sum_t log p(x_t | x_<t), a scalar

Worked numbers. Suppose the four true tokens of a short text received probabilities \(1/2,\ 1/4,\ 4/5,\ 1/10\). Then \(p(x) = 0.5 \cdot 0.25 \cdot 0.8 \cdot 0.1 = 0.01\), so \(\log p(x) = -0.693 - 1.386 - 0.223 - 2.303 = -4.605\) nats. The mean per token is \(4.605/4 = 1.151\) nats. We reuse this example in the metrics section.

Two other ways to train a transformer on text

By 2019 denoising objectives had displaced causal LM for pretraining before fine-tuning, and T5's authors say they "have quickly become standard" [Raffel et al. 2019, §3.1.4]. Masked language modeling 掩码语言模型 (BERT) hides some tokens and predicts them from both sides. Span corruption (T5) drops spans of tokens and asks a decoder to regenerate them.

Denoising objectives train conditionals \(p(x_{\text{masked}} \mid x_{\text{visible}})\) that do not multiply into a joint distribution you can sample left to right, and most of the sequence is input rather than target. BERT itself notes that masked LM "does converge slightly slower" than a left-to-right model, which it attributes to predicting only 15% of tokens per batch [Devlin et al. 2018, App. A.1 and C.1]. The consequences for architecture are in the families section.

From your jet tagger

Your tagger mapped an unordered set of particles to one label with a permutation-invariant encoder: no positional encoding, full bidirectional attention, one output per jet. A language model differs in three ways. Order is the signal, so positions must be injected (page 05). Attention is causal, so row \(t\) sees only \(x_{\le t}\). And there is one output per token, a softmax over \(V \sim 10^5\) classes instead of a handful. In effect the LM is a classifier applied at every position whose labels the data provides for free, by shifting.

How an LLM is used: the generation loop

Before the details of training, look at the trained artifact in use. Generating text is a loop around the forward pass (Figure 1): tokenize the text into ids of shape \((T,)\) (page 02); embed them to \((T, d)\); run \(L\) transformer blocks (pages 03 to 05); apply the LM head, a linear map \(d \to V\), to get logits of shape \((T, V)\); sample a token from the last row (greedy, temperature, top-\(p\); page 06); append it and repeat until an end-of-sequence token or a length limit.

Two facts about this loop matter for the rest of the course. First, processing known tokens is parallel, generating new ones is sequential: training and prefill run all positions in one pass, while decode needs one pass per new token, because each token must be sampled before it can be fed in. So a 2,000-token prompt costs one large pass, while a 500-token answer costs 500 small ones. That asymmetry is why "time to first token" and "inter-token latency" are separate serving metrics, and why decoding is limited by memory bandwidth rather than FLOPs: every pass streams nearly all the weights from GPU memory (about 15 GB for Llama-3-8B in bf16; only the input embedding table is looked up rather than read in full), and a prefill pass reuses them for thousands of tokens while a decode pass uses them for one new token per sequence (page 06, page 07, page 17). Second, a chat product is the same loop over a text in which the conversation has been serialized with special role tokens; the model's turn ends when it emits an end-of-turn token (page 02 on chat templates, page 19 on training with them).

@torch.no_grad()
def generate(model, ids, max_new_tokens, eos_id):
    # ids: (1, T) prompt token ids; model(ids) returns logits (1, T_cur, V)
    for _ in range(max_new_tokens):
        logits = model(ids)                                   # reprocesses all T_cur positions every step (no KV cache)
        next_id = logits[:, -1].argmax(-1, keepdim=True)      # (1, 1) greedy; sampling variants are page 06
        ids = torch.cat([ids, next_id], dim=1)                # append and repeat
        if next_id.item() == eos_id:
            break
    return ids

This version re-runs the whole sequence at every step. A KV cache stores each layer's keys and values so a step processes only the new token; it is the subject of page 06.

From your jet tagger

Your tagger ran one forward pass per jet, so serving it meant batching jets to keep the GPU busy. An LLM reply is hundreds of dependent forward passes, each of which must wait for the previous token. Batching still helps for the weight matmuls, but the sequential dependency is intrinsic to autoregression, and it shapes nearly every serving optimization in page 17.

Training: next-token cross-entropy is maximum likelihood

From maximum likelihood to the loss

Training data is a set of sequences drawn from an unknown distribution \(p_{\text{data}}\). Maximum likelihood estimation 最大似然估计 picks the parameters that make the data most probable. Taking logs, negating and averaging over the \(N\) supervised token positions turns it into a minimization:

\[ \hat\theta = \argmax_\theta \sum_{i} \log p_\theta(x^{(i)}) = \argmin_\theta \; \underbrace{-\frac{1}{N} \sum_{i} \sum_{t} \log p_\theta\big(x^{(i)}_{t+1} \mid x^{(i)}_{\le t}\big)}_{\mathcal{L}(\theta)\ \text{, mean cross-entropy in nats per token}} \]
Next-token cross-entropy = mean negative log-likelihood = maximum likelihood

Two identities are worth having ready. First, the loss at one position is the cross-entropy between the one-hot label \(e_y\) and the softmax, and it simplifies to

\[ \ell_t = -\log \softmax(z_t)_y = \operatorname{logsumexp}(z_t) - z_{t,y}, \qquad \frac{\partial \ell_t}{\partial z_t} = \softmax(z_t) - e_y . \]

The gradient is "prediction minus target", exactly as in logistic regression, applied at every position. Second, in expectation over prefixes drawn from the data, the per-token loss decomposes as

\[ \E_{p_{\text{data}}}[\mathcal{L}] = H(p_{\text{data}}, p_\theta) = H(p_{\text{data}}) + \KL(p_{\text{data}} \,\|\, p_\theta), \]

so minimizing cross-entropy minimizes the KL divergence to the data distribution, and the entropy term \(H(p_{\text{data}})\) is a floor on the expected loss on fresh data (Chinchilla's fitted constant \(E\) estimates it for one dataset and tokenizer; see below). Language modeling is also lossless compression: a model with loss \(\ell\) nats per token, used with an arithmetic coder, encodes each token in about \(\ell/\ln 2\) bits, so "current language model training protocols use a maximum-compression objective" [Delétang et al. 2023, §2].

Teacher forcing, the shift, and why every position is an example

During training the input at position \(t\) is the ground-truth token \(x_t\), never the model's own earlier sample. This is teacher forcing 教师强制. It makes all \(T\) conditional terms computable in parallel from the data, in one forward pass with a causal mask. The consequence for the data pipeline is the one-position shift: the model reads \(x_{0:T-1}\) (BOS first) and the labels are \(x_{1:T}\), so the label at position \(t\) is the input at position \(t+1\). No human labeling is needed, because the text is its own supervision.

Every position is a training example. A causal LM has a loss at all \(T\) positions of each sequence, versus 15% for BERT-style masking and about 18% for span corruption (table above). Wang et al. give the accounting at equal tokens processed: full LM trains on 100% of tokens, a prefix LM on about 50%, span corruption on 18% [Wang et al. 2022, §3.2]. ELECTRA makes the same point about masked LM, which "only learns from 15% of the tokens per example" and so pays a compute cost [Clark et al. 2020, §1]. Two caveats: supervision density is not downstream quality per FLOP (T5 found denoising better than LM objectives for fine-tuned transfer at equal cost, [Raffel et al. 2019, Tab. 2]), and the case for causal LMs rests on generality and scale (below).

Teacher-forced next-token cross-entropy
Problem
A self-supervised objective that scales to trillions of tokens, yields a generative model, and gives a training signal at every position.
Idea
Maximize the log-likelihood of the data with ground-truth prefixes as inputs and the next token as label, for all positions in parallel under a causal mask.
Why it works
The chain rule makes it exactly the sequence log-likelihood, the gradient is simply softmax minus one-hot, and to predict text well the model must learn syntax, facts and task structure (GPT-2's "unsupervised multitask learning" argument, below).
Evidence
Loss falls as a smooth power law in parameters, data and compute over many orders of magnitude [Kaplan et al. 2020, §1.2]; causal LMs show the strongest zero-shot generalization straight after pretraining [Wang et al. 2022, Tab. 3].
Cost
Exposure bias; likelihood is only a proxy for the quality of sampled text; each token is predicted from its past only, and generation is sequential.
Used by
GPT-2 and GPT-3, Llama 3, DeepSeek-V3 (which adds a multi-token-prediction auxiliary loss, page 11), and the other decoder-only models in Part VI.

Masking, normalization and numerics

The production version of the loss is short, but every line hides a decision:

import torch.nn.functional as F

def lm_loss(model, tokens, pad_id):
    # tokens: (B, T) ids, right-padded with pad_id
    inputs  = tokens[:, :-1]                        # (B, T-1) what the model reads
    targets = tokens[:, 1:].clone()                 # (B, T-1) what it must predict: the shift by one
    targets[targets == pad_id] = -100               # drop padding (wrong if pad_id == eos_id, see below)
    logits = model(inputs).float()                  # (B, T-1, V) in fp32 for a stable softmax
    return F.cross_entropy(logits.flatten(0, 1), targets.flatten(), ignore_index=-100)   # mean over real tokens

The drill uses the equivalent convention that keeps length \(T\): inputs are the tokens themselves and labels are shifted left with \(-100\) in the last slot, so shapes match the logits and no slicing is needed.

  • Padding mask. Positions labeled \(-100\) are dropped from the loss and from the denominator. Masking padding by token id is a classic bug when the pad token doubles as end-of-sequence (common for chat models): the real EOS targets are masked too, and the model never learns to stop. Build the mask from sequence lengths or an attention mask instead.
  • Normalization. The mean is over tokens: NLLs \([1, 2, 3, 2]\) and \([0.5, 1.5]\) give \(10/6 = 1.667\), not the mean of per-sequence means \((2.0 + 1.0)/2 = 1.5\), so long sequences weigh more. In distributed training, divide by the global token count rather than averaging per-rank means (page 19 covers SFT and packing).
  • Initial loss. Near-zero logits mean a uniform model, so the first-step loss should be about \(\ln V\): 10.82 for GPT-2's \(V = 50{,}257\) and 11.76 for Llama 3's \(V = 128{,}256\). A first-step loss far above that means large logits; a loss that collapses toward zero within a few hundred steps on natural text means leakage (no shift, or a mask that is not causal).
  • Numerics. Compute the log-softmax in fp32 with max subtraction: \(e^{z}\) overflows fp32 near \(z = 88.7\), and bf16 keeps only 8 bits of precision.
def log_softmax(z):                                   # z: (..., V)
    m = z.max(-1, keepdim=True).values                # subtract the max so every exp() lies in (0, 1]
    return z - m - (z - m).exp().sum(-1, keepdim=True).log()

Memory is the other constraint: 8,192 tokens \(\times\) 128,256 vocabulary entries \(\times\) 4 bytes \(\approx 4.2\) GB of fp32 logits per micro-batch, before gradients, so large-vocabulary training fuses or chunks the LM head with the loss (page 15).

Exposure bias

Teacher forcing creates a mismatch. In training the prefix comes from \(p_{\text{data}}\); at generation time it comes from the model itself. Ranzato et al. named this exposure bias 曝光偏差: the model "is only exposed to the training data distribution, instead of its own predictions", so "errors may accumulate along the way" [Ranzato et al. 2016, Abstract and §1]. Scheduled sampling was an early fix: flip a coin per token and feed the model's own prediction with a probability annealed upward over training [Bengio et al. 2015, §2.4].

How large is the effect for modern LMs? Smaller than the theory suggests. In open-ended generation with Transformer-XL on WikiText-103, He et al. found relative gaps of only about 1 to 2% between generations from ground-truth prefixes and from the model's own, with no growth over prefix length, and the LM recovers from corrupted prefixes ("self-recovery") [He et al. 2019, §6.2]. The field did not adopt sampling-based pretraining. Instead, post-training RL trains on the model's own samples against a reward (page 22), and repetition is handled at decode time (page 06).

Measuring a language model: loss, perplexity, bits per byte

Loss and perplexity

Report the mean loss \(\ell\) in nats per token (natural log). Dividing by \(\ln 2\) gives bits: 1 nat \(= 1.4427\) bits. Perplexity 困惑度 is its exponential:

\[ \operatorname{PPL} = e^{\ell} = \Big(\prod_{t} \frac{1}{p(x_t \mid x_{<t})}\Big)^{1/N} \]
Perplexity = geometric mean of the inverse probability of the true tokens = effective branching factor

The second form gives the "effective branching factor" reading: if the model spread its probability evenly over \(k\) tokens at every step, then \(\ell = \ln k\) and \(\operatorname{PPL} = k\). Ranzato et al. put it as the average number of words the model is "hesitating about", noting that a random model has perplexity near the vocabulary size while a good one on their data had about 50 [Ranzato et al. 2016, §3.2.2]. Checking with our earlier example: the inverse probabilities are \(2,\ 4,\ 1.25,\ 10\), their product is \(100\), and \(100^{1/4} = 3.16 = e^{1.151}\).

Worked conversions. Loss \(2.0\) nats gives \(\operatorname{PPL} = e^{2.0} = 7.39\). Perplexity \(10\) gives \(\ell = \ln 10 = 2.303\) nats \(= 3.32\) bits. A uniform model over Llama 3's vocabulary has \(\ell = \ln 128{,}256 = 11.76\) and \(\operatorname{PPL} = 128{,}256\). To aggregate across datasets, average the losses weighted by token counts and exponentiate once; averaging perplexities is wrong because the exponential is convex.

Why perplexity does not transfer across tokenizers

The "per token" in \(\ell\) is a per-tokenizer unit. The original Transformer paper already warns that its perplexities are per word piece and "should not be compared to per-word perplexities" [Vaswani et al. 2017, Tab. 3]. What a model assigns to a text is its total NLL; a tokenizer only chooses how many tokens to divide that total by.

  • Toy case. A 4,000-byte text carries \(2000\) nats under both models. Tokenizer A cuts it into 1,000 tokens (4.0 bytes per token): \(\ell = 2.0\), \(\operatorname{PPL} = 7.39\). Tokenizer B cuts it into 2,000 tokens (2.0 bytes per token): \(\ell = 1.0\), \(\operatorname{PPL} = 2.72\). Same model quality, perplexities differ by 2.7 times.
  • Real case. Llama 3's tokenizer averages 3.94 characters per token on English versus 3.17 for Llama 2's [Llama 3, §3.2]. At equal bits per character, the Llama 3 tokenizer therefore shows a per-token loss \(3.94/3.17 = 1.243\) times higher: \(2.0 \to 2.486\) nats, and \(\operatorname{PPL}\) from \(7.39\) to \(12.0\). A 1.63 times "worse" perplexity, for identical compression.

Bits per byte

The tokenizer-independent fix is to divide the total NLL by a unit that does not depend on tokenization. The Pile paper's preferred unit is the UTF-8 byte, chosen for "its invariance to different tokenization schemes and the ambiguity of measuring characters in Unicode" [Gao et al. 2020, §3.1]:

\[ \text{bpb} = \frac{L_T}{L_B} \cdot \frac{\ell}{\ln 2} = \frac{\text{total NLL in nats}}{L_B \ln 2}, \qquad L_T = \text{tokens}, \ L_B = \text{UTF-8 bytes} \]
Bits per byte: compressed bits per raw byte of the evaluation text

Worked example. Loss \(\ell = 2.0\) nats per token at 4.0 bytes per token means \(L_T/L_B = 0.25\), so \(\text{bpb} = 2.0 \times 0.25 / 0.6931 = 0.7213\). Raw text costs 8 bits per byte, so this model compresses to \(0.7213/8 = 9.0\%\) of the original size (ignoring the size of the model itself). The toy tokenizer B above gives \(1.0 \times 0.5/0.6931 = 0.7213\) too. Bits per character is the same formula with characters instead of bytes; bytes are preferred because character counts are ambiguous across Unicode scripts.

Real numbers. GPT-3 davinci on the Pile has a per-token perplexity of 5.4508 with the GPT-2 tokenizer, which averages 0.29335 tokens per byte (3.41 bytes per token). So \(\text{bpb} = \ln(5.4508) \times 0.29335 / \ln 2 = 1.6957 \times 0.29335 / 0.6931 = 0.7177\), matching the paper's Table 2 [Gao et al. 2020, Tab. 2, 8]. DeepSeek-V3's report uses the same metric to compare base models with different tokenizers on the Pile test set: 0.548 for V3-Base, 0.542 for Llama-3.1 405B, 0.638 for Qwen2.5 72B and 0.606 for DeepSeek-V2 [DeepSeek-V3, Tab. 3], measured in its own evaluation framework, so treat cross-paper numbers as indicative.

Rules of thumb. Same tokenizer, same text, same context and packing protocol: compare loss or perplexity. Different tokenizers: compare bits per byte on identical text. Protocol still matters: the Pile scores each document independently, and later positions in a context have lower loss because they see more context [Gao et al. 2020, App. E.2]. GPT-2 instead normalized by the benchmark's "canonical units" (a character, byte or word) [Radford et al. 2019, §3.1].

Reading a loss number

Loss differences that matter are small numbers, so calibrate. Kaplan et al. fit \(L(N) \propto N^{-0.076}\) for non-embedding parameters (with enough data), so doubling \(N\) multiplies the loss by \(2^{-0.076} = 0.949\), a 5.1% drop [Kaplan et al. 2020, §1.2]. At a loss of 2.10 that is about \(-0.108\) nats per doubling. A drop from 2.10 to 2.05 is \(-2.4\%\) in loss and \(-4.9\%\) in perplexity (\(8.17 \to 7.77\)); under that fit it is worth about \((2.05/2.10)^{-1/0.076} = 1.37\) times the parameters. Three qualifiers apply:

  • Distance to the floor. The power law has no irreducible term. Chinchilla's fit \(L = E + A/N^{0.34} + B/D^{0.28}\) has \(E = 1.69\) on its dataset and tokenizer, read as the entropy of natural text [Hoffmann et al. 2022, §3.3 and App. D.2]. From that floor, 2.10 to 2.05 is \(0.41 \to 0.36\), a 12% cut of the reducible loss. But \(E\) is specific to that data and tokenizer and cannot be transplanted, and it is not precisely pinned down: a 2024 replication that refit the same form to data reconstructed from the paper's figures got \(E \approx 1.82\) [Besiroglu et al. 2024], which would make the same step \(0.28 \to 0.23\), an 18% cut.
  • Noise. Kaplan et al. saw about 0.05 run-to-run variation in loss for a 3M-parameter model in learning-rate sweeps, roughly constant across sizes [Kaplan et al. 2020, App. D]. That is a small-scale setup, so measure your own seed noise; a paired comparison on the same held-out set removes evaluation-set variance but not training-seed variance.
  • Downstream. Loss tracks benchmark accuracy task by task, not one to one: Llama 3 mapped FLOPs to the negative log-likelihood of the correct answers, then a sigmoid to accuracy [Llama 3, §3.2.1]. In one-epoch pretraining, the running training loss on fresh batches is an unbiased estimate of held-out loss [Hoffmann et al. 2022, §1, footnote 2].

Architectures: why decoder-only won

Three families differ in their attention mask and objective. Encoder-only models (BERT: 110M and 340M parameters for Base and Large) use bidirectional attention and a masked-LM objective, and produce a representation per token for a task head [Devlin et al. 2018, §3]. Encoder-decoder models, the original translation Transformer [Vaswani et al. 2017, §3] and T5 (up to 11B), encode the input bidirectionally and generate the output with a causal decoder that cross-attends to it. Decoder-only models 仅解码器架构 use one causal stack trained on next-token prediction: GPT-2 (1.5B), GPT-3 (175B), Llama 3, DeepSeek-V3.

The case for decoder-only

  • Training-signal density. A loss at every position (100%) versus 15 to 18% for the denoising objectives (above).
  • One uniform stack, no objective hyperparameters. T5 needs a corruption rate, a span length and an encoder/decoder split; the causal LM has no such objective hyperparameters [Raffel et al. 2019, Tab. 6 and 7]. Scaling means adding layers, width and tokens.
  • The prompt is the interface. Any task can be written as a text prefix whose continuation is the answer, with no task heads. GPT-2's argument is formal: "the supervised objective is the same as the unsupervised objective but only evaluated on a subset of the sequence, [so] the global minimum of the unsupervised objective is also the global minimum of the supervised objective" [Radford et al. 2019, §2]. GPT-3 then showed few-shot prompting improving with scale (below).
  • Zero-shot right after pretraining. In the most careful controlled comparison, causal decoders trained with full LM had the best zero-shot scores before any fine-tuning (next subsection).
  • Cache friendliness. Under a causal mask, an earlier token's hidden state never changes when later tokens are appended, so the KV cache is append-only and a shared prefix (a system prompt, earlier chat turns) can be cached exactly across requests. With a bidirectional encoder over the prefix, appending a token changes every earlier representation and the history must be re-encoded. This is an engineering argument rather than a measured one (page 06, page 17).
  • Path dependence. Scaling laws, kernels, parallelism strategies and data pipelines were then built around this shape. Part of the answer to "why did it win?" is that the ecosystem compounded.

The honest reading: a causal decoder is the best generalist out of the box, an encoder-decoder with masked LM is best once you spend a multitask fine-tuning stage, and conversion is cheap. Encoder-decoders are not a dead end: adapting Gemma 2 decoder-only checkpoints into encoder-decoders gave, at a similar inference budget, comparable pretraining and substantially better fine-tuned performance (Gemma 2B-2B beat Gemma 2B by about 7% after instruction tuning) [Zhang et al. 2025, Abstract]. Decoder-only won on generality, simplicity at scale and serving, not on a proof of dominance.

Non-autoregressive alternatives, as of September 2026. Masked-diffusion LMs drop the left-to-right factorization: LLaDA trained an 8B model on 2.3T tokens that was competitive with Llama 3 8B on many benchmarks, without a KV cache [Nie et al. 2025, §2.2 and §3.2]. The report opens with "Autoregressive (AR) models dominate the current Large Language Model (LLM) landscape" [DiffusionGemma report, Abstract, §1, §6, Tab. 3, §10].

The pipeline: pretraining, SFT, preference optimization and RL

A pretrained model is a document continuer, not an assistant. The InstructGPT authors state the mismatch directly: the language-modeling objective, predicting the next token on a webpage, is "different from the objective 'follow the user's instructions helpfully and safely'", so they call it misaligned [Ouyang et al. 2022, §1]. Modern models close that gap in stages. Llama 3's report frames it as two main stages, pretraining with next-token prediction and post-training to follow instructions, align with human preferences and improve specific capabilities [Llama 3, §1].

Stage 1: pretraining and the base model

Pretraining 预训练 is next-token cross-entropy on web text, code, books and math at trillion-token scale, producing a base model 基座模型 that continues text. It teaches language, world knowledge, code and the ability to pick up patterns from context. It is where nearly all compute goes. Stage 2: supervised fine-tuning

Supervised fine-tuning 监督微调 (SFT, or instruction tuning) continues training with the same cross-entropy on (prompt, response) pairs rendered in a chat template. The one change is that the loss is computed on the response tokens only: Llama 3 uses "a standard cross entropy loss on the target tokens (while masking loss on prompt tokens)" [Llama 3, §4.1.3]. Data is tiny next to pretraining: about 13k training prompts for InstructGPT's SFT set [Ouyang et al. 2022, §3.2], and 1.5M instances for two epochs for DeepSeek-V3, with reasoning data generated by an internal DeepSeek-R1 model and non-reasoning data from DeepSeek-V2.5 checked by human annotators [DeepSeek-V3, §5.1]. SFT adds a behavior (follow the instruction, use the format, know when to stop) rather than large amounts of new knowledge. This is the "superficial alignment" view: LIMA fine-tuned a 65B base model on only 1,000 curated examples and was equal or preferred to GPT-4 in 43% of comparisons [Zhou et al. 2023, Abstract], and fine-tuning examples that introduce facts the model does not know are learned slowly and raise hallucination once learned [Gekhman et al. 2024, Abstract]. How strictly it holds is debated: the same study finds that which examples you choose changes how well pretraining knowledge is used, so SFT does more than set style. Details: page 19.

Stage 3: preference optimization and reinforcement learning

The last stage optimizes something a token-level imitation loss cannot express: which of two complete answers is better, or whether a final answer is correct. There are three variants you should be able to name:

  • RLHF 基于人类反馈的强化学习: collect human comparisons, train a reward model, then optimize the policy against it with PPO. InstructGPT used about 33k prompts for the reward model and 31k for PPO, and its 1.3B model was preferred to the 175B GPT-3 despite having over 100 times fewer parameters [Ouyang et al. 2022, §3.2 and §4.1]. It also documents an "alignment tax" (regressions on some public benchmarks, reduced by mixing pretraining gradients into PPO). See page 23.
  • Offline preference optimization (DPO). Llama 3 ran several rounds of SFT (on data that includes reward-model-ranked, rejection-sampled responses) followed by DPO, and chose DPO over on-policy PPO because it "required less compute for large-scale models and performed better, especially on instruction following benchmarks" [Llama 3, §4.1.4]. So "post-training" does not mean PPO. See page 21.
  • RL with verifiable rewards (RLVR) for reasoning. DeepSeek-R1-Zero applies GRPO directly to the V3 base model with rule-based rewards (answer accuracy plus a format reward) and no SFT; average AIME 2024 pass@1 rose from 15.6% to 77.9% in the current arXiv version while responses grew longer [DeepSeek-R1, §2.3]. R1 adds cold-start SFT on thousands of examples, a reasoning RL stage, rejection sampling plus SFT on reasoning and non-reasoning data, and a second RL stage with helpfulness and harmlessness rewards [DeepSeek-R1, §3]. See page 24.

What RL adds that SFT and pretraining lack: it optimizes a sequence-level outcome on the model's own samples, so it trains on the distribution the model will generate from (the exposure-bias mismatch, above), and with a verifier it can exceed any human demonstration. Its risks are reward hacking (the R1 authors avoided neural reward models on reasoning tasks because they "are susceptible to reward hacking during large-scale reinforcement learning", [DeepSeek-R1, §2.2]) and, for RLHF, the alignment tax.

In-context learning and emergent abilities

In-context learning 上下文学习 (ICL) is performing a new task from instructions or a few demonstrations placed in the prompt, with no weight update. GPT-3 defined the settings: zero-shot (an instruction only), one-shot and few-shot (typically \(K = 10\) to \(100\) demonstrations, whatever fits in a 2,048-token window) [Brown et al. 2020, §2]. TriviaQA closed-book accuracy was 64.3%, 68.0% and 71.2% zero-, one- and few-shot, and few-shot SuperGLUE reached 71.8 (32 examples in context) against 69.0 for fine-tuned BERT-Large and 89.0 for the fine-tuned state of the art [Brown et al. 2020, §1 and Tab. 3.8]. The few-shot advantage grew with model size: larger models "make increasingly efficient use of in-context information" (their Figure 1.2).

Why it is surprising, and what explains it

The model was trained only to predict the next token, never to "learn from these examples", and its weights are frozen at test time, yet its behavior on the query depends on the demonstrations as if it had learned. Three partial explanations, at different levels:

  • The objective itself. GPT-2 speculated that "a language model with sufficient capacity will begin to learn to infer and perform the tasks demonstrated in natural language sequences in order to better predict them", making the LM an "unsupervised multitask learner" [Radford et al. 2019, §2]. Web text contains countless natural demonstrations, and inferring the task helps predict the next token.
  • Mechanism. Induction heads (circuits that complete the pattern [A][B] ... [A] \(\to\) [B]) form in a sharp phase change early in training, coinciding with a jump in "in-context learning" measured as the loss at token 50 minus the loss at token 500 (from under 0.15 nats to about 0.4). The evidence is causal for small attention-only models and only correlational for large ones [Olsson et al. 2022, Args. 1 to 6]. That paper's "in-context learning" (loss improving with position) is a different quantity from GPT-3's few-shot task performance.
  • Behavioral. Replacing demonstration labels with random ones barely hurts classification and multiple-choice accuracy across 12 models including GPT-3; demonstrations mostly specify the label space, the input distribution and the format [Min et al. 2022, Abstract]. Under a strict definition (learning a new input-to-label mapping) the model may not be learning at test time; under a broader one (locating and formatting a task it already knows) it is.

Emergent abilities: two readings

Wei et al. define an ability as emergent 涌现能力 "if it is not present in smaller models but is present in larger models", so it cannot be predicted by extrapolating smaller models. Their examples: 3-digit addition and subtraction in GPT-3 appears around \(2 \times 10^{22}\) training FLOPs (13B parameters), and 57-topic MMLU rises above chance only near \(3 \times 10^{23}\) FLOPs (175B) [Wei et al. 2022, §2 and Tab. 1].

Schaeffer et al. argue much of the sharpness is a property of the metric. If per-token accuracy is \(p\) and a task scores exact match over \(L\) tokens, accuracy is about \(p^L\), which changes sharply even when \(p\) improves smoothly; multiple-choice grade is a step function of the probabilities. They report that over 92% of emergent abilities claimed on BIG-Bench appear under just two metrics, multiple-choice grade and exact string match, and they make abilities vanish by switching to token edit distance or Brier score. They also state that nothing in their paper "should be interpreted as claiming that large language models cannot display emergent abilities" [Schaeffer et al. 2023, §1 and §7].

Worked numbers. A 10-token exact-match task with per-token accuracy \(p = 0.90, 0.95, 0.99\) scores \(0.349,\ 0.599,\ 0.904\): halving the per-token error from 10% to 5% lifts task accuracy 1.7 times, and \(p = 0.5\) scores \(0.001\), which looks like "no ability at all". Wei et al. themselves note that cross-entropy improves smoothly even where downstream metrics sit at chance, and that metric choice is only "an incomplete explanation" because emergence also appears on classification tasks [Wei et al. 2022, §5.1 and App. A]. Neutral summary: for the tasks studied, apparent sharpness depends heavily on the metric, and whether genuinely discontinuous capability transitions exist remains open. The practical lesson is to forecast with continuous metrics such as the log-likelihood of the correct answer, as Llama 3 did (above).

Common misconceptions

  • "A language model outputs a word." It outputs a distribution over \(V\) tokens at every position. A "next token" is what a sampler or argmax extracts from that distribution, and tokens are subword pieces, not words.
  • "Perplexity is a universal quality score." It is per token, so it is comparable only across models sharing a tokenizer and evaluated on the same text with the same protocol. Across tokenizers use bits per byte. The same compression quality can show a 1.63 times higher perplexity just by changing the tokenizer (Llama 2 to Llama 3 example).
  • "Perplexity 10 means the model is right 10% of the time." It is the geometric mean of the inverse probabilities of the true tokens, an effective branching factor. Top-1 accuracy is a different quantity.
  • "Teacher forcing lets the model see the answer." It sees the ground-truth prefix, and the causal mask hides the target and everything after it. If the training loss collapses toward zero on natural text, suspect leakage (missing shift or a non-causal mask), not brilliance.
  • "Masking padding by token id is always safe." If the pad token doubles as EOS, the real end-of-sequence targets are masked and the model never learns to stop. Mask by length or attention mask.
  • "Decoder-only won because bidirectional attention is bad." Bidirectional context gives better representations of a fixed input, and encoder-decoder with masked LM was best after multitask fine-tuning in Wang et al. Decoder-only won on generality, dense supervision, simplicity at scale and serving, not on a proof of superiority.
  • "Post-training means RLHF means PPO." Llama 3 used SFT, rejection sampling and DPO; DeepSeek-V3 used SFT plus GRPO; R1-Zero skipped SFT entirely. The algorithms differ, and the stages are defined by data and objective, not by PPO.
  • "Emergence is proven" or "emergence is a mirage." Both are overstated. Sharpness is strongly metric-dependent for the tasks studied (Schaeffer et al.), while cross-entropy scales smoothly (Kaplan et al., Wei et al. App. A), and the existence of true phase transitions is unresolved.

Interview questions

Warm-up Write the autoregressive factorization of a language model. What does the network output, and is the factorization an approximation?

\(p(x_{1:T}) = \prod_{t} p(x_t \mid x_{<t})\). It is the chain rule, so it is exact for any distribution; the only approximation is how well the network represents each conditional. With a BOS token in front, one forward pass returns logits of shape \((B, T, V)\), with row \(t\) depending only on \(x_{\le t}\) thanks to the causal mask, and a softmax over the last axis gives \(p(x_{t+1} \mid x_{\le t})\).

Because the conditionals are normalized and causal, the joint is a valid distribution: you can sample exactly, one token at a time, and compute \(\log p(x)\) exactly as a sum of gathered log-probabilities, which is why perplexity and bits per byte are well defined.

Warm-up A model has validation loss 2.0 nats per token. What is its perplexity, what loss does perplexity 10 correspond to, and what does perplexity 10 mean?

\(\operatorname{PPL} = e^{\ell}\), so \(e^{2.0} = 7.39\). Inversely \(\ell = \ln 10 = 2.303\) nats (3.32 bits). Perplexity is the geometric mean of the inverse probabilities of the true tokens, an effective branching factor: perplexity 10 is as uncertain as a uniform choice among 10 tokens per step. Example: true-token probabilities \(1/2, 1/4, 4/5, 1/10\) have inverse probabilities with product 100, so \(\operatorname{PPL} = 100^{1/4} = 3.16 = e^{1.151}\). It is not an accuracy (a model with perplexity 10 can have 40% top-1 accuracy), and a freshly initialized model has perplexity near \(V\).

Warm-up What is teacher forcing, and what is exposure bias?

Teacher forcing: in training, the input at each position is the ground-truth previous token, not the model's own sample, so all \(T\) conditionals are computed in parallel in one causal forward pass, with labels equal to the inputs shifted by one.

Exposure bias (Ranzato et al. 2016): the model only sees data-distribution prefixes in training but conditions on its own samples at generation time, so an early mistake puts it in a rarely seen state and errors may compound. Scheduled sampling (Bengio et al. 2015) was an early fix. For modern LMs the measured effect is small (He et al.: about a 1 to 2% relative gap, not growing with prefix length, in open-ended generation), and the practical remedies are RL on the model's own samples in post-training and sensible decoding.

Warm-up What are base, instruct and reasoning models, and how do you prompt each?

A base model is the pretraining output. It continues text, so you write the start of a document whose continuation is the answer (few-shot patterns, "Q: ... A:"). An instruct/chat model adds SFT and preference optimization: you use a chat template with role tokens, and it answers and stops at an end-of-turn token. A reasoning model adds large-scale RL with verifiable rewards: it emits a long chain of thought (for R1, inside think tags) and then a final answer, so cost and latency scale with thought tokens. Mismatching format and checkpoint (a raw question to a base model, a foreign template to an instruct model) is a common cause of poor results.

Core Why is next-token cross-entropy the maximum-likelihood objective? Derive it.

MLE maximizes \(\sum_i \log p_\theta(x^{(i)})\). By the chain rule \(\log p_\theta(x) = \sum_t \log p_\theta(x_{t+1} \mid x_{\le t})\). Negating and dividing by the number of supervised positions \(N\) gives \(\mathcal{L}(\theta) = -\frac{1}{N}\sum \log p_\theta(x_{t+1} \mid x_{\le t})\), the average negative log-probability of the true next token. Each term is the cross-entropy between the one-hot label \(e_y\) and \(\softmax(z_t)\), that is \(\operatorname{logsumexp}(z_t) - z_{t,y}\), with gradient \(\softmax(z_t) - e_y\).

Equivalently, in expectation \(H(p_{\text{data}}, p_\theta) = H(p_{\text{data}}) + \KL(p_{\text{data}} \,\|\, p_\theta)\), so minimizing cross-entropy minimizes the KL divergence to the data distribution; the entropy term is constant in \(\theta\) and is the floor on the loss. Teacher forcing is what makes every term computable from the data in parallel.

Core Why can't you compare perplexities of models with different tokenizers? What do you use instead? Show an example.

Perplexity is \(e^{\ell}\) with \(\ell\) per token, and tokenizers cut the same text into different numbers of tokens. What a model assigns to a text is its total NLL; the tokenizer only decides what to divide by. A 4,000-byte text with total NLL 2,000 nats is 1,000 tokens under tokenizer A (\(\ell = 2.0\), \(\operatorname{PPL} = 7.39\)) and 2,000 tokens under B (\(\ell = 1.0\), \(\operatorname{PPL} = 2.72\)) at identical model quality. In practice, Llama 3's tokenizer averages 3.94 characters per token versus Llama 2's 3.17, so equal bits per character means a per-token loss 1.243 times higher (2.0 becomes 2.486 nats; perplexity 7.39 becomes 12.0).

Use bits per byte: \(\text{bpb} = (L_T/L_B)\,\ell/\ln 2 = \text{total NLL}/(L_B \ln 2)\). Here \(2.0 \times 0.25/0.6931 = 0.7213\) for A and \(1.0 \times 0.5/0.6931 = 0.7213\) for B. Bytes beat characters because character counts are ambiguous in Unicode. Also keep the evaluation text, context length and document handling identical.

Core How do you build inputs and labels for a padded batch, what breaks if the pad token equals EOS, and how should the loss be normalized?

Either slice (\(\text{inputs} = x_{1:T-1}\), \(\text{labels} = x_{2:T}\)) or keep length \(T\) with \(\text{labels}[t] = x_{t+1}\) and \(-100\) in the last slot. Set the label to \(-100\) (ignore_index) wherever the target is padding, so those positions add neither loss nor gradient.

If padding is identified by token id and the pad token is also EOS, genuine EOS targets are masked too, so the model gets no gradient for emitting EOS and does not learn to stop; build the mask from sequence lengths or the attention mask instead. Normalize by the number of supervised tokens (NLLs \([1,2,3,2]\) and \([0.5,1.5]\) give \(10/6 = 1.667\), not the per-sequence mean 1.5), dividing by the global token count in data-parallel training, and compute the softmax in fp32 with max subtraction.

Core Why did decoder-only architectures win over encoder-decoder for general-purpose LLMs?

Several reinforcing reasons, plus caveats. (1) Supervision density: a causal LM has a loss at 100% of positions; BERT-style masking 15%, span corruption about 18%. (2) Simplicity: one stack, one objective, no corruption-rate, span-length or encoder/decoder-depth hyperparameters. (3) The prompt is the interface: any task is a text prefix and the answer a continuation, so no task heads; GPT-2 argues the supervised objective is the unsupervised one evaluated on a subset, and GPT-3 showed few-shot ability growing with scale. (4) Zero-shot out of the box: in Wang et al., causal decoders with full LM were best straight after pretraining. (5) Serving: causal states never change when tokens are appended, so KV and prefix caches are exact and append-only. (6) Path dependence: scaling laws and tooling were built around it.

Caveats: the same study found encoder-decoder with masked LM best after multitask fine-tuning (T0-Eval 60.6 versus 51.4), T5 found denoising best for fine-tuned transfer, and adapting Gemma 2 to encoder-decoder gave better fine-tuned results at a similar inference budget. So the honest answer is generality, simplicity and serving at scale, not dominance.

Core What does each post-training stage add that pretraining lacks?

Pretraining gives capability (language, knowledge, code, pattern use in context), but its objective, predict the next token of web text, is misaligned with "follow instructions helpfully and safely". SFT trains the same cross-entropy on (prompt, response) pairs, with loss on response tokens only, and adds the behavior: instruction following, chat format, stopping. It needs thousands to millions of examples (InstructGPT about 13k prompts; DeepSeek-V3 1.5M).

Preference optimization / RL adds what imitation cannot express: a sequence-level objective evaluated on the model's own samples. With human preferences (RLHF with PPO, or offline DPO as in Llama 3) it improves helpfulness and harmlessness, and InstructGPT's 1.3B model beat GPT-3 175B in human preference. With verifiable rewards (GRPO in R1-Zero) it teaches long chain-of-thought behavior and can exceed human demonstrations. Costs: the alignment tax, reward hacking, and small GPU-hour shares that hide large data and engineering costs (V3: 5K of 2,788K GPU-hours).

Core A model's validation loss dropped from 2.10 to 2.05 nats per token. Is that a big improvement?

Convert first: \(-0.05\) nats is \(-2.4\%\) in loss and \(8.17 \to 7.77\), or \(-4.9\%\), in perplexity. Calibrate against scaling: Kaplan et al.'s \(L \propto N^{-0.076}\) gives a 5.1% loss reduction per doubling of parameters (about \(-0.108\) at loss 2.10), so 0.05 is worth about \(1.37\times\) the parameters. Measured from an irreducible floor it looks larger: with Chinchilla's \(E = 1.69\) (specific to its data and tokenizer, and refit to about 1.82 by a replication) the reducible loss goes \(0.41 \to 0.36\), a 12% cut.

Then ask the skeptical questions. Is it outside seed noise (Kaplan et al. saw about 0.05 run-to-run variation in a small setup, so run several seeds)? Same eval set, tokenizer and protocol? Did it cost extra compute or parameters? Does it transfer downstream (loss and benchmarks correlate task by task, and accuracy is nonlinear in loss)? Verdict: a real but modest gain, meaningful if replicated across seeds and free of extra compute.

Core What is in-context learning, and why is it surprising?

ICL is doing a new task from instructions or demonstrations in the prompt, with frozen weights. GPT-3 defined zero-, one- and few-shot (\(K\) about 10 to 100 in a 2,048-token window) and showed the few-shot advantage growing with size (TriviaQA 64.3, 68.0, 71.2; few-shot SuperGLUE 71.8 versus 69.0 for fine-tuned BERT-Large). It is surprising because nothing in the objective asks for it: the model only predicts next tokens, and no gradient step happens at test time.

Explanations at three levels: GPT-2's argument that inferring the task helps predict web text that contains demonstrations; a mechanism, induction heads, whose formation in a sharp phase change coincides with the jump in in-context ability (causal evidence only for small attention-only models); and a behavioral finding that random labels in demonstrations barely hurt (Min et al.), so demonstrations mostly convey label space, input distribution and format. Whether that counts as learning depends on the definition.

Deep-dive Debug: a 128,256-vocabulary model shows a first-step loss of 25, and in a second run the loss falls to about 0.05 within a few hundred steps on web text. What is wrong in each case?

Expected initial loss is about \(\ln V = 11.76\), since near-zero logits are uniform. With logit standard deviation \(\sigma\), the loss is roughly \(\ln V + \sigma^2/2\) for moderate \(\sigma\), or about \(\sigma\sqrt{2\ln V} \approx 4.85\,\sigma\) when the maximum dominates, so a loss of 25 implies \(\sigma \approx 5\): an initialization or scale problem (unscaled tied embeddings, a missing final norm, a wrong output-head init). Check activations at init and the head's weight scale.

A loss near zero on natural text is impossible for an honest model (real text has substantial entropy), so it is leakage: labels not shifted (the model copies its input), a mask that is not causal (position \(t\) sees \(t+1\)), or nearly all labels ignored so the mean covers a few trivial tokens. Tests: perturb token \(t+1\) and assert the logits up to position \(t\) are unchanged; check that the loss on the first real token is high; count supervised tokens per batch; train on shuffled labels and confirm the loss returns to about \(\ln V\).

Deep-dive Design question: what do the public numbers say about splitting a budget across pretraining, SFT and RL, and what do they not say?

What they say: DeepSeek-V3's 2.788M H800 GPU-hours split 95.6% pretraining, 4.3% context extension and 0.2% post-training. InstructGPT spent 0.1% (SFT) and 1.6% (PPO-ptx) of GPT-3's 3,640 PF-days and still beat a model 100 times larger on human preference. R1-Zero and R1 together used about 142K GPU-hours, about 5% of V3's pretraining. So post-training is cheap in FLOPs per unit of behavior change, and its share is growing in the reasoning era.

What they do not say: (1) the figures exclude data creation, annotation, verifier and environment engineering, prior research and ablations; (2) V3's Table 1 counts only V3's official training, so the internal R1 model that generated its reasoning SFT data is presumably outside the 2.788M; (3) they are single reports, so marginal returns are unknown. The R1 authors say the effectiveness of RL from a base model depends heavily on model capacity [DeepSeek-R1, Supp. G.1], so RL complements pretraining rather than replacing it. Decision rule: knowledge comes from pretraining scale, behavior and format from SFT, long-horizon reasoning and verifiable skills from RL given a reliable verifier. Put compute where the target capability is limited, and measure at each stage.

Deep-dive Explain Schaeffer et al.'s argument with numbers. Would a smoothly improving model ever look "emergent"?

Suppose per-token accuracy \(p\) improves smoothly with scale and the task is scored by exact match over \(L = 10\) tokens. Accuracy is about \(p^{10}\): \(0.5 \to 0.001\), \(0.90 \to 0.349\), \(0.95 \to 0.599\), \(0.99 \to 0.904\). Against log-compute the score sits near zero and then rises steeply, like a threshold, although per-token cross-entropy, which the scaling law predicts, moved smoothly throughout. A discontinuous metric such as multiple-choice grade (1 if the correct option has the top probability) is step-like for the same reason. Switching to token edit distance or the Brier score, which are roughly linear or continuous in \(p\), removes the apparent emergence, and low test-set resolution hides above-chance accuracy at small scale.

Limits: Schaeffer et al. do not claim emergence is impossible, and Wei et al. note that jumps also appear on classification metrics and that loss shows an elbow at the point of emergence on some tasks. Metrics explain much of the sharpness in the tasks studied, though not obviously all of it.

Cheat sheet

  • \(p(x_{1:T}) = \prod_t p(x_t \mid x_{<t})\), exact. One pass gives logits \((B, T, V)\); position \(t\) predicts \(x_{t+1}\); softmax over the last axis.
  • Loss = mean NLL over supervised tokens = cross-entropy = MLE = \(\KL(p_{\text{data}} \| p_\theta) + H(p_{\text{data}})\). \(\partial \ell / \partial z = \softmax(z) - e_y\). Initial loss \(\approx \ln V\) (128,256: 11.76; 50,257: 10.82).
  • Teacher forcing: inputs are ground-truth prefixes; labels are inputs shifted left; last slot and padding are \(-100\); token-mean normalization; mask padding by length, not id, if pad = EOS.
  • \(\operatorname{PPL} = e^{\ell}\): 2.0 nats is 7.389; PPL 10 is 2.303 nats; uniform over \(k\) tokens is PPL \(k\). Average losses, never perplexities.
  • \(\text{bpb} = (L_T/L_B)\,\ell/\ln 2\): 2.0 nats at 4.0 bytes per token is 0.7213. Never compare perplexity across tokenizers (Llama 3 vs 2: 3.94 vs 3.17 characters per token, 1.243 times per-token loss).
  • Loss scale: doubling \(N\) multiplies loss by 0.949 (Kaplan); 0.05 nats at loss 2.10 is about \(1.37\times\) parameters. Check seed noise first.
  • Supervised positions: causal LM 100%, prefix LM about 50%, span corruption about 18%, masked LM 15%. Decoder-only won on generality, density, simplicity, prompt-as-interface and caching; encoder-decoder with masked LM is best after multitask fine-tuning (Wang et al.).
  • Pipeline: pretrain (\(10^{13}\) tokens; 95.6% of V3's GPU-hours), SFT (\(10^4\) to \(10^6\) examples, loss on response tokens), preference/RL (PPO, DPO, GRPO): small in FLOPs, large in data and engineering.
  • Anchors: GPT-3 175B on 300B tokens; Llama 3 405B on 15.6T (\(3.8 \times 10^{25}\) FLOPs); V3 671B total and 37B activated on 14.8T, 2.788M H800 GPU-hours; R1 on V3-Base about 147K GPU-hours.
  • Generation: tokenize, embed, \(L\) blocks, logits, sample, append. Prefill is parallel and compute-bound; decode is one token per pass, bandwidth-bound, with the KV cache.
  • ICL: task from demonstrations, no weight update; demonstrations mostly convey label space, input distribution and format (Min et al.). Emergence is largely metric-dependent (\(p^{L}\) for exact match) and still debated.
