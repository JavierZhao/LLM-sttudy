Beyond full attention: sparse, linear, SSM, hybrid

P1 ~75 min Prereqs: 03 Attention, 05 Positional encoding, 06 Decoding & KV cache, 07 KV-efficient attention

Full attention pays \(O(T^2)\) compute and an \(O(T)\) cache to keep every token exactly addressable. Every alternative gives up some of that exactness to save FLOPs, bytes read, or resident memory. This page derives each family, states what it trades away (almost always exact recall), and explains why, as of September 2026, frontier open models use hybrids and learned sparse attention rather than pure linear or state-space models.

The cost landscape: what to save, and what it costs

Page 06 established the two regimes. During training and prefill, full attention computes all \(T(T+1)/2\) causal query-key pairs, so compute grows as \(O(T^2 d)\). During decoding, each new token reads the entire KV cache and does \(O(Td)\) FLOPs against it, so both the bytes read per step and the resident cache grow as \(O(T)\). Decoding is memory-bound: for grouped-query attention the arithmetic intensity is about \(n_h/n_{kv}\) FLOPs per byte, far below what a GPU needs to be compute-bound. Page 07 attacked the feature axis of that cache (MQA, GQA, MLA). This page attacks the sequence axis, and asks whether the cache must be a list of tokens at all.

Three different quantities can be saved, and methods differ in which ones they touch:

  • FLOPs in prefill and training (compute-bound work): reduced by any method that computes fewer query-key pairs.
  • Bytes read per decoded token (decode latency and throughput): reduced by reading fewer cache entries, or a smaller state.
  • Resident memory (the batch size and context that fit on a GPU): reduced only if entries are dropped, merged, or replaced by a fixed-size state. A method can cut FLOPs and bytes read while leaving resident memory untouched, which is exactly what learned top-k selection does.

A useful way to organize everything that follows: a sequence mixer keeps a memory of the past, and the families differ in the shape of that memory.

  1. Append-only list (full attention): memory grows with \(T\), nothing is lost, any token can be addressed exactly.
  2. Truncated list (sliding window): constant memory, everything older than \(W\) tokens is forgotten by that layer.
  3. List plus a selector (sparse attention): memory still grows, but each query reads only \(k\) entries chosen by content.
  4. Compressed list (MLA, DeepSeek-V4's CSA and HCA): memory grows more slowly because entries are merged along the feature or sequence axis.
  5. Fixed-size matrix state (linear attention, state-space models, delta-rule models): constant memory, the past is compressed into \(d_k \times d_v\) numbers per head, and retrieval is approximate by construction.

Key idea

The linear layer does 1,024 times fewer FLOPs than the full-attention layer at 128K, but its intensity is worse (2.1 MFLOP over 4 MiB moved is 0.5 FLOPs per byte, versus 4.0). It is still memory-bound. It wins because it moves 256 times fewer bytes (2 MiB versus 512 MiB). The crossover, where the fp32 state equals the KV cache, is at \(2\ \text{MiB} / 4096\ \text{B} = 512\) tokens (256 tokens for a bf16 state). Below 512 tokens the fixed state is actually larger than the cache; the entire benefit is at long \(T\).

Two consequences shape every design on this page. First, because decoding is bandwidth-bound, real speedups track memory access volume, not FLOPs: NSA's paper notes that its expected decode speedup is "approximately linear with the volume of memory access" [NSA, §5.2, Tab. 4]. Second, prefill and training are compute-bound, so a method that helps decoding (a smaller cache) may do nothing for training cost, and vice versa. NSA states the split directly: reduce computation during training and prefilling, reduce memory access during decoding.

Local attention and sliding windows

Language is mostly local: the next token depends overwhelmingly on the last few hundred tokens, plus a small number of long-range references. 滑动窗口注意力 (sliding-window attention) exploits this by letting query \(i\) attend only to the \(W\) most recent keys. Longformer introduced the pattern for encoders: each token attends to \(w/2\) tokens on each side, giving \(O(n \cdot w)\) cost, with optional dilation and a few task-specific "global" tokens that attend to, and are attended by, everything [Longformer, §3.1]. For a causal language model the window is one-sided. In this page's convention (and the drill's), \(W\) counts the keys a query sees including itself:

\[ M^{\text{sw}}_{ij} = \mathbb{1}[\,i - W \lt j \le i\,], \qquad \operatorname{Attn}_i = \softmax_{j:\,M_{ij}=1}\!\left(\frac{q_i k_j^\top}{\sqrt{d_h}}\right) V. \]

Why depth restores long-range reach, and why it is only a bound

One layer of window \(W\) lets information travel \(W-1\) positions. Stack \(\ell\) layers and the top layer's value at position \(i\) can depend on inputs up to about \(\ell (W-1)\) positions back. Longformer states this as a receptive field of \(\ell \times w\) at the top layer, "similar to CNNs" [Longformer, §3.1], and Mistral 7B uses the same argument: with \(W = 4096\) and 32 layers "we have a theoretical attention span of approximately 131K tokens" [Mistral 7B, §2]. The arithmetic is \(32 \times 4096 = 131{,}072\).

The word "theoretical" matters. The receptive field is an upper bound on where information can come from, not a capacity. A token 100K positions away can influence the current output only if a chain of about 25 intermediate positions each attends to the previous link and copies the information forward, and every hop passes through a softmax average and a residual stream shared with everything else. Exact retrieval of a specific fact (a name, a number, an identifier) does not survive that chain reliably. The evidence is stark when a full-attention model is converted without retraining: GLM's team replaced half of a 40-layer GLM-9B's layers by 4096-token windows in a fixed 1:1 interleave, with no further training, and RULER fell from 95.19 (full attention) to 94.87 at 4K, then 54.02 at 8K, 25.89 at 16K, and 6.51 at 128K [GLM-5, §2.1.2, Tab. 4], although 20 window layers have a nominal reach of \(20 \times 4096 = 81{,}920\) tokens. A model trained to relay information does better than a converted one, but MiniMax's continued-pretraining experiments with hybrid SWA (hundreds of billions to trillions of tokens) still showed degraded retrieval, multi-hop, and in-context-learning scores, with RULER at 128K falling from 99.0 to 93.0 on multi-query needles and from 90.0 to 72.0 on common-words extraction, while the 32K scores were identical [MiniMax-M2 report, §2.2.2, Tab. 2]. Depth gives reach; it does not give reliable long-range lookup.

The rolling-buffer cache

Because a window layer never looks further back than \(W\) tokens, its cache can have a fixed size. Mistral stores the keys and values of position \(i\) in slot \(i \bmod W\), overwriting the entry that just fell out of the window, so "the size of the cache stops increasing" and on a 32K sequence memory falls 8x "without impacting model quality" [Mistral 7B, §2] (\(32768 / 4096 = 8\)). For prefill, Mistral chunks a long prompt with the window size as the chunk size, so each chunk attends to the cache plus itself.

import torch

class RollingKV:
    """Fixed-size KV cache for one sliding-window layer (batch 1, one KV head)."""
    def __init__(self, W: int, d: int):
        self.W, self.k, self.v, self.n = W, torch.zeros(W, d), torch.zeros(W, d), 0
    def append(self, k_t, v_t):           # k_t, v_t: (d,)
        slot = self.n % self.W            # position i is stored at i mod W
        self.k[slot], self.v[slot] = k_t, v_t
        self.n += 1
    def read(self):                       # keys, values currently inside the window
        m = min(self.n, self.W)           # slot order is scrambled, which softmax does not care about
        return self.k[:m], self.v[:m]     # (RoPE is applied to keys before caching, so relative positions survive)

Interleaved local and global layers

If local layers cannot do long-range lookup, give that job to a few layers that can. Modern models interleave: most layers are local (cheap, constant cache) and a minority are global (full attention, growing cache). Verified configurations:

  • Gemma 2 alternates local and global layers one to one: local window 4096, global span 8192 [Gemma 2, §2].
  • Gemma 3 uses 5 local layers per global layer, starting with a local layer, with a local window of only 1024 tokens; RoPE base 10k on local layers and 1M on global layers [Gemma 3, §2]. Ablations show minimal perplexity impact from changing the local:global ratio (2B and 9B models, even at 7:1), and that the window can be cut from 4096 to as low as 512 without hurting perplexity (2B models). For a 2B model at 32K context, a global-only stack has a KV-cache memory overhead of 60%, versus under 15% for a 1:3 ratio with a 1024 window [Gemma 3, §5.2, Figs. 3-6].
  • gpt-oss alternates banded-window and fully dense layers with a bandwidth of 128 tokens, 64 query heads of dimension 64 and 8 KV heads, and extends the dense layers to 131,072 tokens with YaRN [gpt-oss model card, §2.2].
  • Gemma 4 keeps 5:1 local to global (4:1 for the 2.3B model), with p-RoPE, KV sharing and keys reused as values in global layers; together these cut the global KV cache by up to 37.5% [Gemma 4 report, §1].
  • MiMo-V2-Flash (309B total, 15B active) uses 5:1 with a 128-token window and a learnable sink bias, described as "nearly a 6x reduction in KV-cache storage and attention computation" [MiMo-V2-Flash, §1].

The window sizes span a factor of 32 (128 to 4096), which is itself a finding. MiMo's ablation on a 32B dense model shows why the small window can work and the medium one can fail. All variants were trained on 250B tokens at 8K, extended to 32K on 40B more, then SFT'd. With sinks, \(W=128\) and \(W=512\) match all-global attention on general benchmarks, but after long-context extension \(W=512\) collapses on NoLiMa (38.5 versus 49.7 for all-global) and MRCR (19.6 versus 32.5) while \(W=128\) is slightly better than all-global (51.2 and 34.4) [MiMo-V2-Flash, §2.2.1, Tabs. 2-3]. The authors' hypothesis is a division of labor: a tight window forces local layers to model local structure and delegate long-range work to the global layers, whereas a medium window lets local layers half-solve long-range dependencies and blurs the split. They stress that this is empirical and specific to their setup, and it sits in tension with MiniMax's finding above. One reconciling detail: MiMo's long-context evaluations top out at 32K, while MiniMax found SWA hybrids diverging beyond 32K.

Interleaved local/global attention
Problem
Full attention at every layer makes the KV cache and the decode bandwidth grow linearly with context, and prefill quadratically.
Idea
Make most layers sliding-window (constant cache, \(O(TW)\) compute) and keep a small fraction (1 in 2 to 1 in 6) fully global.
Why it works
Most dependencies are local, so local layers handle them at a fraction of the cost. The global layers carry exact long-range lookup, so retrieval quality does not depend on relaying information through many windowed hops. Cache and decode bytes fall by roughly the local fraction (a 5:1 ratio removes about 5/6 of the cache).
Evidence
Gemma 3: perplexity is insensitive to the ratio (even 7:1) and to window sizes down to 1024 [Gemma 3, §5.2]. MiMo: \(W=128\) with sinks matches or beats all-global at 32K [MiMo-V2-Flash, Tab. 3]. Against: MiniMax found SWA hybrids degrade on retrieval and on long-context tasks beyond 32K [MiniMax-M2 report, §2.2.2], and naive interleaving of a pretrained model is catastrophic (GLM-5 Tab. 4).
Cost
Local layers cannot retrieve beyond \(W\). The global layers still cost \(O(T^2)\) prefill and \(O(T)\) cache, so long-context cost is reduced by a constant factor, not made sub-quadratic. Perplexity and short-context benchmarks barely register the loss.
Used by
Gemma 2, 3, 4; gpt-oss; MiMo-V2-Flash; Mistral 7B (all layers windowed, relying on depth).

Worked number: prefill FLOPs, full versus window

For the Llama-3-8B stack at \(T = 131{,}072\) and \(W = 4096\). Count causal pairs, not the full square: full attention computes \(T(T+1)/2 = 131072 \cdot 131073 / 2 = 8{,}590{,}000{,}128\) pairs per layer, while a window computes \(W(W+1)/2 + (T-W)W = 8{,}390{,}656 + 520{,}093{,}696 = 528{,}484{,}352\) (a ramp for the first \(W\) queries, then \(W\) each). The ratio is \(8.59\text{e}9 / 5.28\text{e}8 = 16.25\), not \(T/W = 32\), because causal full attention already skips half the square.

Each pair costs \(4 n_h d_h = 16{,}384\) FLOPs per layer, so attention totals \(16384 \cdot 32 \cdot 8{,}590{,}000{,}128 = 4.50 \times 10^{15}\) FLOPs for full attention and \(2.77 \times 10^{14}\) for the window, a 16.25x cut. But the whole model also does the dense matmuls (QKV and output projections, SwiGLU MLP), which windowing does not touch: the model has \(6{,}979{,}321{,}856\) matmul parameters per token outside the embeddings (per layer \(4096^2 + 2 \cdot 4096 \cdot 1024 + 4096^2 + 3 \cdot 4096 \cdot 14336 = 218{,}103{,}808\), times 32), so \(2 N T = 2 \cdot 6{,}979{,}321{,}856 \cdot 131072 = 1.83 \times 10^{15}\) FLOPs. Totals: \(6.33 \times 10^{15}\) full versus \(2.11 \times 10^{15}\) windowed, a ratio of 3.01x. At 128K, attention is 71.1% of full prefill, so the windowed model is dominated by the projections and MLP. This is why sliding windows (and every attention-only trick) give large gains in the attention term but bounded gains in total FLOPs, and why the gain grows with \(T\) (attention share rises) and shrinks for wide models.

Attention sinks

Pure window attention has a puzzling failure. StreamingLLM ran Llama-2-13B on the first book of PG-19 (65K tokens) with a 1024-token window and got perplexity 5158.07; keeping the first 4 tokens and the most recent 1020 restored it to 5.40 [StreamingLLM, Tab. 1]. The first tokens carry no special meaning: replacing them with newline tokens still gave 5.60. What matters is that they are there.

The explanation is the softmax. Attention weights must sum to one, so when a query has no strong match anywhere, the mass has to go somewhere. Beyond the bottom two layers, the model "heavily attends to the initial token across all layers and heads" [StreamingLLM, Fig. 2, §3.1]. The initial tokens are visible to every later position in a causal model, which makes them the easiest thing to train into a dump. These tokens are attention sinks, and they hold a large share of the softmax denominator. Evict them and the denominator changes for every head in every layer, so all later attention distributions shift off what the model learned. The fix, StreamingLLM, keeps the KV of about 4 sink tokens plus a rolling window, and assigns positions within the cache rather than original text positions: with cache tokens \([0,1,2,3,6,7,8]\) and the 9th token being decoded, the positions are \([0,1,2,3,4,5,6,7]\). For RoPE it caches keys before rotation and rotates them at each step. The reported result is stable modeling to 4 million tokens and up to a 22.2x speedup over recomputing a window each step.

Pitfall

StreamingLLM does not extend memory. It keeps the model stable on unbounded streams, but information older than the cache is gone: the paper's own test shows retrieval accuracy falling to zero once the query-answer distance exceeds the cache size [StreamingLLM, App., Tab. 7]. Sinks fix a distribution shift, not a capacity limit.

If the sink is a learned artifact, give the model an explicit one. StreamingLLM pretrained 160M models with a learnable placeholder token: with a 1024-token cache and no initial tokens, perplexity was 27.87 (vanilla), 29,214 (softmax-off-by-one, "Zero Sink"), and 1,235 (learnable sink token), but with just one initial token kept, 18.49, 19.90, and 18.01 [StreamingLLM, Tab. 3]. A single dedicated sink suffices where vanilla models need about four, while zero sink (a key and value of zero, equivalent to \(\mathrm{softmax}_1\)) is not enough alone. Current models put the sink inside the softmax as a per-head learned logit \(z'_h\):

\[ s_{h,i,j} = \frac{\exp(z_{h,i,j})}{\sum_{k}\exp(z_{h,i,k}) + \exp(z'_h)}. \]

This adds a fictitious key with logit \(z'_h\) and a zero value, so a head's real weights can sum to nearly zero when nothing is relevant. gpt-oss describes it as "a learned bias in the denominator of the softmax" that "enables the attention mechanism to pay no attention to any tokens" [gpt-oss model card, §2.2]; MiMo-V2-Flash and DeepSeek-V4 (Eq. 27 of §2.3.3) use the same form. MiMo's ablation shows it is load-bearing for small windows: without the sink bias, \(W=128\) loses 2.4 MMLU points to all-global (54.9 versus 57.3); with it, \(W=128\) reaches 58.3 [MiMo-V2-Flash, Tab. 2]. Sinks also relate to massive activations and gated attention, treated as a stability topic in page 11, and to the long-context recipes of page 10.

Sparse attention: choosing which keys to read

Windows decide which keys matter by position. 稀疏注意力 (sparse attention) in the modern sense decides by content: each query attends to a small subset of keys that are likely to matter, so compute per query is \(O(k)\) instead of \(O(T)\). The design questions are how the subset is chosen, whether the choice is trainable, and which resource (FLOPs, bytes, memory) is actually saved.

Fixed patterns: Sparse Transformer and BigBird

The Sparse Transformer factorizes attention into two sparse heads whose composition reconnects every pair of positions in two hops. The strided pattern (a local window plus every \(\ell\)-th earlier position) suits data with periodic structure such as images; for text the authors found strided routing can fail and use a fixed pattern in which specific "summary" cells propagate information to all later positions (for stride 128 and \(c=8\), every position past 128 attends to positions 120 to 128), reducing cost to \(O(n\sqrt{n})\) [Sparse Transformer, Abstract, §4.3]. BigBird combines three components (a sliding window, a few global tokens, and random keys), reaches \(O(n)\), proves the pattern is a universal approximator of sequence functions and Turing complete, and handles sequences up to 8x longer on the same hardware [BigBird, Abstract]. Both save FLOPs. Neither is what current LLMs use, for two reasons: a fixed pattern cannot know where the relevant key is (it relies on depth and on the fixed global cells to route information), and the irregular sparsity is hard to make fast on tensor cores.

Learned and dynamic selection

Native Sparse Attention (NSA) computes attention over three compact key-value sets per query and mixes them with learned gates [NSA, §3.2, Eq. 5]:

\[ o^*_t = \sum_{c \in \{\text{cmp},\,\text{slc},\,\text{win}\}} g^c_t \cdot \operatorname{Attn}\!\big(q_t,\ \tilde K^c_t,\ \tilde V^c_t\big), \qquad g^c_t \in [0,1]. \]

The compressed branch summarizes blocks of keys into coarse tokens; the selected branch keeps the highest-scoring blocks at full resolution, with block importance read off the compressed-branch attention scores at no extra cost; the window branch keeps recent tokens. For GQA and MQA models, all heads in a group must select the same blocks so the KV cache is loaded once. The configuration is compression block \(l=32\) with stride \(d=16\), selection block \(l'=64\), \(n=16\) selected blocks (one initial and two local blocks fixed), window \(w=512\), on a 27B-parameter (3B active) GQA and MoE model with 30 layers. Pretraining on 270B tokens at 8K matched or beat full attention on general, long-context, and reasoning benchmarks. Speedups at 64K are 9.0x forward, 6.0x backward, and 11.6x decoding [NSA, Fig. 1, §4.1, §5]. The decode figure follows from bytes: per step NSA loads the equivalent of 5,632 tokens at 64K versus 65,536 for full attention, and \(65536/5632 = 11.6\) (Table 4). The paper's intro says 260B tokens and its setup says 270B; I use the setup value.

Mixture of Block Attention (MoBA) borrows the MoE recipe: split the context into blocks and route each query to the top-\(k\) blocks with a parameter-free gate [MoBA, §2, Eqs. 5-6],

\[ g_i = \mathbb{1}\big[s_i \in \operatorname{Top\text{-}k}(\{s_j\})\big], \qquad s_i = \big\langle q,\ \operatorname{meanpool}(K[I_i])\big\rangle . \]

Future blocks get \(s_i=-\infty\), and the query's own block is always attended (causally masked). No new parameters means MoBA can be switched on or off in an existing model, and the authors train with MoBA for 90% of tokens then switch to full attention for the last 10%, reaching a position-wise loss almost identical to full attention (1.5B models, 30B tokens, block size 2048, top-3). Reported speedup is up to 6.5x when prefilling 1M tokens, and a 16x cut in attention time at 10M tokens with fixed sparsity [MoBA, §3.2 and §3.4].

DeepSeek Sparse Attention (DSA)

DSA is the design to be able to explain in detail, because V3.2, GLM-5, and (in modified form) V4, MiniMax-M3, and Qwen3.8 all use variants of it. It has two parts: a lightning indexer that scores every earlier token for the current query, and a top-\(k\) selector that keeps only those key-value entries for core attention [DeepSeek-V3.2, §2.1, Eqs. 1-2]:

\[ I_{t,s} = \sum_{j=1}^{H^I} w^I_{t,j}\, \operatorname{ReLU}\!\big(q^I_{t,j} \cdot k^I_s\big), \qquad u_t = \operatorname{Attn}\!\big(h_t,\ \{c_s \mid I_{t,s} \in \operatorname{Top\text{-}k}(I_{t,:})\}\big). \]

The indexer has few heads (\(H^I = 64\), index head dimension \(d^I = 128\), from the released config), uses ReLU for throughput, and runs in FP8. The core attention is built on the MQA mode of MLA, where each cached latent is shared by all query heads of the token, because kernel efficiency requires each selected entry to be reused across many queries. In V3.2, \(k = 2048\).

import torch, torch.nn.functional as F

def dsa_select(q_idx, w, k_idx, k_top):
    """q_idx: (B,T,H_I,d_I)  w: (B,T,H_I)  k_idx: (B,T,d_I).  Returns top-k key indices (B,T,k)."""
    s = torch.einsum('bthd,bsd->bths', q_idx, k_idx)          # per-head dot products
    I = (w[..., None] * F.relu(s)).sum(2)                     # (B,T,S): weighted sum of ReLU scores
    T = I.shape[1]
    future = torch.triu(torch.ones(T, T, dtype=torch.bool), diagonal=1)
    I = I.masked_fill(future, float('-inf'))                  # causal: only s <= t
    return I.topk(min(k_top, T), dim=-1).indices              # entries the core attention will read

Training. Top-\(k\) is not differentiable, so the indexer is trained as a student of the model's own dense attention. Starting from a dense 128K-context checkpoint (V3.1-Terminus), there are two stages [DeepSeek-V3.2, §2.1.1, Eqs. 3-4]:

  1. Dense warm-up. Keep dense attention, freeze everything except the indexer, and minimize \(\mathcal{L}^I = \sum_t D_{\mathrm{KL}}\big(p_{t,:}\,\|\,\softmax(I_{t,:})\big)\), where \(p_{t,:}\) is the main attention distribution summed over heads and L1-normalized. 1000 steps of 16 sequences of 128K tokens, learning rate \(10^{-3}\): \(1000 \cdot 16 \cdot 131072 = 2.1\)B tokens.
  2. Sparse training. Turn on top-\(k\) selection and train all parameters (learning rate \(7.3\times10^{-6}\), \(k=2048\)), with the KL loss restricted to the selected set. The indexer input is detached, so the indexer learns only from \(\mathcal{L}^I\) and the main model only from the language-modeling loss. 15,000 steps of 480 sequences of 128K tokens: \(15000 \cdot 480 \cdot 131072 = 943.7\)B tokens.

Parity was reported against V3.1-Terminus: no substantial degradation on short- or long-context benchmarks, similar ChatbotArena Elo, and AA-LCR four points higher in reasoning mode [DeepSeek-V3.2, §2.2]. GLM-5 (744B parameters, trained on 28.5T tokens) adopted the same recipe, with a 1000-step indexer warm-up (14 sequences of 202,752 tokens per step) and only 20B tokens of sparse adaptation, far below V3.2's 943.7B; it reports that the DSA and MLA models tie in SFT loss and benchmarks (for example 128K SQuAD 86.0 versus 79.7, HotpotQA 63.0 versus 66.3) [GLM-5, §2.1.1, Tab. 3].

Successors: MSA and QSA

MiniMax Sparse Attention (MSA) is block-based and built on GQA: a single-head Index Branch scores key-value blocks and picks a top-\(k\) set independently for each GQA group, the query's local block is always included, and the Main Branch runs exact attention over the chosen blocks. CSA compression. With hidden states \(H \in \mathbb{R}^{n \times d}\) and head dimension \(c\), compute two series of entries and weights, \(C^a = H W^{a}_{KV}\), \(C^b = H W^{b}_{KV}\), \(Z^a = H W^a_Z\), \(Z^b = H W^b_Z\) (Eqs. 9-10). Each block of \(m\) tokens becomes one entry through a learned softmax over the block and the previous block (\(2m\) rows in all), with learned positional biases \(B^a, B^b \in \mathbb{R}^{m \times c}\) (Eqs. 11-12):

\[ \big[S^a_{mi:m(i+1)-1};\, S^b_{m(i-1):mi-1}\big] = \operatorname{Softmax}_{\text{row}}\big([Z^a_{mi:m(i+1)-1} + B^a;\ Z^b_{m(i-1):mi-1} + B^b]\big), \] \[ C^{\text{Comp}}_i = \sum_{j=mi}^{m(i+1)-1} S^a_j \odot C^a_j + \sum_{j=m(i-1)}^{mi-1} S^b_j \odot C^b_j. \]

Each compressed entry mixes \(2m\) source entries, but the ranges overlap between neighbors, so the sequence length shrinks by \(1/m\), not \(1/2m\). CSA selection then applies DSA to the compressed entries: indexer keys \(K^{\text{IComp}}\) are compressed the same way, the indexer query is built from the same low-rank latent \(c^Q_t = h_t W^{DQ}\) as the attention queries, and for a compressed block \(s \lt \lfloor t/m \rfloor\) (Eqs. 13-17)

\[ I_{t,s} = \sum_{h=1}^{n^I_h} w^I_{t,h}\, \operatorname{ReLU}\!\big(q^I_{t,h} \cdot K^{\text{IComp}}_s\big), \qquad C^{\text{SprsComp}}_t = \big\{C^{\text{Comp}}_s \mid I_{t,s} \in \operatorname{Top\text{-}k}(I_{t,:})\big\}. \]

Shared-KV MQA core. The selected entry is both key and value for all query heads: \(o_{t,i} = \operatorname{CoreAttn}(q_{t,i},\ C^{\text{SprsComp}}_t,\ C^{\text{SprsComp}}_t)\) (Eq. 19). HCA is the same idea without selection or overlap: blocks of \(m' \gg m\) tokens, \(S = \operatorname{Softmax}_{\text{row}}(Z + B)\), \(C^{\text{Comp}}_i = \sum_j S_j \odot C_j\) (Eqs. 20-23), and dense MQA over all compressed entries (Eq. 26). Four further details are in §2.3.3: an RMSNorm on each query head and on the KV entry before core attention (for logit stability); partial RoPE on the last 64 dimensions of queries, KV entries, and outputs, with the output rotated by position \(-i\) so that, because keys double as values, the contribution of each entry stays relative; an extra uncompressed sliding window of \(n_{\text{win}} = 128\) recent tokens in both layer types (a query cannot otherwise see the other tokens of its own block, and recent tokens matter most); and attention sinks with a learned logit per head (Eq. 27, above). Compression keeps causality by letting a query see only earlier compressed blocks.

Contrast with the linear and state-space hybrids

V4 makes a different bet from GDN or Mamba hybrids. Linear and SSM hybrids make three of every four layers constant-memory but pay with approximate recall in those layers, and lean on the remaining full-attention layers for retrieval. V4 reduces the sequence factor of \(\text{layers} \times \text{tokens} \times \text{features} \times \text{bytes}\) by merging tokens, where the hybrids remove the cache from most layers altogether. Which bet wins at 1M tokens and beyond is an open question (see the decision section).

Linear attention: a recurrent network with a matrix state

Start from causal softmax attention for one head, in the row-vector convention of this course (\(q_t, k_s \in \mathbb{R}^{1\times d_k}\), \(v_s \in \mathbb{R}^{1\times d_v}\)):

\[ o_t = \frac{\sum_{s \le t} \exp\!\big(q_t k_s^\top/\sqrt{d_k}\big)\, v_s}{\sum_{s \le t} \exp\!\big(q_t k_s^\top/\sqrt{d_k}\big)}. \]

The exponential of a dot product does not factor into a function of \(q_t\) times a function of \(k_s\), which is why every query must be compared with every key. 线性注意力 (linear attention) replaces \(\exp(q\cdot k)\) by a kernel that does factor, \(\operatorname{sim}(q,k) = \phi(q)\phi(k)^\top\), with a feature map \(\phi\). Katharopoulos et al. use \(\phi(x) = \operatorname{elu}(x) + 1\), which is positive so the normalizer never vanishes [Katharopoulos et al. 2020, §3.2, Eq. 7].

The derivation, step by step

Substitute the kernel and use associativity of matrix products, \((\phi(q_t)\phi(k_s)^\top)\, v_s = \phi(q_t)\,(\phi(k_s)^\top v_s)\). The factor \(\phi(q_t)\) does not depend on \(s\), so it leaves the sum:

\[ o_t = \frac{\sum_{s\le t} \phi(q_t)\phi(k_s)^\top v_s}{\sum_{s\le t} \phi(q_t)\phi(k_s)^\top} = \frac{\phi(q_t)\, \Big(\sum_{s\le t} \phi(k_s)^\top v_s\Big)}{\phi(q_t)\, \Big(\sum_{s\le t} \phi(k_s)^\top\Big)}. \]

The two bracketed sums depend only on the prefix, so define a state \(S_t\) and a normalizer state \(z_t\) that grow by one term per token:

\[ S_t = S_{t-1} + \phi(k_t)^\top v_t, \qquad z_t = z_{t-1} + \phi(k_t)^\top, \qquad o_t = \frac{\phi(q_t)\, S_t}{\phi(q_t)\, z_t}, \qquad S_t \in \mathbb{R}^{d_k \times d_v},\ z_t \in \mathbb{R}^{d_k}. \]
Causal linear attention as an RNN (Katharopoulos et al. 2020, §3.3-3.4)

The state has \(d_k d_v\) numbers (plus \(d_k\) for the normalizer) per head, independent of \(t\). With \(d_k = d_v = 128\) that is 16,384 numbers per head, the same as the cache of 64 tokens for one KV head (each token stores \(2 \cdot 128 = 256\) numbers per KV head). The per-token cost is \(O(d_k d_v)\) for the update and the readout, and the parallel form \(O = \big((\phi(Q)\phi(K)^\top) \odot M\big) V\), normalized by row sums, gives the same numbers in \(O(T^2 d)\). The drill asks you to write both and check they agree. Katharopoulos et al. report linear transformers that are "up to 4000x faster on autoregressive prediction of very long sequences" [Abstract].

Chunkwise form: how these models train fast

The pure recurrence is sequential, and the parallel form is quadratic, so neither is good for training on long sequences. The standard solution splits the sequence into chunks of \(C\) tokens (64 or 128 in practice [DeltaNet, §2.1]), uses the parallel masked form inside each chunk, and passes the state between chunks with the recurrence. For chunk \(i\) with state \(S_{i-1}\) coming in (dropping the normalizer, as all modern variants do in favor of a norm on the output):

\[ O_{[i]} = \underbrace{\phi(Q_{[i]})\, S_{i-1}}_{\text{inter-chunk}} + \underbrace{\big(\phi(Q_{[i]})\phi(K_{[i]})^\top \odot M\big) V_{[i]}}_{\text{intra-chunk}}, \qquad S_i = S_{i-1} + \phi(K_{[i]})^\top V_{[i]}. \]

Cost is \(O(T C d + T d_k d_v)\) per head: intra-chunk work is \(T/C\) chunks times \(C^2 d\), and the state passing is \(T/C\) matmuls of size \(d_k \times d_v\). Both are dense matmuls, so they run on tensor cores. RetNet introduced the same triple (parallel, recurrent, chunkwise) for its decayed variant [RetNet, §2.1, Eqs. 5-7], and Gated Linear Attention showed it can be implemented faster than FlashAttention-2 even at 1K length [GLA, Abstract].

Why plain linear attention lags

Three separate reasons, each fixed by a different later idea.

  1. Fixed capacity. \(S\) holds \(d_k d_v\) numbers per head. It cannot store more than \(O(d_k)\) independent associations exactly. Formal versions of this appear in the recall section below.
  2. Crosstalk. The readout is \(\phi(q)S = \sum_s (\phi(q)\phi(k_s)^\top)\, v_s\). Querying with \(q = k_j\) returns \(\phi(k_j)\phi(k_j)^\top v_j\) plus \(\sum_{s\ne j} \phi(k_j)\phi(k_s)^\top v_s\). If the feature vectors were orthogonal the second term would vanish, but with a positive map such as \(\operatorname{elu}+1\) every pair has a positive inner product, so the noise terms cannot cancel. A positive kernel also produces a smooth, low-contrast average, where the exponential in softmax amplifies the best match and can focus almost all weight on one key.
  3. No forgetting. \(S_t\) is a plain sum, so its norm grows with \(t\) and old associations never make room for new ones. The normalizer rescales the output but does not free capacity.

Decay and gates: RetNet and GLA

The cheapest fix for the third problem multiplies the old state by a decay before adding the new association. RetNet uses a constant per-head \(\gamma\) [RetNet, Eq. 6]:

\[ S_n = \gamma\, S_{n-1} + K_n^\top V_n, \qquad \operatorname{Retention}(X_n) = Q_n S_n, \]

where different heads get different \(\gamma\) ("multi-scale" retention) and a GroupNorm replaces the softmax normalizer. A constant \(\gamma\) builds in an exponential recency bias, but it is data-independent: the layer cannot decide to keep one thing and drop another. Gated Linear Attention (GLA) makes the decay depend on the input, with a gate per key dimension: \(S_t = G_t \odot S_{t-1} + k_t^\top v_t\), where \(G_t = \alpha_t^\top \mathbf{1}\) repeats the row vector \(\alpha_t \in (0,1)^{d_k}\) across the value dimension (that is, \(S_t = \operatorname{Diag}(\alpha_t) S_{t-1} + k_t^\top v_t\)), and \(\alpha_t = \sigma(x_t W^1_\alpha W^2_\alpha + b_\alpha)^{1/\tau}\) with a rank-16 factorization and \(\tau = 16\) "to encourage the model to have a slower forgetting rate" [GLA, §4.1, §4.4, Tab. 1]. GLA's Table 1 shows that many recent recurrent layers are the same equation with a different gate parameterization: Mamba-2 uses a scalar \(\gamma_t\) shared by the whole state, RWKV-6 a per-key-dimension vector, and so on.

Decay is a trade, not a free lunch. It frees capacity by construction, but an item written at time \(s\) and read at \(t\) is multiplied by \(\prod_{u=s+1}^{t} \alpha_u\). Retrieving something far in the past requires the gates on its channels to have stayed near 1 the whole way, and the model must decide that at write time, before it knows what will be asked.

State-space models: S4, Mamba, Mamba-2

状态空间模型 (state-space models, SSMs) come from control theory and reach the same destination by a different road. S4 starts from a continuous linear system \(x'(t) = Ax(t) + Bu(t)\), \(y(t) = Cx(t)\), discretizes it with step size \(\Delta\) (S4 uses the bilinear rule) into a recurrence \(x_k = \bar A x_{k-1} + \bar B u_k\), and observes that because \(\bar A, \bar B, \bar C\) are the same at every step (the system is linear time-invariant, LTI), unrolling gives a global convolution \(y = \bar K * u\) with kernel \(\bar K = (\bar C\bar B, \bar C\bar A\bar B, \dots, \bar C\bar A^{L-1}\bar B)\), computed with FFTs for training. The recurrence gives constant-memory decoding. The hard part is choosing \(A\) so that the state remembers long histories (the HiPPO matrices) and computing \(\bar K\) stably; S4's normal-plus-low-rank parameterization reduces this to a Cauchy kernel with \(\tilde O(N + L)\) cost, and solved the 16K-length Path-X task that all prior models failed [S4, §2-3]. The weakness is exactly the LTI property: the dynamics are the same for every input, so the model cannot decide, based on content, what to store.

Mamba (selective SSM) removes that limitation by making the parameters functions of the input: \(B_t\) and \(C_t\) come from linear projections of \(x_t\), and the step size is \(\Delta_t = \tau_\Delta(\text{param} + s_\Delta(x_t))\) with a softplus \(\tau_\Delta\) [Mamba, §3.2, Alg. 2]. With the zero-order-hold rule \(\bar A_t = \exp(\Delta_t A)\), \(\bar B_t = (\Delta_t A)^{-1}(\exp(\Delta_t A) - I)\,\Delta_t B_t\) (Eq. 4), each channel runs

\[ h_t = \bar A_t\, h_{t-1} + \bar B_t\, x_t, \qquad y_t = C_t\, h_t. \]

A large \(\Delta_t\) drives \(\bar A_t \to 0\): the state resets and the current input is written. A small \(\Delta_t\) gives \(\bar A_t \approx I\): the state persists and the input is ignored. That is a content-dependent gate, and it is what lets Mamba solve the Selective Copying and Induction Heads tasks that LTI models fail. The price is that time-varying parameters break the convolution trick, so Mamba computes the recurrence with a hardware-aware parallel scan that materializes the expanded state (batch, length, channels, state dimension) only in fast SRAM, with recomputation in the backward pass. The paper reports 5x higher throughput than Transformers, and a 3B model that outperforms same-size Transformers and matches ones twice its size.

Mamba-2 makes one restriction and gets a theory in return. The matrix \(A\) becomes a scalar times the identity per head, \(A_t = a_t I\), and the head dimension \(P\) becomes 64 or 128 instead of Mamba's 1 [Mamba-2, §2.4]. Unrolling the recurrence shows the whole layer is a matrix product \(Y = MX\) with

\[ M = L \circ (C B^\top), \qquad L_{ji} = a_{j:i} = a_j a_{j-1} \cdots a_{i+1}\ (j \ge i),\ \text{else } 0. \]
SSD: structured state-space duality (Dao and Gu 2024, §5.1)

\(L\) is a 1-semiseparable mask, and \(M\) is exactly masked kernel attention with queries \(C\), keys \(B\), values \(X\) and a decay mask \(L\). If every \(a_t = 1\), \(L\) is the causal mask and the layer is ordinary causal linear attention. So a Mamba-2 layer is a linear-attention layer with a scalar, data-dependent decay, and the two vocabularies map one to one:

Delta-rule models: writing by error correction

Decay lets a linear-attention state forget, but it cannot edit. Suppose the state already stores a value under some key and the sequence now presents a new value under the same key (a variable being reassigned, a fact being corrected). Plain linear attention adds the new pair on top, so a later read returns the sum of old and new. The DeltaNet paper points to a related capacity problem: a purely additive rule makes it difficult to deallocate old associations, which "eventually leads to key collisions when \(L > d\)" [DeltaNet, §2.2]. The delta rule fixes this by writing only the error.

DeltaNet, derived carefully

Treat the state as the weights of a tiny linear regressor that maps keys to values, and take one online SGD step on the reconstruction loss at each token. In our row-vector convention (\(S \in \mathbb{R}^{d_k \times d_v}\), \(k_t \in \mathbb{R}^{1\times d_k}\), so the prediction for key \(k_t\) is \(k_t S\)):

\[ \mathcal{L}_t(S) = \tfrac12\,\big\| k_t S - v_t \big\|^2, \qquad \nabla_S \mathcal{L}_t = k_t^\top (k_t S - v_t). \]
\[ S_t = S_{t-1} - \beta_t\, k_t^\top (k_t S_{t-1} - v_t) = S_{t-1} + \beta_t\, k_t^\top \big(v_t - k_t S_{t-1}\big) = \big(I - \beta_t k_t^\top k_t\big) S_{t-1} + \beta_t\, k_t^\top v_t, \qquad o_t = q_t S_t. \]
DeltaNet recurrence (row-vector convention, \(S_t \in \mathbb{R}^{d_k \times d_v}\))

Read it as retrieve, compare, correct. \(k_t S_{t-1}\) is what the memory currently returns for key \(k_t\) (the "old value"), \(v_t - k_t S_{t-1}\) is the prediction error, and \(\beta_t \in (0,1)\) is a learned per-token write strength. Equivalently, with \(v^{\text{new}}_t = \beta_t v_t + (1-\beta_t) v^{\text{old}}_t\), the update removes the old association and writes the new one: \(S_t = S_{t-1} - k_t^\top v^{\text{old}}_t + k_t^\top v^{\text{new}}_t\). Linear attention is the same derivation applied to the loss \(-\langle k_t S, v_t\rangle\), which has no error term and so never corrects anything [Kimi Linear, §2.2].

Pitfall: three conventions in the literature

The DeltaNet paper stores \(S \in \mathbb{R}^{d_v \times d_k}\) and writes \(S_t = S_{t-1}(I - \beta_t k_t k_t^\top) + \beta_t v_t k_t^\top\) with column vectors and \(o_t = S_t q_t\) [DeltaNet, §2.2]. Kimi Linear uses \(S \in \mathbb{R}^{d_k \times d_v}\) with column vectors, \(S_t = (I - \beta_t k_t k_t^\top) S_{t-1} + \beta_t k_t v_t^\top\) and \(o_t = S_t^\top q_t\) [Kimi Linear, §2.2, §3]; that is the transpose of the DeltaNet form and identical to this page's form once column \(k_t\) is written as the row \(k_t\). When you write it on a whiteboard, state \(S\)'s shape and whether vectors are rows or columns first. The brief's shorthand "\(S_{t-1} + \beta_t (v_t - k_t S_{t-1})^\top k_t\)" is the DeltaNet-paper layout with row vectors.

Why this stores more. With unit-norm \(k_t\) and \(\beta_t = 1\), after the update \(k_t S_t = k_t S_{t-1} + (v_t - k_t S_{t-1}) = v_t\): the memory returns exactly the value just written for that key, replacing what was there (this is a test in the drill: writing \(v_1\) then \(v_2\) under the same key returns \(v_2\), where linear attention would return \(v_1 + v_2\)). For a key \(k_j\) orthogonal to \(k_t\), \(k_j (I - k_t^\top k_t) = k_j\), so the update does not disturb it. A \(d_k\)-dimensional key space can therefore hold \(d_k\) orthonormal associations exactly. The capacity is still bounded by the state size; the delta rule just uses it without waste. For stability, the eigenvalues of \(I - \beta k^\top k\) are 1 (with multiplicity \(d_k - 1\)) and \(1 - \beta\|k\|^2\), so DeltaNet applies L2 normalization to \(q\) and \(k\) (after a SiLU) and keeps \(\beta \in (0,1)\), which puts every eigenvalue in \([0,1]\) [DeltaNet, §3.3].

Chunkwise training: the WY and UT tricks

The update multiplies the state by a different rank-one-perturbed matrix at every step, and the recurrence looks inherently sequential. Unrolling shows a hidden linear structure: \(S_t = \sum_{i \le t} k_i^\top u_i\) with "pseudo-values" \(u_i = \beta_i (v_i - k_i S_{i-1}) = \beta_i\big(v_i - \sum_{j\lt i} (k_i k_j^\top)\, u_j\big)\), because \(S_{i-1} = \sum_{j\lt i} k_j^\top u_j\). So DeltaNet is linear attention with \(v\) replaced by \(u\) [DeltaNet, §3.1], and computing \(u\) within a chunk is a small triangular linear system. For a chunk of \(C\) tokens with incoming state \(S_0\) (rows are tokens):

\[ T = I + \operatorname{diag}(\beta)\,\operatorname{StrictTril}(K K^\top), \quad U = T^{-1}\operatorname{diag}(\beta)\,(V - K S_0), \quad O = Q S_0 + (Q K^\top \odot M)\,U, \quad S_C = S_0 + K^\top U. \]

I checked these four equations against the token-by-token recurrence numerically (they match to float precision). The published papers write the same thing with \(W = T^{-1}\operatorname{diag}(\beta)K\) and \(U' = T^{-1}\operatorname{diag}(\beta)V\), giving \((U' - W S_0)\) in place of \(U\) [Gated DeltaNet, Eqs. 8-9]. The \(T^{-1}\) comes from the WY representation of products of Householder-like matrices; the "UT transform" of Kimi Linear computes it by forward substitution and reduces the non-matmul FLOPs that would otherwise limit tensor-core use [Kimi Linear, §3.1, Eqs. 6-7]. The chunk cost is the linear-attention cost plus a \(C \times C\) triangular solve, so training stays \(O(T)\) in sequence length.

Gated DeltaNet and Kimi Delta Attention

The delta rule edits but is slow to clear: to erase an old item you must present its key. Decay clears everything at once but cannot target. Gated DeltaNet composes them with a scalar decay \(\alpha_t \in (0,1)\) [Gated DeltaNet, §3.1, Eq. 10]:

\[ S_t = \alpha_t\,\big(I - \beta_t k_t^\top k_t\big)\, S_{t-1} + \beta_t\, k_t^\top v_t. \]
Gated DeltaNet (row-vector convention). \(\alpha_t \to 0\) clears the state, \(\alpha_t \to 1\) is the pure delta rule.

The paper's online-learning view makes the roles precise (its Table 1): Mamba-2 relaxes linear attention's objective with a scale \(\alpha_t\) on the old state, DeltaNet uses the regression error, and Gated DeltaNet does both. Kimi Linear's Kimi Delta Attention (KDA) refines the decay from a scalar to a per-key-dimension diagonal gate [Kimi Linear, §3, Eq. 1]:

Kimi Linear also observes that a data-dependent transition acts like a learned multiplicative positional encoding, relaxing the orthogonality that RoPE imposes, and it applies NoPE to its full-attention layers, delegating position information to the KDA layers. Gated DeltaNet-2 (NVIDIA, May 2026) notes that even the delta-rule family uses a single scalar to control two different things, how much old content to erase and how much new content to write, and separates them into a channel-wise erase gate and a channel-wise write gate; it reduces to KDA when the two collapse to one scalar and to Gated DeltaNet when the decay also becomes scalar. At 1.3B parameters and 100B FineWeb-Edu tokens the authors report the strongest overall results among Mamba-2, Gated DeltaNet, KDA, and Mamba-3 variants, with the largest gains on RULER needle tasks [Gated DeltaNet-2, Abstract]. Problem
Plain linear attention piles new associations on old ones, and decay-only layers cannot edit a specific association.
Idea
Apply a delta-rule correction (write only the error) and a decay gate (clear the state when needed) in one update, trained with a chunkwise WY algorithm.
Why it works
The correction removes interference for keys already stored and lets orthogonal keys coexist; the gate frees capacity when context shifts. Both are cheap rank-one and scalar operations, so the layer stays \(O(T)\) with tensor-core friendly chunks.

Recall, and why hybrids won

Every fixed-state layer on this page is a lossy compressor of the past. The question that decides architecture is which lookups the state can still answer. This section gives the theory that says "not all of them", the evidence that a few softmax layers repair it, the verified hybrid recipes, the state-size arithmetic, and the counter-evidence.

The tension between constant state and exact recall

联想召回 (associative recall) means answering "what followed this key last time?" from the context: name-to-attribute lookups, variable reads, in-context translation, copying a span. Two theorems make the limitation precise. Based (Arora et al. 2024) proves that any recurrent model depending causally on the input needs \(\Omega(N)\) bits of state to solve multi-query associative recall (MQAR) over \(N\) tokens [Based, Thm. 3.1]. Jelassi et al. show that for the task of copying a uniformly random string, a fixed-size "generalized state-space model" with state space \(S\) has error above \(1 - |S|/D^L\) (for vocabulary size \(D\) and length \(L\)), so any such model with fewer than \(L \log D - 1\) bits of memory errs more than half the time, while a two-layer transformer of dimension \(O(n\log D)\) can copy strings of length up to \(D^n\) with small error [Jelassi et al. 2024, Thms. 2.3, 2.7, Cor. 2.8]. The argument is information-theoretic: \(B\) bits of state can distinguish only \(2^B\) contexts, but exact recall of arbitrary content needs bits proportional to the content. Attention avoids the bound by not compressing: the KV cache is the raw context, and even a few attention layers can address it by content (induction heads).

The empirical picture agrees:

  • Zoology. Across 17 pretrained models, gated-convolution and similar attention-free architectures trail attention by up to 2.1 perplexity points on the Pile, and 82% of that gap is explained by associative-recall ability; a 70M-parameter attention model beats a 1.4B-parameter gated-convolution model on recall [Zoology, Abstract]. The synthetic MQAR task, unlike earlier single-query versions, reproduces the real gap.
  • Based pairs a Taylor-feature linear attention with a tiny sliding window (64 to 128 tokens) and reports 10.36 accuracy points over Mamba on recall-intensive tasks and up to 24x higher generation throughput than FlashAttention-2 [Based, Abstract, Fig. 1]. It is a cheap hybrid: the window handles precise local comparison, the state provides bounded long-range memory.
  • NVIDIA's 8B study (up to 3.5T tokens): pure Mamba and Mamba-2 match or beat Transformers on many tasks but lag on 5-shot MMLU, Phonebook lookup, and long-context reasoning. An 8B hybrid with 43% Mamba-2, 7% attention, and 50% MLP layers beats the Transformer on all 12 standard tasks (+2.65 points on average), is predicted to generate up to 8x faster, and closely matches or exceeds it on 23 further long-context tasks [Waleffe et al. 2024, Abstract].
  • Jamba reports that a pure Mamba model fails to follow an in-context output format on IMDB where a hybrid with just 1 attention layer in 8 succeeds, and links this to induction heads [Jamba, §6].

Mamba-2's authors put the division of labor this way: SSM layers "function well as a general sequence-to-sequence mapping, and attention layers act as a retrieval mechanism" [Mamba-2, §9.2.3]. Qwen's 2026 architecture report phrases the same idea: recurrent layers compress the prefix at linear cost, while one full-attention layer in four "retains the direct token-level retrieval that no finite-state memory reproduces exactly" [Qwen3.8-Next, §1].

The counter-trend and the conflicting evidence

The story so far is "hybrids and sparse attention won". The evidence is less clean, and the most informative case is MiniMax, which has taken all three positions.

  • January 2025, MiniMax-01 bet on a 7:1 lightning hybrid. Its report found that pure lightning attention "demonstrates limited retrieval capabilities", so it interleaved softmax layers, and showed at 1B and 3B scale that hybrid-lightning beat a hybrid whose linear layers were replaced by sliding-window attention on needle retrieval (NIAH scores 95.7 versus 25.7 to 53.9 at 1B for windows 256 to 1024, and 98.0 versus 40.9 to 57.9 at 3B) [MiniMax-01, §2.2.3, Tabs. 3-4]. It also argued that hybrid-lightning has "larger capacity" than softmax because its recurrent state is \(O(d^2/h)\) versus \(O(d)\); that argument treats softmax as an RNN recomputed from scratch at each step, not the KV cache as the state, so I would not lean on it.
  • M2 (October 2025 blog by the pre-training lead; report published 2026) went back to full attention in all 62 layers (229.9B total, 9.8B active, 29.2T tokens, 192K maximum context, 48 query heads and 8 KV heads). The stated reasons [MiniMax-M2 report, §2.2.2], [MiniMax blog]: (1) evaluation difficulty: hybrids matched full attention on MMLU, BBH, MATH, and LongBench at small scale but showed "clear deficits in complex multi-hop reasoning" at larger scale, and their proxy metrics were "fragile"; (2) infrastructure: linear architectures are memory-bound even in training, and remain hard on low-precision storage, prefix caching, and speculative decoding; (3) failed SWA hybrids, described above. They add that they expect efficient attention to matter more as context grows and GPU scaling slows.
  • M3 (MSA paper, June 2026) moved to MiniMax Sparse Attention on a GQA base, not back to linear layers.

The positive results come from different places. Kimi Linear reports, under an identical recipe and 1.4T training tokens, MMLU-Pro 51.0 versus 47.2 and RULER at 128K 84.3 versus 81.3 against full MLA, with up to 75% less KV cache and up to 6x decoding throughput at 1M [Kimi Linear, Abstract, Fig. 1]. Qwen's 25B-A3B ablation (400B tokens at 4K plus 80B at 32K) has the GDN hybrid averaging 53.81 over nine benchmarks against 49.87 for full attention and 51.15 for an SWA hybrid with window 128 [Qwen3.8-Next, §2.1.1, Tab. 1]. MiMo found \(W=128\) SWA plus sinks better than all-global attention through 32K. Against these, GLM's team found that converting a pretrained model to any efficient variant lost accuracy: even the best conversion lost 5.69 RULER points at 128K "even when half of the layers retain full attention", and they concluded DSA was preferable because it discards no long-range dependency by construction [GLM-5, §2.1.2]. That last claim needs a caveat: top-\(k\) with \(k=2048\) can miss a relevant token, and their own Table 6 shows an indexer trained only in warm-up losing 7.9 RULER points at 128K before joint training recovers them.

How to reconcile them: (a) most positive results are small-scale or evaluated at 32K and below, most negative ones at 64K to 128K and on multi-hop tasks; (b) from-scratch training differs from conversion; (c) perplexity and knowledge benchmarks, the usual arbiters, are exactly the metrics that do not see the difference (MiniMax's Table 2 shows MMLU 85.5 versus 85.6 and identical 32K needle scores while 128K common-words extraction falls from 90.0 to 72.0). I know of no public head-to-head at 1M tokens between a GDN or KDA hybrid, a compressed-sparse design, and full attention under one recipe. As of September 2026 the models I checked from primary sources are, by family: GDN or KDA hybrids at 3:1 (Qwen3.5, Qwen3.8-Flash-Next, Kimi K3); learned sparse or compressed attention (DeepSeek-V3.2, GLM-5, DeepSeek-V4, MiniMax-M3, and Qwen's QSA); sliding window with sinks (gpt-oss, Gemma 4, MiMo-V2-Flash); and no pure linear or state-space model at the frontier.

What to ablate

  • Hybrid ratio and placement: 0:1, 1:1, 3:1, 7:1, 15:1 (Kimi Linear's grid), plus evenly spaced versus clustered global layers. Keep parameters and tokens fixed; compare at equal measured decode throughput, not FLOPs.
  • Linear-layer type: plain gated linear attention, Mamba-2, Gated DeltaNet, KDA, and the state size (\(d_k\)) at fixed parameters; the S-NIAH results above suggest the delta rule matters for recall.
  • Window and sinks: \(W \in \{128, 512, 4096\}\) with and without sink logits, evaluated after long-context extension, since MiMo's \(W=512\) failure only appears then.
  • Positional encoding in global layers: NoPE (Kimi Linear) versus RoPE. Sources disagree: Kimi found NoPE works when the linear layers carry position, while Qwen found NoPE showed a substantially higher rate of endless generation after post-training. Test through post-training, not just pretraining loss.
  • From scratch versus conversion: distilling an existing full-attention checkpoint (GLM's conversions, DSA's continued training) is far cheaper but lossy in reported cases.
  • Selector variants if going sparse: indexer size and compression (CSA, QSA), \(k\), block size, and whether selection is per KV group (MSA) or shared.

How to evaluate

  1. Synthetic recall as a unit test at small scale: MQAR, S-NIAH variants, copy, and phonebook lookup. They are cheap and they reproduce the real gaps (Zoology, Waleffe).
  2. RULER at several lengths, per-length curves. RULER has 13 tasks in four categories (retrieval, multi-hop tracing, aggregation, question answering), and found almost all models had large drops as length grew despite near-perfect vanilla NIAH [RULER, Abstract]. Vanilla NIAH is saturated and superficial; MiMo also reports NoLiMa and MRCR, and MiniMax HELMET.
  3. Position-wise loss (MoBA's diagnostic): trailing-token loss at the end of long sequences catches degradation that mean perplexity hides.
  4. After SFT and RL, at 2x to 4x your target length. MiniMax saw SWA gaps widen after SFT beyond 32K; GLM saw RL collapse with a nondeterministic top-k. Architectures must be tested in the regime they will run in (long agentic trajectories).
  5. Short-context regressions (MMLU-style) as a sanity check only. They passed for every design that later failed at long context.
  6. Systems metrics measured with real kernels: time per output token, prefill throughput, cache bytes, compatibility with prefix caching and speculative decoding (MiniMax's infrastructure concerns).

Long-context evaluations are noisy and expensive; MiniMax notes that the compute needed for statistically significant evaluation grows with task complexity. Use many needles, several seeds, and report confidence intervals per length before believing a two-point difference.

Open problems

  • A middle path between constant and linear state. Theory says exact recall needs \(\Omega(N)\) bits; practice shows most tokens are not needed. Compressed caches that grow sublinearly (V4's \(T/4\) and \(T/128\) entries) and selective eviction are one side; better-used fixed states (delta rules) are the other.
  • Selector cost at 1M and beyond. DSA's \(O(L^2)\) indexer motivated compression before scoring (CSA) and pooled indexers (QSA); hierarchical selection is open.
  • Training and inference consistency for sparse selection in RL. GLM-5 found nondeterministic top-k caused collapse within a few steps, an analogue of MoE routing replay, and worked around it by freezing the indexer and using a deterministic top-k.
  • Infrastructure for recurrent states. Prefix caching, speculative decoding, low-precision storage, and hybrid cache management are named by MiniMax as the practical obstacles; V4 needed a dedicated "state cache" for its sliding-window and uncompressed-tail entries.
  • Evaluation that predicts agentic long-horizon behavior. The whole field is calibrating on proxies that MiniMax reports were fragile.
  • Position encoding in hybrids. The NoPE and RoPE evidence is contradictory across labs.
A 1M-context architecture
Problem
At 1M tokens a full-attention 8B-class stack needs 128 GiB of cache per sequence and quadratic prefill; agentic and RL workloads make decode bandwidth the bottleneck.
Idea
Keep a small fraction of exact-retrieval layers (full, compressed, or sparse attention) and make the rest cheap (windows with sinks, or gated delta-rule layers), stacking reductions on the layer, token, feature, and byte axes.
Why it works
Exact recall needs an addressable memory in only a few layers (theory: \(\Omega(N)\) bits for recall; practice: about 1 in 4 to 1 in 8 attention layers restores it), while most layers do local or summary mixing that a small state handles.
Evidence
Kimi Linear (identical recipe, 3:1 beats full MLA), Qwen3.5 and K3 at frontier scale, V4 (27% of V3.2's FLOPs and 10% of its cache at 1M), against MiniMax-M2's negative SWA results and GLM's lossy conversions.
Cost
Kernel and cache-management complexity; evaluation that must go beyond perplexity; extra training stages for indexers; unresolved position-encoding choices.
Used by
See Table 8 and the sparse section; pick by whether your constraint is cache memory (favors E, D), bandwidth (C, D, E), or engineering risk (B, then A).

Common misconceptions

  • "Linear attention is softmax attention with a cheaper trick, so quality should match." It is a different function class with a fixed-size state. A positive kernel gives smooth, low-contrast weights, keys cross-talk, and exact recall needs \(\Omega(N)\) bits of state (Based Thm. 3.1). The gap is measurable: 82% of the Zoology perplexity gap is associative recall.
  • "An \(\ell\)-layer window-\(W\) model sees \(\ell W\) tokens, so it does not need global layers." The receptive field is a bound on where information can come from, not a capacity. A converted GLM-9B with 4096-token windows on half its layers falls to RULER 6.51 at 128K although its nominal reach is over 80K tokens.
  • "Sparse attention shrinks the KV cache." DSA, NSA, MoBA, and MSA keep every token's entries because any future query might select them. They cut FLOPs and bytes read. Cache shrinks only with MLA, compression (V4), windows, or fixed states.
  • "Attention sinks mean the first tokens are semantically important, and StreamingLLM extends the context." Replacing the first four tokens with newlines works almost as well (5.60 versus 5.40 perplexity); it is their position and global visibility that matter. StreamingLLM keeps generation stable; information older than the cache is gone.
  • "SSMs and attention are separate worlds." Mamba-2's SSD shows a scalar-decay SSM layer is masked linear attention with a 1-semiseparable decay mask. Only Mamba-1's per-channel selective scan sits outside the matmul family.
  • "If perplexity and MMLU match, the architecture is fine." MiniMax's SWA hybrid matched full attention on MMLU (85.6 versus 85.5) and on 32K needles while common-words extraction at 128K fell from 90.0 to 72.0. Use recall-heavy, length-swept, post-SFT evaluations.
  • "A hybrid can beat its ratio." The linear state is negligible next to the remaining KV cache, so the saving is about the ratio (3.95x at 1:3, 7.79x at 1:7 in Table 9). More needs a second reduction on another axis (MLA, compression, low precision).
  • "DeltaNet's write strength and key norm are free choices." The transition \(I - \beta k^\top k\) has eigenvalue \(1 - \beta\|k\|^2\), so unnormalized keys or \(\beta \ge 2/\|k\|^2\) make the state diverge. DeltaNet L2-normalizes \(q\) and \(k\) and keeps \(\beta \in (0,1)\).

Interview questions

Warm-up Why doesn't sliding-window attention lose all long-range information in a deep model?

Each layer lets a position read \(W-1\) positions back, and that position's hidden state already summarizes its own window from the layer below. Information therefore travels \(W-1\) positions per layer, and after \(\ell\) layers the top layer can depend on inputs about \(\ell(W-1)\) tokens away. Mistral 7B quotes this: \(W=4096\) and 32 layers give a "theoretical attention span of approximately 131K tokens".

The important qualification is that this is a reach bound, not a capacity. A fact 100K tokens back must be relayed through about 25 intermediate positions, each of which must attend to the previous link and copy it into a residual stream shared with everything else, through softmax averages that dilute it. Coarse information (topic, the entities in play) survives that chain; exact strings often do not. Evidence: converting a pretrained GLM-9B to 4096-token windows on half its layers, with no retraining, took RULER from 94.87 at 4K to 54.02 at 8K and 6.51 at 128K, and MiniMax's trained SWA hybrids lost 18 points on 128K common-words extraction while matching at 32K.

The fix used in practice is a minority of global layers (Gemma 3's 5:1, gpt-oss and MiMo's alternation), which take over exact long-range lookup. Local layers then only need to be good at local structure, and their cache is constant.

Warm-up What is an attention sink and why does it matter for streaming inference?

Softmax forces attention weights to sum to one, so a head with nothing relevant to read must put its mass somewhere. Trained causal models learn to dump it on the first few tokens, which every later position can see; StreamingLLM calls them attention sinks and shows Llama-2 attends heavily to the initial token in all layers beyond the bottom two. It is positional, not semantic: replacing the first four tokens with newlines barely changes perplexity.

This matters for streaming because a sliding window evicts the first tokens once the sequence exceeds the cache. That removes a large part of the softmax denominator in every head, and the attention distributions shift off what the model learned: Llama-2-13B perplexity went from 5.40 (4 sink tokens plus 1020 recent) to 5158 (1024-token window alone). The fix is to keep the KV of about 4 initial tokens plus a rolling window, and to assign positions inside the cache (with RoPE, cache keys before rotation and rotate at each step). This gives stable generation over millions of tokens at bounded memory, up to 22.2x faster than recomputing a window each step. It does not extend memory: older content is still gone.

Current models make the sink explicit: a learned per-head logit \(z'_h\) added to the softmax denominator (gpt-oss, MiMo-V2-Flash, DeepSeek-V4), so a head can attend to nothing. Without it, MiMo's window-128 model loses 2.4 MMLU points.

Warm-up Compute the decode state per sequence at 128K tokens for a Llama-3-8B-shaped model: full attention, a 1:7 hybrid, and pure linear attention.

Full attention: per token per layer the cache is \(2 \cdot n_{kv} \cdot d_h \cdot 2\ \text{B} = 2 \cdot 8 \cdot 128 \cdot 2 = 4096\) B. At \(T = 131{,}072\) that is 512 MiB per layer, and \(32 \times 512\) MiB \(= 16\) GiB.

Linear layer with \(H = 32\) heads and \(d_k = d_v = 128\): the state is \(32 \cdot 128 \cdot 128 \cdot 4\ \text{B} = 2\) MiB in fp32, independent of \(T\) (1 MiB in bf16).

1:7 hybrid: 4 attention layers and 28 linear layers. KV \(= 4 \cdot 512\) MiB \(= 2\) GiB, state \(= 28 \cdot 2\) MiB \(= 56\) MiB, total 2.055 GiB, a 7.79x reduction. Pure linear: \(32 \cdot 2\) MiB \(= 64\) MiB, 256x smaller. The 1:3 hybrid gives 4.047 GiB (3.95x).

Comments a strong answer adds: the state equals the KV cache at \(2\ \text{MiB}/4096\ \text{B} = 512\) tokens, so the advantage exists only at long context; the hybrid's saving is essentially its ratio because state is negligible; at 1M tokens the full stack is 128 GiB and the 1:7 hybrid still 16 GiB, so real designs stack a second reduction (MLA, compression).

Core Derive the recurrent form of causal linear attention. What is the state size?

Causal softmax attention is \(o_t = \sum_{s\le t} \exp(q_t k_s^\top/\sqrt{d})\, v_s \big/ \sum_{s\le t} \exp(q_t k_s^\top/\sqrt{d})\). Replace the exponential of a dot product with a factorizable kernel, \(\operatorname{sim}(q,k) = \phi(q)\phi(k)^\top\) with \(\phi\) positive (for example \(\operatorname{elu}+1\)). Then

\[ o_t = \frac{\phi(q_t)\sum_{s\le t}\phi(k_s)^\top v_s}{\phi(q_t)\sum_{s\le t}\phi(k_s)^\top}, \]

because \((\phi(q_t)\phi(k_s)^\top)v_s = \phi(q_t)(\phi(k_s)^\top v_s)\) by associativity and \(\phi(q_t)\) does not depend on \(s\). The sums depend only on the prefix, so with \(S_t = \sum_{s \le t}\phi(k_s)^\top v_s\) and \(z_t = \sum_{s\le t}\phi(k_s)^\top\):

\[ S_t = S_{t-1} + \phi(k_t)^\top v_t, \quad z_t = z_{t-1} + \phi(k_t)^\top, \quad o_t = \frac{\phi(q_t) S_t}{\phi(q_t) z_t}. \]

State size: \(S_t \in \mathbb{R}^{d_k \times d_v}\), so \(d_k d_v\) numbers per head (16,384 for 128 by 128) plus \(d_k\) for the normalizer, constant in \(t\). Per-token cost \(O(d_k d_v)\). The parallel form \(((\phi(Q)\phi(K)^\top)\odot M)V\) with row normalization gives identical outputs at \(O(T^2 d)\); the chunkwise form uses the parallel form within chunks and passes \(S\) between them. Mention the memory-capacity reading: \(S\) is an associative memory that can store about \(d_k\) key-value pairs before interference, which sets up the next question.

Core Why do pure linear-attention and SSM models underperform on retrieval? What fixes it?

Three reasons. (1) Information: a fixed state of \(B\) bits cannot hold arbitrary context. Based proves any recurrent model needs \(\Omega(N)\) bits of state for MQAR over \(N\) tokens; Jelassi et al. show a fixed-state model copying a random string of length \(L\) errs more than half the time below \(L \log D - 1\) bits, while a two-layer transformer copies exponentially long strings. (2) Interference and contrast: reads \(\phi(q)S\) sum over all stored pairs, with a positive kernel every pair contributes, and there is no exponential to sharpen the best match. (3) No editing: additive writes cannot overwrite.

Empirically, Zoology found 82% of the perplexity gap between attention-free models and attention comes from associative recall; a 70M attention model beat a 1.4B gated-convolution model on recall. Pure Mamba and Mamba-2 lag at 8B on 5-shot MMLU and phonebook lookup.

Fixes at two levels. Within the layer: decay and gates to free capacity (Mamba-2, GLA), the delta rule to overwrite (Gated DeltaNet, KDA), larger states (Mamba-2 allows 8x). These help but do not close the gap: Gated DeltaNet still retrieves under 30% on S-NIAH-2 at 8K at 1.3B. Across layers: keep a minority of softmax layers, 1 in 4 to 1 in 8. A 7% attention hybrid beat the Transformer on all 12 tasks in NVIDIA's 8B study, and Jamba's pure Mamba failed in-context formatting where a 1-in-8 hybrid succeeded. Or use a tiny window plus linear attention (Based).

Core Explain DeepSeek Sparse Attention. What does it save and what does it not?

A lightning indexer scores every earlier token for query \(t\): \(I_{t,s} = \sum_{j=1}^{H^I} w^I_{t,j}\operatorname{ReLU}(q^I_{t,j}\cdot k^I_s)\), with few heads (64), small dimension (128), ReLU, FP8. Top-\(k\) selection (\(k=2048\)) keeps those key-value entries, and MLA in its MQA mode attends only to them, so core attention is \(O(Lk)\) instead of \(O(L^2)\). The indexer is trained as a student of the dense attention: a dense warm-up with all else frozen minimizing \(\mathrm{KL}(p_t \| \softmax(I_t))\) (2.1B tokens), then sparse training with the indexer detached from the language-modeling loss (943.7B tokens).

Saves: core attention FLOPs and the bytes read per decoded token. My estimate for V3.2 shapes at 128K: 13.4x fewer FLOPs per layer (36.5 GFLOP dense versus 0.57 core plus 2.15 indexer) and 7.9x fewer bytes.

Does not save: (a) the KV cache, since every token must stay selectable, plus the indexer's own keys; (b) the indexer is still \(O(L^2)\): 16,384 FLOPs per key versus 278,528 for dense MLA core attention, so the total saving saturates at about 17x and the indexer is 30x the sparse core at 1M. That is why V4 compresses before indexing and Qwen pools its indexer. Also note discontinuity: top-\(k\) selection caused RL instability until GLM-5 used a deterministic top-\(k\) and froze the indexer.

Core Mamba versus linear attention versus Gated DeltaNet: what distinguishes them?

All three carry a matrix-valued state written with a key-value outer product and read with a query. They differ in how the old state is transformed before the write (Table 7).

  • Linear attention: \(S_t = S_{t-1} + k_t^\top v_t\). No decay, no editing; the state saturates and cross-talks.
  • Mamba (selective SSM): input-dependent \(\Delta_t, B_t, C_t\) and a diagonal \(A\); the decay \(\exp(\Delta_t A)\) is content-dependent and per state channel, so Mamba can reset or persist based on the token. It forgets but never edits. Per-channel time-varying dynamics cannot be written as matmuls, so it needs a hardware-aware parallel scan. Mamba-2 restricts \(A\) to a scalar per head, which makes the layer masked linear attention with a decay mask (queries \(C\), keys \(B\), values \(x\)) and allows chunked matmul training and larger states.
  • Gated DeltaNet: \(S_t = \alpha_t(I - \beta_t k_t^\top k_t)S_{t-1} + \beta_t k_t^\top v_t\). The delta-rule term reads what the memory holds for \(k_t\) and writes only the error (an online SGD step on \(\tfrac12\|k S - v\|^2\)), so it can overwrite and keeps orthogonal keys from interfering. The scalar gate \(\alpha_t\) clears memory wholesale. Trained by a chunkwise WY/UT algorithm.

Evidence: at 1.3B on S-NIAH, delta-only is strong on a single needle but drowns in distractors (14.4% on number-in-haystack at 8K), decay-only forgets the needle (30.4% pass-key at 8K), and the combination is best (91.8% and 29.6%). KDA further makes the decay per key dimension.

Core Compute the prefill FLOPs ratio of full attention versus a sliding window (W = 4096) at T = 128K for Llama-3-8B. Why is the whole-model saving so much smaller than the attention saving?

Causal pairs: full \(T(T+1)/2 = 8{,}590{,}000{,}128\); window \(W(W+1)/2 + (T-W)W = 528{,}484{,}352\). Ratio 16.25 (not \(T/W = 32\), since causal full attention already skips half the square). Each pair costs \(4 n_h d_h = 16{,}384\) FLOPs per layer, so attention is \(4.50\times10^{15}\) versus \(2.77\times10^{14}\) over 32 layers.

Windowing does not touch the projections and MLP: \(2NT = 2 \cdot 6{,}979{,}321{,}856 \cdot 131072 = 1.83\times10^{15}\) FLOPs, where \(N\) counts matmul parameters excluding embeddings. Totals: \(6.33\times10^{15}\) versus \(2.11\times10^{15}\), a 3.01x ratio. Attention is only 71% of full prefill at 128K, so removing nearly all of it leaves the dense matmuls.

Follow-up points: the whole-model gain grows with \(T\) (1.41x at 32K where attention is 38% of prefill, 17.9x at 1M where it is 95%) and shrinks with model width. Decoding is different, because reads are dominated by the cache: there the window cuts bytes by \(T/W = 32\) for that layer.

Core Write the DeltaNet update, say why it improves recall, and explain how it is trained in parallel.

With \(S \in \mathbb{R}^{d_k\times d_v}\) and row vectors (state the convention first): \(S_t = S_{t-1} + \beta_t k_t^\top (v_t - k_t S_{t-1}) = (I - \beta_t k_t^\top k_t)S_{t-1} + \beta_t k_t^\top v_t\), \(o_t = q_t S_t\). It is one SGD step with rate \(\beta_t\) on \(\tfrac12\|k_t S - v_t\|^2\): read the current prediction \(k_t S_{t-1}\), and write the error along \(k_t\).

Why recall improves: with \(\|k_t\| = 1\) and \(\beta_t = 1\), \(k_t S_t = v_t\) exactly, so re-writing a key replaces the old value instead of adding to it; keys orthogonal to \(k_t\) are unchanged, so \(d_k\) orthonormal pairs coexist without cross-talk. Stability needs \(\|k\|=1\) and \(\beta\in(0,1)\) because the transition's eigenvalues are 1 and \(1-\beta\|k\|^2\).

Parallel training: unrolling gives \(S_t = \sum_{i\le t}k_i^\top u_i\) with pseudo-values \(u_i = \beta_i(v_i - \sum_{j\lt i}(k_ik_j^\top)u_j)\). Within a chunk of \(C\) tokens with incoming state \(S_0\): \(T = I + \operatorname{diag}(\beta)\operatorname{StrictTril}(KK^\top)\), \(U = T^{-1}\operatorname{diag}(\beta)(V - KS_0)\), \(O = QS_0 + (QK^\top\odot M)U\), \(S_C = S_0 + K^\top U\). The triangular inverse comes from the WY representation of Householder-like products, and the UT transform computes it with few non-matmul FLOPs. Cost is linear-attention cost plus a \(C\times C\) triangular solve.

Core MiniMax used a 7:1 lightning-attention hybrid in MiniMax-01, full attention in M2, and sparse attention in M3. What happened, and what does it teach about evaluating architectures?

MiniMax-01 (Jan 2025) found pure lightning attention had "limited retrieval capabilities", interleaved a softmax layer every 8, and showed hybrid-lightning beating hybrid-SWA on needle retrieval at 1B and 3B. For M2 the pre-training lead wrote (Oct 2025; the 2026 report repeats it) that they found no efficient variant that reliably matched full attention in production settings, for three reasons. Evaluation: hybrids matched on MMLU, BBH, MATH, and LongBench at small scale, but at larger scale showed clear deficits on multi-hop reasoning, and proxy metrics were fragile. Infrastructure: linear layers are memory-bound even in training, sensitive to low-precision storage, and awkward with prefix caching and speculative decoding. SWA hybrids: extensively tested with hundreds of billions to trillions of tokens, they degraded retrieval, multi-hop, and in-context learning, and after SFT were significantly worse beyond 32K. M3 then adopted MiniMax Sparse Attention (28.4x less attention compute at 1M in a 109B model).

Lessons. Standard benchmarks and perplexity do not discriminate: M2's Table 2 shows MMLU 85.5 versus 85.6 and equal 32K needles beside 90.0 versus 72.0 on 128K common-words extraction. Test at target length, after SFT, on multi-hop tasks. Infrastructure readiness is a first-class criterion. And it is not a verdict against linear hybrids: Kimi Linear and Qwen report wins under matched budgets, on different evaluations and recipes. The productive reading is that the conclusion depends on what you measure.

Deep-dive You are designing a 1M-context model. Which attention architecture would you choose and how would you validate it?

First pin down what binds: decode bandwidth (long agentic or RL rollouts, many concurrent sequences), prefill compute, or cache capacity. At 1M an 8B-class GQA stack needs 128 GiB per sequence, so capacity and bandwidth both bind, and I would not ship plain full attention.

Candidates, in order of risk. (1) Interleaved local/global at about 5:1 with small windows (128 to 1024) and sink logits on top of GQA or MLA: about 6x less cache, well understood. (2) A 3:1 Gated DeltaNet or KDA hybrid with MLA or GQA global layers, with a stacked reduction in the global layers: it makes 3/4 of layers constant-memory (Kimi K3: 27 GiB plus 0.4 GiB state at 1M). (3) Compressed sparse attention in the V4 style: the smallest cache (about 4.8 GiB at 1M by my estimate) but heavy engineering. I would pick (2) as the main bet with (1) as the low-risk arm, and keep a full-attention twin as the control.

Validation: same parameters and tokens; ablate ratio (1:1 to 15:1), placement, window and sinks, gate type and state size, NoPE versus RoPE. Evaluate in a ladder: MQAR and S-NIAH at small scale, RULER at 32K to 1M with per-length curves (not vanilla NIAH), position-wise loss, then after SFT and RL at 2 to 4 times the training length; use perplexity and MMLU only as regression checks. Compare on measured time per output token and prefill throughput with real kernels, and check prefix caching and speculative decoding work. Decide on the quality-versus-throughput Pareto frontier, with confidence intervals per length.

Deep-dive Compare DeepSeek-V4's CSA/HCA with a Gated-DeltaNet hybrid. What does each keep and what does each lose?

Both attack the sequence axis of the cache but differently. V4 keeps an addressable memory in every layer: CSA merges each 4 tokens into one entry with a learned softmax (overlapping windows) and selects the top 1024 (Pro) with a lightning indexer; HCA merges 128 tokens and attends densely; a 128-token window keeps recent tokens exact. Lost: within-block token identity, since a merged entry is a learned mixture (the window and the small \(m=4\) mitigate it), and the \(O(L^2/m)\) indexer remains. Cache still grows as \(T/4\) and \(T/128\); my estimate at 1M is 4.83 GiB for Pro, and the report gives 10% of V3.2's cache and 27% of its FLOPs. Costs: custom KV cache management (a separate state cache for the window and tail), FP8 and FP4 kernels.

A GDN hybrid makes 3 in 4 layers constant-memory with a fixed state (Qwen3.5: 180 MiB for 45 layers) and keeps every token exactly in the remaining global layers, so its cache is 1/4 of a full model's (30 GiB at 1M for Qwen3.5, 27 GiB for K3 with MLA). Lost: exact recall in the linear layers (fixed capacity), so retrieval must route through the global layers. Costs: recurrent-state infrastructure (prefix caching, precision) and chunkwise kernels; position-encoding choices.

Trade-off summary: V4 preserves exact-content addressing everywhere at reduced fidelity and has the smaller cache at 1M; the hybrid removes memory from most layers entirely and has cheaper layers, but relies on the few global layers for recall. There is no public equal-recipe comparison, so I would measure both on recall-heavy tasks at target length and on throughput before choosing.

Deep-dive Gemma 3 uses 5:1 local/global with a 1024-token window, MiMo-V2-Flash uses 5:1 with a 128-token window, and MiniMax found SWA hybrids degrade beyond 32K. How would you choose a window size, and what would you test?

The window is cheap: it costs \(4 n_h d_h W\) FLOPs and \(2 n_{kv}d_hW\) cache entries per layer, so even \(W=4096\) is 1/32 of full attention at 128K. The real question is what the local layers are for. MiMo's 32B dense ablation suggests they should be pure local mixers: with sinks, \(W=128\) and \(W=512\) look alike on general benchmarks, but after long-context extension \(W=512\) collapses (NoLiMa 38.5 versus 49.7 all-global, MRCR 19.6 versus 32.5) while \(W=128\) slightly beats all-global. Their hypothesis is a division of labor: a tight window forces long-range work into the global layers, while a medium window lets local layers half-solve it and blurs the split. Gemma 3's ablations found perplexity insensitive to the window from 4096 down to 512, which is exactly the metric that cannot see this.

MiniMax's negative results are compatible: their hybrids may have relied on SWA layers for some long-range work, and their evaluations go past 32K where MiMo's stop. I would test: (1) sink logits on and off; (2) window sizes 128, 512, 4096 and the global fraction (1:1 to 1:7), evaluated after context extension; (3) RULER and multi-hop tasks per length, out to well beyond 32K; (4) position-wise loss; (5) from scratch versus conversion. I would default to a small window, sinks, and a global layer every 4 to 6, and revise from the per-length curves.

Deep-dive Your hybrid matches the full-attention baseline on perplexity and MMLU but fails needle retrieval at 128K. How do you debug it?

Start by localizing. (1) Sweep length: does it fail from a certain length (and is that length beyond what training and extension covered)? (2) Sweep task type with RULER's categories: single needle, multi-key, multi-hop, aggregation. Single-needle failure points at the global layers not learning retrieval; multi-key or aggregation failure points at state capacity in linear layers.

Then test causes. Architecture: too few or badly placed global layers (try 1:3 and even spacing), or a window in local layers so large that it blurs the division of labor (MiMo). Position: global layers with RoPE trained only to short lengths, or NoPE versus RoPE mismatch; check extension recipe (page 10). Numerics: state precision (linear layers are sensitive to low-precision storage), gate initialization that forgets too fast (\(\alpha\) near 0), missing L2 normalization of keys in delta-rule layers, chunk-size or kernel bugs; verify recurrent and chunkwise forms match token by token, as the drill does. Data: too little long-range-dependent data. Inference: prefix caching or quantization corrupting states.

Probes: check attention heads in the global layers for retrieval behavior (do they attend to the needle?); replace linear layers by full attention in a small ablation to see how much recall returns; compare with the full-attention twin trained on the same tokens. Only after such controls decide whether to change the ratio, the layer type, or the training data.

Hands-on

Beyond full attention. One module with six pieces, all on small tensors, all testable on CPU: sliding_window_mask and sliding_window_attention (window counts keys including the query, so it matches a rolling buffer), linear_attention_parallel and linear_attention_recurrent (causal, \(\operatorname{elu}+1\) feature map, with normalizer; the tests assert the two forms agree), delta_rule_recurrent (DeltaNet, row-vector convention, no normalizer, checked against a naive loop and against the overwrite property), and topk_sparse_attention (causal attention over the top-\(k\) keys chosen by given index scores, the core-attention half of DSA). exercises/drills/efficient_attention.py

The tests include a receptive-field check (two stacked window-3 layers reach 4 positions back and no further) and a no-future-leakage check for top-\(k\).

  2. Xiao et al. (2023). Efficient Streaming Language Models with Attention Sinks. Why read it: the explanation of sinks, Table 1 and Table 3 (sink token ablation), and the honest limitation that memory is not extended.
  3. Jiang et al. (2023). Mistral 7B, with Gemma Team (2025). Gemma 3 Technical Report. Why read them: sliding window and rolling buffer in §2 of Mistral; Gemma 3's 5:1 interleave and its ratio, window, and KV-memory ablations (§5.2).
  4. DeepSeek-AI (2025). DeepSeek-V3.2, with Yuan et al. (2025). Native Sparse Attention. Why read them: DSA's indexer, top-k selection, and two-stage KL training (§2.1), and NSA's three-branch design and memory-access argument.
  5. Dao and Gu (2024). Transformers are SSMs: Generalized Models and Efficient Algorithms Through Structured State Space Duality. Why read it: the SSM-attention duality (§5), the chunked algorithm, and the hybrid ablation (§9.2.3). Pair with S4 and Mamba for the lineage.
  6. Yang et al. (2024). Gated Delta Networks, with Yang et al. (2024). Parallelizing Linear Transformers with the Delta Rule. Why read them: the delta-rule derivation and WY chunkwise algorithm (DeltaNet §2 to §3), and the gated delta rule with its S-NIAH evidence.
  7. Arora et al. (2023). Zoology: Measuring and Improving Recall in Efficient Language Models, with Arora et al. (2024). Simple linear attention language models balance the recall-throughput tradeoff (Based). Why read them: the 82% recall-gap finding and MQAR, and the Omega(N) state lower bound.
  8. Kimi Team (2025). Kimi Linear: An Expressive, Efficient Attention Architecture. Why read it: KDA, the chunkwise UT algorithm, and the cleanest public hybrid-ratio and NoPE ablations (§5).
  9. MiniMax (2026). The MiniMax-M2 Series, with MiniMax (2025). MiniMax-01. Why read them: §2.2.2 of M2 is the best primary account of why a lab left efficient attention, with the Table 2 numbers; MiniMax-01 is the case for the other side.
  10. DeepSeek-AI (2026). DeepSeek-V4: Towards Highly Efficient Million-Token Context Intelligence. Why read it: §2.3 for CSA and HCA (Eqs. 9 to 27) and §2.3.4 for the cache and FLOPs accounting at 1M tokens.
  11. Hsieh et al. (2024). RULER: What's the Real Context Size of Your Long-Context Language Models? Why read it: the evaluation you should use to validate any efficient-attention model instead of vanilla needle-in-a-haystack.

Cheat sheet

  • Three savings: FLOPs (prefill), bytes read per decoded token, resident memory. Sparse top-k saves the first two; windows, MLA, compression, and fixed states save memory too.
  • Llama-3-8B at 128K: cache 4096 B per token per layer, 512 MiB per layer, 16 GiB in total. Linear state 32 x 128 x 128 x 4 B = 2 MiB per layer. Hybrids: 1:3 gives 4.047 GiB (3.95x), 1:7 gives 2.055 GiB (7.79x), pure linear 64 MiB.
  • Window: \(W\) keys including self; cache slot \(i \bmod W\); receptive field about \(\ell(W-1)\), a bound only. Causal pairs: full \(T(T+1)/2\), window \(W(W+1)/2 + (T-W)W\). At 128K, W=4096: 16.25x fewer pairs, 3.01x fewer total prefill FLOPs (attention is 71% of prefill).
  • Configs: Gemma 2 alternates 1:1 (window 4096); Gemma 3 5:1, window 1024; gpt-oss alternates with banded 128; MiMo-V2-Flash 5:1, window 128 with sink bias.
  • Sinks: softmax must sum to 1; keep ~4 initial KV plus a rolling window; positions within the cache; \(s = e^{z_j}/(\sum_k e^{z_k} + e^{z'_h})\) for a learned sink logit. Llama-2-13B: 5158 versus 5.40 perplexity.
  • Linear attention: \(S_t = S_{t-1} + \phi(k_t)^\top v_t\), \(z_t = z_{t-1} + \phi(k_t)^\top\), \(o_t = \phi(q_t)S_t/\phi(q_t)z_t\); state \(d_k \times d_v\). Decay: RetNet \(\gamma S\), GLA \(\operatorname{Diag}(\alpha_t)S\), Mamba-2 \(a_t S\).
  • Mamba-2 (SSD): \(M = L \circ (CB^\top)\), \(L_{ji} = a_{j:i}\); \(C, B, x \leftrightarrow q, k, v\).
  • DeltaNet (row convention): \(S_t = (I - \beta k^\top k)S_{t-1} + \beta k^\top v\); GDN adds \(\alpha_t\); KDA uses \(\operatorname{Diag}(\alpha_t)\). Need \(\|k\|=1\), \(\beta \in (0,1)\). Chunkwise: \(U = T^{-1}\operatorname{diag}(\beta)(V - KS_0)\).
  • Recall: exact recall of \(N\) tokens needs \(\Omega(N)\) bits (Based Thm. 3.1); keep 1 in 4 to 1 in 8 layers as full attention. Kimi Linear val PPL: 3:1 5.65, 7:1 5.70, 15:1 5.82, pure MLA 5.77.
  • DSA: \(I_{t,s}=\sum_j w_j \operatorname{ReLU}(q_j\cdot k_s)\), top-2048, MQA-mode MLA; warm-up 2.1B tokens (KL), sparse 943.7B. Saves core FLOPs and bytes; not cache; indexer \(O(L^2)\), saving capped near 17x.
  • NSA: compressed + selected + window, gated; 11.6x decode at 64K (5,632 versus 65,536 tokens read). MoBA: top-k blocks by mean-pooled key. MSA: per-GQA-group block selection, 28.4x attention compute at 1M.
  • DeepSeek-V4: CSA (merge 4, top-k 1024 Pro or 512 Flash) and HCA (merge 128, dense), 128-token window, shared 512-dim KV entries, sink logits; 1M tokens: 27% of V3.2 FLOPs, 10% of cache, about 2% of a GQA-8 BF16 baseline.
  • Conflicting evidence: Kimi Linear (3:1 KDA beats MLA at 1.4T tokens) and Qwen (GDN hybrid beats full attention at 25B-A3B) versus MiniMax-M2 (SWA hybrids degrade beyond 32K) and GLM (conversions lose accuracy). Perplexity and MMLU do not discriminate.
  • Validate with: MQAR and S-NIAH (small), RULER per length (13 tasks, 4 categories), position-wise loss, post-SFT and post-RL tests at 2 to 4 times training length, and measured decode throughput.
