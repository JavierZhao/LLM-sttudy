Beyond full attention: sparse, linear, SSM, hybrid

P1 ~75 min Prereqs: 03 Attention, 05 Positional encoding, 06 Decoding & KV cache, 07 KV-efficient attention

Full attention pays \(O(T^2)\) compute and an \(O(T)\) cache to keep every token exactly addressable. Every alternative gives up some of that exactness to save FLOPs, bytes read, or resident memory. This page derives each family, states what it trades away (almost always exact recall), and explains why, as of September 2026, frontier open models use hybrids and learned sparse attention rather than pure linear or state-space models.

The cost landscape: what to save, and what it costs

Page 06 established the two regimes. In training and prefill, full attention computes all \(T(T+1)/2\) causal pairs, \(O(T^2 d)\). In decoding, each new token reads the whole KV cache and does \(O(Td)\) FLOPs against it, so bytes read per step and resident cache both grow as \(O(T)\); decoding is memory-bound, with arithmetic intensity about \(n_h/n_{kv}\) FLOPs per byte. Page 07 attacked the feature axis of the cache (MQA, GQA, MLA). This page attacks the sequence axis, and asks whether the cache must be a list of tokens at all.

Three quantities can be saved, and methods differ in which they touch. FLOPs in prefill and training fall with any method that computes fewer query-key pairs. Bytes read per decoded token (decode latency and throughput) fall when fewer entries, or a smaller state, are read. Resident memory (the batch and context that fit on a GPU) falls only if entries are dropped, merged, or replaced by a fixed-size state. Learned top-k selection cuts FLOPs and bytes but leaves resident memory untouched.

A useful organizing view: a sequence mixer keeps a memory of the past, and families differ in its shape. Full attention is an append-only list (grows, lossless). A sliding window is a truncated list (constant, older tokens forgotten). Sparse attention is a list plus a selector (grows, but each query reads \(k\) entries by content). MLA and DeepSeek-V4 use a compressed list. Linear attention, SSMs, and delta-rule models keep a fixed-size matrix state of \(d_k \times d_v\) numbers per head, so retrieval is approximate by construction.

Table 1 puts numbers on four of these. The shapes are the reference Llama-3-8B layer (\(n_h=32\), \(n_{kv}=8\), \(d_h=128\), bf16 cache) at \(T = 128\text{K} = 131{,}072\). The linear row uses \(H=32\) heads, \(d_k=d_v=128\), and an fp32 state, a conservative choice (MiniMax reports linear attention is more sensitive to low-precision storage than full attention [MiniMax-M2 report, §2.2.2]).

Key idea

The linear layer does 1,024 times fewer FLOPs than the full-attention layer at 128K, but its intensity is worse (2.1 MFLOP over 4 MiB moved is 0.5 FLOPs per byte, versus 4.0). It is still memory-bound, and wins because it moves 256 times fewer bytes. The fp32 state equals the KV cache at \(2\ \text{MiB} / 4096\ \text{B} = 512\) tokens, so below that the state is larger; the entire benefit is at long \(T\). Because decoding is bandwidth-bound, real speedups track memory access volume, not FLOPs: NSA's paper says its decode speedup is "approximately linear with the volume of memory access" [NSA, §5.2, Tab. 4]. Prefill is compute-bound, so a smaller cache may do nothing for training cost, and vice versa.

Local attention and sliding windows

Language is mostly local. 滑动窗口注意力 (sliding-window attention) lets query \(i\) attend only to the \(W\) most recent keys. Longformer introduced it for encoders, with \(w/2\) tokens on each side, cost \(O(n \cdot w)\), optional dilation, and a few task-specific "global" tokens that see and are seen by everything [Longformer, §3.1]. For a causal model the window is one-sided. In this page's convention (and the drill's), \(W\) counts the keys a query sees including itself:

\[ M^{\text{sw}}_{ij} = \mathbb{1}[\,i - W \lt j \le i\,], \qquad \operatorname{Attn}_i = \softmax_{j:\,M_{ij}=1}\!\left(\frac{q_i k_j^\top}{\sqrt{d_h}}\right) V. \]

Why depth restores long-range reach, and why it is only a bound

One layer moves information \(W-1\) positions. Stack \(\ell\) layers and the top layer at position \(i\) can depend on inputs about \(\ell (W-1)\) positions back. Longformer gives a top-layer receptive field of \(\ell \times w\), "similar to CNNs" [Longformer, §3.1], and Mistral 7B argues the same: with \(W = 4096\) and 32 layers, "a theoretical attention span of approximately 131K tokens" [Mistral 7B, §2] (\(32 \times 4096 = 131{,}072\)).

"Theoretical" is the operative word: the receptive field bounds where information can come from, not a capacity. A token 100K positions back reaches the output only through about 25 relay positions, each a softmax average in a shared residual stream. Coarse information survives that; exact strings often do not. When GLM's team converted a 40-layer GLM-9B by replacing half its layers with 4096-token windows (no retraining), RULER fell from 95.19 to 94.87 at 4K, then 54.02 at 8K, 25.89 at 16K, and 6.51 at 128K [GLM-5, §2.1.2, Tab. 4], though 20 window layers nominally reach \(20 \times 4096 = 81{,}920\) tokens. A model trained to relay does better, but MiniMax's SWA hybrids (continued pretraining on hundreds of billions to trillions of tokens) still lost accuracy: RULER at 128K fell from 90.0 to 72.0 on common-words extraction and from 99.0 to 93.0 on multi-query needles, while 32K scores were identical [MiniMax-M2 report, §2.2.2, Tab. 2].

The rolling-buffer cache

A window layer never looks back more than \(W\) tokens, so its cache can be fixed-size. Mistral stores position \(i\)'s keys and values in slot \(i \bmod W\), overwriting the entry that just left the window, so "the size of the cache stops increasing" and on a 32K sequence memory falls 8x "without impacting model quality" [Mistral 7B, §2] (\(32768/4096 = 8\)). For prefill it chunks the prompt using the window as the chunk size.

import torch

class RollingKV:
    """Fixed-size KV cache for one sliding-window layer (batch 1, one KV head)."""
    def __init__(self, W: int, d: int):
        self.W, self.k, self.v, self.n = W, torch.zeros(W, d), torch.zeros(W, d), 0
    def append(self, k_t, v_t):           # k_t, v_t: (d,)
        slot = self.n % self.W            # position i is stored at i mod W
        self.k[slot], self.v[slot] = k_t, v_t
        self.n += 1
    def read(self):                       # keys, values currently inside the window
        m = min(self.n, self.W)           # slot order is scrambled, which softmax does not care about
        return self.k[:m], self.v[:m]     # (RoPE is applied to keys before caching, so relative positions survive)

Interleaved local and global layers

If local layers cannot do long-range lookup, give that job to a few layers that can. Verified configurations:

  • Gemma 2 alternates 1:1, local window 4096, global span 8192 [Gemma 2, §2]. Gemma 3 uses 5 local layers per global layer with a 1024-token window; RoPE base 10k on local and 1M on global layers [Gemma 3, §2]. Perplexity is barely affected by the ratio (even 7:1) or by windows down to 512; at 32K a 2B global-only model has a 60% KV-cache memory overhead versus under 15% at 1:3 with a 1024 window [Gemma 3, §5.2, Figs. 3-6].
  • gpt-oss alternates banded (128-token) and dense layers, with 64 query heads of dimension 64, 8 KV heads, and YaRN extending the dense layers to 131,072 tokens [gpt-oss model card, §2.2].
  • Gemma 4 keeps 5:1 (4:1 at 2.3B) with p-RoPE, KV sharing, and keys reused as values in global layers, cutting global KV cache by up to 37.5% [Gemma 4 report, §1]. MiMo-V2-Flash (309B, 15B active) uses 5:1, a 128-token window, and a learnable sink bias: "nearly a 6x reduction in KV-cache storage and attention computation" [§1].

Windows span a factor of 32 (128 to 4096). MiMo's 32B dense ablation (250B tokens at 8K, 40B at 32K, then SFT) shows why a small one can work and a medium one fail: with sinks, \(W=128\) and \(W=512\) match all-global on general benchmarks, but after long-context extension \(W=512\) collapses on NoLiMa (38.5 versus 49.7 all-global) and MRCR (19.6 versus 32.5) while \(W=128\) slightly exceeds all-global (51.2, 34.4) [MiMo-V2-Flash, §2.2.1, Tabs. 2-3]. Their hypothesis is a division of labor: a tight window forces local layers to handle local structure and delegate long-range work to global layers, while a medium window blurs the split. It is empirical and setup-specific, and in tension with MiniMax's finding, though MiMo's long-context evaluations stop at 32K, where MiniMax saw SWA hybrids diverge.

Worked number: prefill FLOPs, full versus window

For the Llama-3-8B stack at \(T = 131{,}072\), \(W = 4096\), count causal pairs. Full attention computes \(T(T+1)/2 = 131072 \cdot 131073 / 2 = 8{,}590{,}000{,}128\) pairs per layer; a window computes \(W(W+1)/2 + (T-W)W = 8{,}390{,}656 + 520{,}093{,}696 = 528{,}484{,}352\) (a ramp for the first \(W\) queries, then \(W\) each). The ratio is 16.25, not \(T/W = 32\), because causal full attention already skips half the square.

Each pair costs \(4 n_h d_h = 16{,}384\) FLOPs per layer, so attention totals \(16384 \cdot 32 \cdot 8{,}590{,}000{,}128 = 4.50 \times 10^{15}\) versus \(2.77 \times 10^{14}\) windowed. But the projections and MLP are untouched: with \(6{,}979{,}321{,}856\) matmul parameters outside the embeddings (per layer \(4096^2 + 2 \cdot 4096 \cdot 1024 + 4096^2 + 3 \cdot 4096 \cdot 14336 = 218{,}103{,}808\), times 32), \(2NT = 2 \cdot 6{,}979{,}321{,}856 \cdot 131072 = 1.83 \times 10^{15}\). Totals: \(6.33 \times 10^{15}\) versus \(2.11 \times 10^{15}\), a ratio of 3.01x. Attention is 71.1% of full prefill at 128K, so the windowed model is dominated by projections and MLP. The whole-model gain grows with \(T\) (1.41x at 32K, 17.9x at 1M) and shrinks for wider models.

Attention sinks

Pure window attention has a puzzling failure. StreamingLLM ran Llama-2-13B on the first PG-19 book (65K tokens) with a 1024-token window and got perplexity 5158.07; keeping the first 4 tokens plus the most recent 1020 restored 5.40 [StreamingLLM, Tab. 1]. The first tokens carry no special meaning: replacing them with newlines still gave 5.60.

The cause is the softmax. Weights must sum to one, so a query with no strong match must put its mass somewhere. Beyond the bottom two layers the model "heavily attends to the initial token across all layers and heads" [StreamingLLM, Fig. 2, §3.1]; initial tokens are visible to every later position, the easiest dump to learn. These attention sinks hold a large share of the denominator, so evicting them shifts every head off its learned distribution. StreamingLLM keeps about 4 sink tokens plus a rolling window and assigns positions within the cache (cache tokens \([0,1,2,3,6,7,8]\) get positions \([0,1,2,3,4,5,6]\)); for RoPE it caches keys before rotation. Result: stable modeling to 4 million tokens and up to 22.2x speedup over recomputing a window.

Pitfall

StreamingLLM does not extend memory. Retrieval accuracy falls to zero once the query-answer distance exceeds the cache size [StreamingLLM, App., Tab. 7]. Sinks fix a distribution shift, not a capacity limit.

Since the sink is a learned artifact, give the model an explicit one. StreamingLLM pretrained 160M models with a learnable placeholder token: with a 1024-token cache and no initial tokens, perplexity was 27.87 (vanilla), 29,214 (softmax-off-by-one, "Zero Sink"), and 1,235 (learnable sink); with one initial token kept, 18.49, 19.90, and 18.01 [StreamingLLM, Tab. 3]. Current models put the sink inside the softmax as a per-head learned logit \(z'_h\):

\[ s_{h,i,j} = \frac{\exp(z_{h,i,j})}{\sum_{k}\exp(z_{h,i,k}) + \exp(z'_h)}. \]

This adds a fictitious key with a zero value, so a head's real weights can sum to nearly zero. gpt-oss calls it "a learned bias in the denominator of the softmax" that "enables the attention mechanism to pay no attention to any tokens" [gpt-oss model card, §2.2]; MiMo-V2-Flash and DeepSeek-V4 (Eq. 27, §2.3.3) use the same form. MiMo shows it is load-bearing for small windows: without it, \(W=128\) loses 2.4 MMLU points to all-global (54.9 versus 57.3); with it, 58.3 [MiMo-V2-Flash, Tab. 2]. Sinks connect to massive activations and gated attention (stability, page 11) and to long-context recipes (page 10).

Sparse attention: choosing which keys to read

Windows choose keys by position. 稀疏注意力 (sparse attention) in the modern sense chooses by content: each query attends to a small subset of keys likely to matter, so compute per query is \(O(k)\) instead of \(O(T)\). The design questions are how the subset is chosen, whether the choice is trainable, and which resource (FLOPs, bytes, memory) is saved.

Fixed patterns: Sparse Transformer and BigBird

The Sparse Transformer factorizes attention into two sparse heads that together reconnect all positions in two steps, at \(O(n\sqrt{n})\) cost: a strided pattern for periodic data like images, and for text a fixed pattern with summary cells (stride 128, \(c=8\): positions past 128 attend to 120 to 128) [Sparse Transformer, Abstract, §4.3]. BigBird combines a window, a few global tokens, and random keys at \(O(n)\), is a universal approximator and Turing complete, and handles 8x longer sequences [BigBird, Abstract]. Both save FLOPs; neither is used by current LLMs, since a fixed pattern cannot know where the relevant key is.

Learned and dynamic selection

Native Sparse Attention (NSA) attends over three compact key-value sets per query and mixes them with learned gates [NSA, §3.2, Eq. 5]:

\[ o^*_t = \sum_{c \in \{\text{cmp},\,\text{slc},\,\text{win}\}} g^c_t \cdot \operatorname{Attn}\!\big(q_t,\ \tilde K^c_t,\ \tilde V^c_t\big), \qquad g^c_t \in [0,1]. \]

The compressed branch summarizes key blocks into coarse tokens; the selected branch keeps the top-scoring blocks at full resolution (importance read off the compressed branch's scores at no extra cost); the window branch keeps recent tokens. In GQA all heads of a group select the same blocks, so the cache loads once. Configuration: compression block 32 with stride 16, selection block 64, 16 selected blocks (one initial, two local fixed), window 512, on a 27B (3B active) GQA and MoE model with 30 layers, pretrained on 270B tokens (the intro says 260B; I use the setup value). It matched or beat full attention on general, long-context, and reasoning benchmarks, with 9.0x forward, 6.0x backward, and 11.6x decoding speedups at 64K [NSA, Fig. 1, §4.1, §5]. The decode figure is a bytes ratio: NSA loads the equivalent of 5,632 tokens at 64K versus 65,536, and \(65536/5632 = 11.6\).

Mixture of Block Attention (MoBA) borrows the MoE recipe: split the context into blocks and route each query to the top-\(k\) blocks with a parameter-free gate [MoBA, §2.2, Eqs. 5-6],

\[ g_i = \mathbb{1}\big[s_i \in \operatorname{Top\text{-}k}(\{s_j\})\big], \qquad s_i = \big\langle q,\ \operatorname{meanpool}(K[I_i])\big\rangle . \]

Future blocks get \(s_i=-\infty\) and the query's own block is always attended. With no new parameters MoBA can be switched on or off in an existing model: training with MoBA for 90% of tokens and full attention for the last 10% gave a position-wise loss almost identical to full attention (1.5B models, 30B tokens, block 2048, top-3). Reported speedups: up to 6.5x prefill at 1M tokens and 16x at 10M with fixed sparsity [MoBA, §3.2, §3.4].

DeepSeek Sparse Attention (DSA)

DSA is the design to explain in detail, since V3.2, GLM-5, and (modified) V4, MiniMax-M3, and Qwen3.8 all build on it. A lightning indexer scores every earlier token for the current query, and a top-\(k\) selector keeps only those entries for core attention [DeepSeek-V3.2, §2.1, Eqs. 1-2]:

\[ I_{t,s} = \sum_{j=1}^{H^I} w^I_{t,j}\, \operatorname{ReLU}\!\big(q^I_{t,j} \cdot k^I_s\big), \qquad u_t = \operatorname{Attn}\!\big(h_t,\ \{c_s \mid I_{t,s} \in \operatorname{Top\text{-}k}(I_{t,:})\}\big). \]

The indexer has few heads (\(H^I = 64\), \(d^I = 128\), from the released config), uses ReLU for throughput, and runs in FP8. Core attention uses the MQA mode of MLA, where each cached latent is shared by all query heads, because kernels need each selected entry reused across many queries. In V3.2, \(k = 2048\).

import torch, torch.nn.functional as F

def dsa_select(q_idx, w, k_idx, k_top):
    """q_idx: (B,T,H_I,d_I)  w: (B,T,H_I)  k_idx: (B,T,d_I).  Returns top-k key indices (B,T,k)."""
    s = torch.einsum('bthd,bsd->bths', q_idx, k_idx)          # per-head dot products
    I = (w[..., None] * F.relu(s)).sum(2)                     # (B,T,S): weighted sum of ReLU scores
    T = I.shape[1]
    future = torch.triu(torch.ones(T, T, dtype=torch.bool), diagonal=1)
    I = I.masked_fill(future, float('-inf'))                  # causal: only s <= t
    return I.topk(min(k_top, T), dim=-1).indices              # entries the core attention will read

Training. Top-\(k\) is not differentiable, so the indexer is trained as a student of the model's own dense attention, in two stages from a dense 128K checkpoint [DeepSeek-V3.2, §2.1.1, Eqs. 3-4]. Warm-up: dense attention, all but the indexer frozen, minimizing \(\mathcal{L}^I = \sum_t D_{\mathrm{KL}}\big(p_{t,:}\,\|\,\softmax(I_{t,:})\big)\), where \(p_{t,:}\) is the main attention summed over heads and L1-normalized (1000 steps of 16 sequences of 128K, learning rate \(10^{-3}\): \(1000 \cdot 16 \cdot 131072 = 2.1\)B tokens). Sparse training: turn on top-\(k\) and train everything (learning rate \(7.3\times10^{-6}\)), with the KL restricted to the selected set and the indexer input detached, so the indexer learns only from \(\mathcal{L}^I\) and the main model only from the language-modeling loss (15,000 steps of 480 sequences of 128K: \(15000 \cdot 480 \cdot 131072 = 943.7\)B tokens). The paper reports no substantial degradation against V3.1-Terminus, similar ChatbotArena Elo, and AA-LCR four points higher in reasoning mode [§2.2]. GLM-5 (744B) used the recipe with a 1000-step warm-up and only 20B sparse tokens, and reports DSA and MLA tying in SFT loss and benchmarks [GLM-5, §2.1.1, Tab. 3].

What DSA saves, and what it does not

The paper's own accounting: core attention falls "from \(O(L^2)\) to \(O(Lk)\)... Although the lightning indexer still has a complexity of \(O(L^2)\), it requires much less computation" [§2.3]. Third, and vital for capacity planning: the KV cache is not smaller. Every token's latent stays because any future query might select it, and the indexer adds its own keys. From your jet tagger

If you have used ParticleNet-style dynamic graph networks, top-k attention will feel familiar: EdgeConv builds a k-nearest-neighbor graph in a learned feature space and each particle aggregates only from its neighbors. DSA and MoBA do the same over tokens, with neighbors chosen by a learned score and constrained to the past.

Successors: MSA and QSA

MiniMax Sparse Attention (MSA) is block-based on GQA: an index branch picks top-\(k\) key blocks per GQA group (the local block always included), trained with a detached KL loss as in DSA. On a 109B model it matches GQA with 28.4x less attention compute at 1M and 14.2x prefill and 7.6x decode speedups on H800 [MSA, Abstract]; the released MiniMax-M3 config selects 16 blocks of 128 tokens, so a query reads 2048 tokens (0.2% of 1M). Qwen Sparse Attention (QSA) attacks the indexer bottleneck with an average-pooled indexer over micro-blocks, and replaces the full-attention layers of Qwen3.8-Flash-Next's GDN hybrid at continued pretraining [Qwen3.8-Next, §2.1.2].

CSA compression. With \(H \in \mathbb{R}^{n \times d}\) and head dimension \(c\), compute \(C^a = H W^{a}_{KV}\), \(C^b = H W^{b}_{KV}\), \(Z^a = H W^a_Z\), \(Z^b = H W^b_Z\) (Eqs. 9-10). Each block of \(m\) tokens becomes one entry via a learned softmax over the block and the previous block (\(2m\) rows), with learned positional biases \(B^a, B^b \in \mathbb{R}^{m \times c}\) (Eqs. 11-12):

\[ \big[S^a_{mi:m(i+1)-1};\, S^b_{m(i-1):mi-1}\big] = \operatorname{Softmax}_{\text{row}}\big([Z^a_{mi:m(i+1)-1} + B^a;\ Z^b_{m(i-1):mi-1} + B^b]\big), \] \[ C^{\text{Comp}}_i = \sum_{j=mi}^{m(i+1)-1} S^a_j \odot C^a_j + \sum_{j=m(i-1)}^{mi-1} S^b_j \odot C^b_j. \]

Each entry mixes \(2m\) sources but neighbors overlap, so length shrinks by \(1/m\). CSA selection applies DSA to compressed entries: indexer keys \(K^{\text{IComp}}\) are compressed the same way, the indexer query comes from the same low-rank latent \(c^Q_t = h_t W^{DQ}\) as the attention queries, and for a block \(s \lt \lfloor t/m \rfloor\) (Eqs. 13-17)

\[ I_{t,s} = \sum_{h=1}^{n^I_h} w^I_{t,h}\, \operatorname{ReLU}\!\big(q^I_{t,h} \cdot K^{\text{IComp}}_s\big), \qquad C^{\text{SprsComp}}_t = \big\{C^{\text{Comp}}_s \mid I_{t,s} \in \operatorname{Top\text{-}k}(I_{t,:})\big\}. \]

Shared-KV MQA core. Each selected entry is both key and value for all query heads: \(o_{t,i} = \operatorname{CoreAttn}(q_{t,i},\ C^{\text{SprsComp}}_t,\ C^{\text{SprsComp}}_t)\) (Eq. 19). HCA is the same without selection or overlap: blocks of \(m' \gg m\) tokens, \(S = \operatorname{Softmax}_{\text{row}}(Z + B)\), \(C^{\text{Comp}}_i = \sum_j S_j \odot C_j\) (Eqs. 20-23), and dense MQA over all compressed entries (Eq. 26). Contrast with linear and state-space hybrids

V4 never gives up an addressable memory: every layer attends to entries derived from actual tokens, so content lookup survives, at the price of a cache that still grows as \(T/4\) and \(T/128\). In \(\text{layers} \times \text{tokens} \times \text{features} \times \text{bytes}\), V4 shrinks the token factor; the hybrids remove the cache from most layers. Which wins at 1M is open.

Linear attention: a recurrent network with a matrix state

Start from causal softmax attention for one head, in the row-vector convention of this course (\(q_t, k_s \in \mathbb{R}^{1\times d_k}\), \(v_s \in \mathbb{R}^{1\times d_v}\)):

\[ o_t = \frac{\sum_{s \le t} \exp\!\big(q_t k_s^\top/\sqrt{d_k}\big)\, v_s}{\sum_{s \le t} \exp\!\big(q_t k_s^\top/\sqrt{d_k}\big)}. \]

The exponential of a dot product does not factor into a function of \(q_t\) times a function of \(k_s\), so every query must be compared with every key. 线性注意力 (linear attention) replaces \(\exp(q\cdot k)\) by a kernel that factors, \(\operatorname{sim}(q,k) = \phi(q)\phi(k)^\top\). Katharopoulos et al. use \(\phi(x) = \operatorname{elu}(x) + 1\), positive so the normalizer never vanishes [Katharopoulos et al. 2020, §3.2, Eq. 7].

The derivation, step by step

Substitute the kernel and use associativity, \((\phi(q_t)\phi(k_s)^\top)\, v_s = \phi(q_t)\,(\phi(k_s)^\top v_s)\). The factor \(\phi(q_t)\) does not depend on \(s\), so it leaves the sum:

\[ o_t = \frac{\sum_{s\le t} \phi(q_t)\phi(k_s)^\top v_s}{\sum_{s\le t} \phi(q_t)\phi(k_s)^\top} = \frac{\phi(q_t)\, \Big(\sum_{s\le t} \phi(k_s)^\top v_s\Big)}{\phi(q_t)\, \Big(\sum_{s\le t} \phi(k_s)^\top\Big)}. \]

The bracketed sums depend only on the prefix, so define a state and a normalizer state that grow by one term per token:

\[ S_t = S_{t-1} + \phi(k_t)^\top v_t, \qquad z_t = z_{t-1} + \phi(k_t)^\top, \qquad o_t = \frac{\phi(q_t)\, S_t}{\phi(q_t)\, z_t}, \qquad S_t \in \mathbb{R}^{d_k \times d_v},\ z_t \in \mathbb{R}^{d_k}. \]
Causal linear attention as an RNN (Katharopoulos et al. 2020, §3.3-3.4)

The state has \(d_k d_v\) numbers (plus \(d_k\)) per head, independent of \(t\): 16,384 for \(d_k = d_v = 128\), the cache of 64 tokens for one KV head (each token stores \(2 \cdot 128 = 256\) numbers). Per-token cost is \(O(d_k d_v)\). The parallel form \(O = \big((\phi(Q)\phi(K)^\top) \odot M\big) V\), row-normalized, gives the same numbers in \(O(T^2 d)\); the drill asks you to write both and check they agree. Katharopoulos et al. report linear transformers "up to 4000x faster on autoregressive prediction of very long sequences" [Abstract].

Chunkwise form: how these models train fast

The recurrence is sequential and the parallel form quadratic. The standard fix splits the sequence into chunks of \(C\) tokens (64 or 128 [DeltaNet, §2.1]), uses the parallel masked form inside each chunk, and passes state between chunks. For chunk \(i\) (normalizer dropped, as modern variants do in favor of an output norm):

\[ O_{[i]} = \underbrace{\phi(Q_{[i]})\, S_{i-1}}_{\text{inter-chunk}} + \underbrace{\big(\phi(Q_{[i]})\phi(K_{[i]})^\top \odot M\big) V_{[i]}}_{\text{intra-chunk}}, \qquad S_i = S_{i-1} + \phi(K_{[i]})^\top V_{[i]}. \]

Cost is \(O(T C d + T d_k d_v)\) per head, all dense matmuls. RetNet introduced this parallel, recurrent, chunkwise triple [RetNet, §2.1, Eqs. 5-7]; GLA's version beats FlashAttention-2 even at 1K [GLA, Abstract].

Why plain linear attention lags

Three reasons, each fixed by a different later idea. (1) Fixed capacity: \(S\) holds \(d_k d_v\) numbers and cannot store more than \(O(d_k)\) independent associations exactly. (2) Crosstalk: querying with \(q = k_j\) returns \(\phi(k_j)\phi(k_j)^\top v_j + \sum_{s\ne j} \phi(k_j)\phi(k_s)^\top v_s\). Orthogonal features would zero the second term, but with a positive map such as \(\operatorname{elu}+1\) every pair has a positive inner product, so the noise cannot cancel, and the weights are a smooth, low-contrast average where the exponential in softmax would focus almost all weight on the best match. (3) No forgetting: \(S_t\) is a plain sum, so its norm grows and old associations never make room for new ones.

Decay and gates: RetNet and GLA

The cheapest fix for (3) multiplies the old state by a decay before adding the new association. RetNet uses a constant per-head \(\gamma\) [RetNet, Eq. 6]:

\[ S_n = \gamma\, S_{n-1} + K_n^\top V_n, \qquad \operatorname{Retention}(X_n) = Q_n S_n, \]

with different \(\gamma\) per head ("multi-scale") and a GroupNorm replacing the softmax normalizer. A constant \(\gamma\) gives an exponential recency bias but is data-independent: the layer cannot keep one thing and drop another. Gated Linear Attention (GLA) makes decay input-dependent with a gate per key dimension, \(S_t = \operatorname{Diag}(\alpha_t) S_{t-1} + k_t^\top v_t\), where \(\alpha_t = \sigma(x_t W^1_\alpha W^2_\alpha + b_\alpha)^{1/\tau}\) with a rank-16 factorization and \(\tau = 16\) "to encourage the model to have a slower forgetting rate" [GLA, §4.1, §4.4, Tab. 1]. GLA's Table 1 shows many recent layers are the same equation with different gates: Mamba-2 uses a scalar \(\gamma_t\) for the whole state, RWKV-6 a per-key vector.

Decay frees capacity, but an item written at \(s\) and read at \(t\) is multiplied by \(\prod_{u=s+1}^{t} \alpha_u\): retrieving something distant needs its channels' gates near 1 the whole way, decided at write time, before the question is known.

From your jet tagger

An encoder that pools a jet into one embedding is also a fixed-size summary, and that works because the readout (the jet class) is known at training time, so the summary can specialize. A linear-attention state is a fixed-size summary written before the queries are known: the same state must answer any later lookup. That is the source of both its efficiency and its recall problem.

State-space models: S4, Mamba, Mamba-2

状态空间模型 (state-space models, SSMs) reach the same destination from control theory. S4 starts from a continuous system \(x'(t) = Ax(t) + Bu(t)\), \(y(t) = Cx(t)\), discretizes it with step \(\Delta\) (bilinear rule) into \(x_k = \bar A x_{k-1} + \bar B u_k\), and observes that because \(\bar A, \bar B, \bar C\) are the same at every step (linear time-invariant, LTI), unrolling gives a global convolution \(y = \bar K * u\) with kernel \(\bar K = (\bar C\bar B, \bar C\bar A\bar B, \dots, \bar C\bar A^{L-1}\bar B)\), computed by FFT for training, while the recurrence gives constant-memory decoding. The hard parts are choosing \(A\) so the state remembers long histories (HiPPO) and computing \(\bar K\) stably; S4's normal-plus-low-rank parameterization gives \(\tilde O(N + L)\) cost and solved the 16K-length Path-X task all prior models failed [S4, §2-3]. Its weakness is the LTI property: identical dynamics for every input, so it cannot decide by content what to store.

Mamba (selective SSM) makes the parameters functions of the input: \(B_t\) and \(C_t\) come from linear projections of \(x_t\), and the step is \(\Delta_t = \tau_\Delta(\text{param} + s_\Delta(x_t))\) with softplus \(\tau_\Delta\) [Mamba, §3.2, Alg. 2]. With zero-order hold, \(\bar A_t = \exp(\Delta_t A)\) and \(\bar B_t = (\Delta_t A)^{-1}(\exp(\Delta_t A) - I)\,\Delta_t B_t\) (Eq. 4), each channel runs

\[ h_t = \bar A_t\, h_{t-1} + \bar B_t\, x_t, \qquad y_t = C_t\, h_t. \]

Large \(\Delta_t\) drives \(\bar A_t \to 0\): reset the state and write the current input. Small \(\Delta_t\) gives \(\bar A_t \approx I\): persist and ignore the input. This content-dependent gate lets Mamba solve Selective Copying and Induction Heads, which LTI models fail. The price is that time-varying parameters break the convolution trick, so Mamba uses a hardware-aware parallel scan that keeps the expanded state (batch, length, channels, state dimension) only in SRAM, recomputing in the backward pass. The paper reports 5x the throughput of Transformers and a 3B model that beats same-size Transformers and matches ones twice its size.

Mamba-2 makes one restriction and gets a theory back: \(A_t = a_t I\), a scalar per head, and head dimension \(P\) of 64 or 128 instead of 1 [Mamba-2, §2.4]. Unrolling shows the layer is a matrix product \(Y = MX\) with

\[ M = L \circ (C B^\top), \qquad L_{ji} = a_{j:i} = a_j a_{j-1} \cdots a_{i+1}\ (j \ge i),\ \text{else } 0. \]
SSD: structured state-space duality (Dao and Gu 2024, §5.1)

\(L\) is a 1-semiseparable mask, so \(M\) is masked kernel attention with queries \(C\), keys \(B\), values \(X\), and a decay mask; if every \(a_t = 1\), \(L\) is the causal mask and the layer is causal linear attention. So a Mamba-2 layer is linear attention with a scalar, data-dependent decay: \(C, B, x, a_t\) play the roles of \(q, k, v, \gamma_t\), and the SSM state \(h_t \in \mathbb{R}^{N \times P}\) is \(S_t\) with \(N = d_k\), \(P = d_v\).

The duality yields an algorithm: a block decomposition with the quadratic form inside chunks and the recurrence between them, all matmuls because \(A\) is a scalar per head. SSD is reported 2 to 8x faster than Mamba's fused scan, faster than FlashAttention-2 from length 2K and 6x faster at 16K, and allows states 8x larger [Mamba-2, Abstract, §1]; Nemotron-H's Mamba-2 layers use state dimension 128 (8B) and 256 (56B) [Nemotron-H, §2.1]. The authors say the restriction "slightly decreas[es] the expressive power in return for significant training efficiency improvements". The trade recurs below: any decay structure beyond scalar or diagonal needs a special chunkwise algorithm to stay on tensor cores.

Delta-rule models: writing by error correction

Decay lets a state forget but not edit. If the state holds a value under some key and the sequence presents a new value under the same key (a reassigned variable, a corrected fact), plain linear attention adds the new pair on top, and a later read returns the sum. The DeltaNet paper notes a purely additive rule makes it hard to deallocate old associations, "eventually leading to key collisions when \(L > d\)" [DeltaNet, §2.2]. The delta rule writes only the error.

DeltaNet, derived carefully

Treat the state as the weights of a tiny linear regressor from keys to values and take one online SGD step on the reconstruction loss per token. In our row-vector convention (\(S \in \mathbb{R}^{d_k \times d_v}\), \(k_t \in \mathbb{R}^{1\times d_k}\), prediction \(k_t S\)):

\[ \mathcal{L}_t(S) = \tfrac12\,\big\| k_t S - v_t \big\|^2, \qquad \nabla_S \mathcal{L}_t = k_t^\top (k_t S - v_t). \]
\[ S_t = S_{t-1} - \beta_t\, k_t^\top (k_t S_{t-1} - v_t) = S_{t-1} + \beta_t\, k_t^\top \big(v_t - k_t S_{t-1}\big) = \big(I - \beta_t k_t^\top k_t\big) S_{t-1} + \beta_t\, k_t^\top v_t, \qquad o_t = q_t S_t. \]
DeltaNet recurrence (row-vector convention, \(S_t \in \mathbb{R}^{d_k \times d_v}\))

Read it as retrieve, compare, correct: \(k_t S_{t-1}\) is what the memory returns for \(k_t\) (the old value), \(v_t - k_t S_{t-1}\) is the error, and \(\beta_t \in (0,1)\) is a learned write strength. Equivalently, with \(v^{\text{new}}_t = \beta_t v_t + (1-\beta_t) v^{\text{old}}_t\): \(S_t = S_{t-1} - k_t^\top v^{\text{old}}_t + k_t^\top v^{\text{new}}_t\), remove then write. Linear attention is the same derivation on the loss \(-\langle k_t S, v_t\rangle\), which has no error term [Kimi Linear, §2.2].

Pitfall: conventions differ across papers

DeltaNet stores \(S \in \mathbb{R}^{d_v \times d_k}\) with column vectors: \(S_t = S_{t-1}(I - \beta_t k_t k_t^\top) + \beta_t v_t k_t^\top\), \(o_t = S_t q_t\) [DeltaNet, §2.2]. Kimi Linear uses \(S \in \mathbb{R}^{d_k \times d_v}\), \(S_t = (I - \beta_t k_t k_t^\top) S_{t-1} + \beta_t k_t v_t^\top\), \(o_t = S_t^\top q_t\) [§2.2, §3], which is this page's form with \(k_t\) written as a row. State \(S\)'s shape and rows-versus-columns first on a whiteboard.

Why it stores more. With unit-norm \(k_t\) and \(\beta_t = 1\), \(k_t S_t = k_t S_{t-1} + (v_t - k_t S_{t-1}) = v_t\): the memory returns exactly what was just written and the old value is replaced (a drill test: writing \(v_1\) then \(v_2\) under one key returns \(v_2\), where linear attention returns \(v_1 + v_2\)). A key \(k_j \perp k_t\) is untouched, since \(k_j (I - k_t^\top k_t) = k_j\), so \(d_k\) orthonormal associations coexist exactly; capacity is still bounded by the state, but used without waste. For stability, \(I - \beta k^\top k\) has eigenvalues 1 (multiplicity \(d_k - 1\)) and \(1 - \beta\|k\|^2\), so DeltaNet L2-normalizes \(q\) and \(k\) (after SiLU) and keeps \(\beta \in (0,1)\), putting every eigenvalue in \([0,1]\) [DeltaNet, §3.3].

Chunkwise training: the WY and UT tricks

The update multiplies the state by a different rank-one-perturbed matrix each step, which looks sequential. Unrolling reveals a linear structure: \(S_t = \sum_{i \le t} k_i^\top u_i\) with pseudo-values \(u_i = \beta_i (v_i - k_i S_{i-1}) = \beta_i\big(v_i - \sum_{j\lt i} (k_i k_j^\top)\, u_j\big)\), since \(S_{i-1} = \sum_{j\lt i} k_j^\top u_j\). DeltaNet is linear attention with \(v\) replaced by \(u\) [DeltaNet, §3.1], and computing \(u\) inside a chunk is a small triangular system. For a chunk of \(C\) tokens with incoming state \(S_0\) (rows are tokens):

\[ T = I + \operatorname{diag}(\beta)\,\operatorname{StrictTril}(K K^\top), \quad U = T^{-1}\operatorname{diag}(\beta)\,(V - K S_0), \quad O = Q S_0 + (Q K^\top \odot M)\,U, \quad S_C = S_0 + K^\top U. \]

I checked these equations against the token-by-token recurrence numerically (they match to float precision). The papers write the same with \(W = T^{-1}\operatorname{diag}(\beta)K\) and \(U' = T^{-1}\operatorname{diag}(\beta)V\), giving \((U' - W S_0)\) for \(U\) [Gated DeltaNet, Eqs. 8-9]. The \(T^{-1}\) comes from the WY representation of products of Householder-like matrices, and Kimi Linear's "UT transform" computes it by forward substitution with few non-matmul FLOPs [Kimi Linear, §3.1, Eqs. 6-7]. Cost is the linear-attention cost plus a \(C \times C\) triangular solve, so training stays \(O(T)\).

Gated DeltaNet and Kimi Delta Attention

The delta rule edits but is slow to clear (you must present the key); decay clears everything but cannot target. Gated DeltaNet composes them with a scalar decay \(\alpha_t \in (0,1)\) [Gated DeltaNet, §3.1, Eq. 10]:

\[ S_t = \alpha_t\,\big(I - \beta_t k_t^\top k_t\big)\, S_{t-1} + \beta_t\, k_t^\top v_t. \]
Gated DeltaNet (row-vector convention). \(\alpha_t \to 0\) clears the state, \(\alpha_t \to 1\) is the pure delta rule.

Recall, and why hybrids won

Every fixed-state layer is a lossy compressor of the past, and the question that decides architecture is which lookups the state can still answer. Below: the theory that says "not all of them", the evidence that a few softmax layers repair it, verified recipes, state-size arithmetic, and the counter-evidence.

The tension between constant state and exact recall

联想召回 (associative recall) means answering "what followed this key last time?" from context: attribute lookups, variable reads, in-context translation, copying. Two theorems make the limit precise. Based proves any causal recurrent model needs \(\Omega(N)\) bits of state to solve multi-query associative recall (MQAR) over \(N\) tokens [Based, Thm. 3.1]. Jelassi et al. show that copying a random length-\(L\) string over vocabulary \(D\) with a fixed-size state space \(S\) has error above \(1 - |S|/D^L\), so under \(L \log D - 1\) bits of memory the model errs more than half the time, whereas a two-layer transformer of dimension \(O(n\log D)\) copies strings up to length \(D^n\) with small error [Jelassi et al. 2024, Thms. 2.3, 2.7, Cor. 2.8]. The argument is information-theoretic (\(B\) bits distinguish only \(2^B\) contexts); attention avoids it by not compressing, since the KV cache is the raw context and even a few attention layers can address it by content (induction heads).

The empirical picture agrees. Zoology: across 17 models, attention-free architectures trail attention by up to 2.1 Pile perplexity points, 82% explained by associative recall, and a 70M attention model beats a 1.4B gated-convolution model on recall [Zoology, Abstract]. Based pairs Taylor-feature linear attention with a 64 to 128-token window: 10.36 accuracy points over Mamba on recall-intensive tasks, up to 24x the generation throughput of FlashAttention-2 [Based, Abstract]. NVIDIA's 8B study (up to 3.5T tokens): pure Mamba and Mamba-2 lag on 5-shot MMLU, Phonebook lookup, and long-context reasoning, while a hybrid of 43% Mamba-2, 7% attention, and 50% MLP layers beats the Transformer on all 12 standard tasks (+2.65 on average), is predicted to generate up to 8x faster, and matches or exceeds it on 23 long-context tasks [Waleffe et al. 2024, Abstract]. Jamba: pure Mamba fails an in-context output format where a hybrid with 1 attention layer in 8 succeeds [§6]. Mamba-2's authors: SSM layers "function well as a general sequence-to-sequence mapping, and attention layers act as a retrieval mechanism" [§9.2.3]. Qwen: one full-attention layer in four "retains the direct token-level retrieval that no finite-state memory reproduces exactly" [Qwen3.8-Next, §1].

The counter-trend and the conflicting evidence

"Hybrids and sparse attention won" is less clean than it sounds; MiniMax, which has taken all three positions, is the most informative case.

  • MiniMax-01 (January 2025) bet on a 7:1 lightning hybrid: pure lightning attention "demonstrates limited retrieval capabilities", and at 1B and 3B the hybrid beat one with sliding-window layers on needle retrieval (NIAH 95.7 versus 25.7 to 53.9 at 1B, for windows 256 to 1024) [MiniMax-01, §2.2.3, Tabs. 3-4].
  • M2 (October 2025 blog by the pre-training lead; 2026 report) went back to full attention in all 62 layers (229.9B total, 9.8B active, 29.2T tokens, 192K context). The reasons [MiniMax-M2 report, §2.2.2], [blog]: (1) evaluation: hybrids matched full attention on MMLU, BBH, MATH, and LongBench at small scale but showed "clear deficits in complex multi-hop reasoning" at larger scale, and proxy metrics were "fragile"; (2) infrastructure: linear architectures are memory-bound even in training and hard on low-precision storage, prefix caching, and speculative decoding; (3) failed SWA hybrids (above). They expect efficient attention to matter more as context grows.
  • M3 (MSA paper, June 2026) adopted MiniMax Sparse Attention on a GQA base, not linear layers.

Positive results come from elsewhere. Kimi Linear reports, under an identical recipe and 1.4T tokens, MMLU-Pro 51.0 versus 47.2 and RULER at 128K 84.3 versus 81.3 against full MLA, with up to 75% less KV cache and 6x decode throughput at 1M [Abstract, Fig. 1]. Qwen's 25B-A3B ablation (400B tokens at 4K, 80B at 32K) has the GDN hybrid averaging 53.81 over nine benchmarks versus 49.87 for full attention and 51.15 for a window-128 SWA hybrid [Qwen3.8-Next, §2.1.1, Tab. 1]. Against them, GLM found every conversion of a pretrained model lost accuracy (the best lost 5.69 RULER points at 128K "even when half of the layers retain full attention") and preferred DSA as "lossless by construction" [GLM-5, §2.1.2], a claim that needs a caveat: top-\(k\) can miss a relevant token, and warm-up-only indexer training lost 7.9 RULER points at 128K in their own Table 6.

Reconciling them: (a) most positive results are small-scale or evaluated at 32K and below, most negative ones at 64K to 128K and on multi-hop tasks; (b) from-scratch training differs from conversion; (c) perplexity and knowledge benchmarks do not see the difference (M2's Table 2: MMLU 85.5 versus 85.6 beside 90.0 versus 72.0 on 128K common-words extraction). I know of no public equal-recipe comparison at 1M tokens between a GDN or KDA hybrid, a compressed-sparse design, and full attention. As of September 2026 the models I checked are: GDN or KDA hybrids at 3:1 (Qwen3.5, Qwen3.8-Flash-Next, Kimi K3); learned sparse or compressed attention (DeepSeek-V3.2, GLM-5, DeepSeek-V4, MiniMax-M3); windows with sinks (gpt-oss, Gemma 4, MiMo-V2-Flash); and no pure linear or state-space model at the frontier.

What to ablate

  • Hybrid ratio and placement: 0:1, 1:1, 3:1, 7:1, 15:1 (Kimi Linear's grid), evenly spaced versus clustered, at fixed parameters and tokens, compared at equal measured decode throughput.
  • Linear-layer type and state size: gated linear attention, Mamba-2, Gated DeltaNet, KDA, and \(d_k\) (S-NIAH suggests the delta rule matters for recall).
  • Window and sinks: \(W \in \{128, 512, 4096\}\) with and without sink logits, evaluated after long-context extension (MiMo's \(W=512\) failure shows only then).
  • Position encoding in global layers: NoPE versus RoPE. Kimi found NoPE works when the linear layers carry position; Qwen found NoPE gave a substantially higher rate of endless generation after post-training. Test through post-training.
  • From scratch versus conversion (cheaper but lossy in reported cases), and, if sparse, indexer size and compression, \(k\), block size, per-group versus shared selection.

How to evaluate

  1. Synthetic recall as unit tests: MQAR, S-NIAH, copy, phonebook. Cheap, and they reproduce the real gaps.
  2. RULER per length. Its 13 tasks in four categories (retrieval, multi-hop tracing, aggregation, question answering) exposed large drops with length in almost all models despite near-perfect vanilla NIAH [RULER, Abstract]. MiMo also reports NoLiMa and MRCR, MiniMax HELMET.
  3. Position-wise loss (MoBA's diagnostic): trailing-token loss catches degradation mean perplexity hides.
  4. After SFT and RL, at 2x to 4x target length: MiniMax's SWA gaps widened after SFT beyond 32K; GLM's RL collapsed with a nondeterministic top-k.
  5. Short-context benchmarks as regression checks only, and systems metrics with real kernels (time per output token, prefill throughput, cache bytes, prefix-caching and speculative-decoding compatibility).

Long-context evaluations are noisy and expensive, so use many needles and seeds and report intervals per length before believing a two-point difference.

Open problems

  • A middle path between constant and linear state: exact recall needs \(\Omega(N)\) bits, yet most tokens are unneeded. Sublinear-growing caches (V4's \(T/4\), \(T/128\)) and better-used fixed states (delta rules) attack it from two sides.
  • Selector cost at 1M and beyond: DSA's \(O(L^2)\) indexer motivated compress-then-score (CSA) and pooled indexers (QSA); hierarchical selection is open.
  • Train-inference consistency of sparse selection in RL: GLM-5's nondeterministic top-k collapsed RL within a few steps (an analogue of MoE routing replay).
  • Infrastructure for recurrent states: prefix caching, speculative decoding, low-precision storage, hybrid cache management (V4 needed a dedicated "state cache" for its window and uncompressed tail).
  • Evaluation that predicts agentic long-horizon behavior (the proxies were reported fragile), and position encoding in hybrids, where labs disagree.

Common misconceptions

  • "Linear attention is softmax attention with a cheaper trick, so quality should match." It is a different function class with a fixed-size state. A positive kernel gives smooth, low-contrast weights, keys cross-talk, and exact recall needs \(\Omega(N)\) bits of state (Based Thm. 3.1). The gap is measurable: 82% of the Zoology perplexity gap is associative recall.
  • "An \(\ell\)-layer window-\(W\) model sees \(\ell W\) tokens, so it does not need global layers." The receptive field is a bound on where information can come from, not a capacity. A converted GLM-9B with 4096-token windows on half its layers falls to RULER 6.51 at 128K although its nominal reach is over 80K tokens.
  • "Sparse attention shrinks the KV cache." DSA, NSA, MoBA, and MSA keep every token's entries because any future query might select them. They cut FLOPs and bytes read. Cache shrinks only with MLA, compression (V4), windows, or fixed states.
  • "Attention sinks mean the first tokens are semantically important, and StreamingLLM extends the context." Replacing the first four tokens with newlines works almost as well (5.60 versus 5.40 perplexity); it is their position and global visibility that matter. StreamingLLM keeps generation stable; information older than the cache is gone.
  • "SSMs and attention are separate worlds." Mamba-2's SSD shows a scalar-decay SSM layer is masked linear attention with a 1-semiseparable decay mask. Only Mamba-1's per-channel selective scan sits outside the matmul family.
  • "If perplexity and MMLU match, the architecture is fine." MiniMax's SWA hybrid matched full attention on MMLU (85.6 versus 85.5) and on 32K needles while common-words extraction at 128K fell from 90.0 to 72.0. Use recall-heavy, length-swept, post-SFT evaluations.
  • "A hybrid can beat its ratio." The linear state is negligible next to the remaining KV cache, so the saving is about the ratio (3.95x at 1:3, 7.79x at 1:7 in Table 7). More needs a second reduction on another axis (MLA, compression, low precision).
  • "DeltaNet's write strength and key norm are free choices." The transition \(I - \beta k^\top k\) has eigenvalue \(1 - \beta\|k\|^2\), so unnormalized keys or \(\beta \ge 2/\|k\|^2\) make the state diverge. DeltaNet L2-normalizes \(q\) and \(k\) and keeps \(\beta \in (0,1)\).

Interview questions

Warm-up Why doesn't sliding-window attention lose all long-range information in a deep model?

Each layer lets a position read \(W-1\) positions back, and that position's hidden state already summarizes its own window from the layer below. Information therefore travels \(W-1\) positions per layer, and after \(\ell\) layers the top layer can depend on inputs about \(\ell(W-1)\) tokens away. Mistral 7B quotes this: \(W=4096\) and 32 layers give a "theoretical attention span of approximately 131K tokens".

The important qualification is that this is a reach bound, not a capacity. A fact 100K tokens back must be relayed through about 25 intermediate positions, each of which must attend to the previous link and copy it into a residual stream shared with everything else, through softmax averages that dilute it. Coarse information (topic, the entities in play) survives that chain; exact strings often do not. Evidence: converting a pretrained GLM-9B to 4096-token windows on half its layers, with no retraining, took RULER from 94.87 at 4K to 54.02 at 8K and 6.51 at 128K, and MiniMax's trained SWA hybrids lost 18 points on 128K common-words extraction while matching at 32K.

The fix used in practice is a minority of global layers (Gemma 3's 5:1, gpt-oss and MiMo's alternation), which take over exact long-range lookup. Local layers then only need to be good at local structure, and their cache is constant.

Warm-up What is an attention sink and why does it matter for streaming inference?

Softmax forces attention weights to sum to one, so a head with nothing relevant to read must put its mass somewhere. Trained causal models learn to dump it on the first few tokens, which every later position can see; StreamingLLM calls them attention sinks and shows Llama-2 attends heavily to the initial token in all layers beyond the bottom two. It is positional, not semantic: replacing the first four tokens with newlines barely changes perplexity.

This matters for streaming because a sliding window evicts the first tokens once the sequence exceeds the cache. That removes a large part of the softmax denominator in every head, and the attention distributions shift off what the model learned: Llama-2-13B perplexity went from 5.40 (4 sink tokens plus 1020 recent) to 5158 (1024-token window alone). The fix is to keep the KV of about 4 initial tokens plus a rolling window, and to assign positions inside the cache (with RoPE, cache keys before rotation and rotate at each step). This gives stable generation over millions of tokens at bounded memory, up to 22.2x faster than recomputing a window each step. It does not extend memory: older content is still gone.

Current models make the sink explicit: a learned per-head logit \(z'_h\) added to the softmax denominator (gpt-oss, MiMo-V2-Flash, DeepSeek-V4), so a head can attend to nothing. Without it, MiMo's window-128 model loses 2.4 MMLU points.

Warm-up Compute the decode state per sequence at 128K tokens for a Llama-3-8B-shaped model: full attention, a 1:7 hybrid, and pure linear attention.

Full attention: per token per layer the cache is \(2 \cdot n_{kv} \cdot d_h \cdot 2\ \text{B} = 2 \cdot 8 \cdot 128 \cdot 2 = 4096\) B. At \(T = 131{,}072\) that is 512 MiB per layer, and \(32 \times 512\) MiB \(= 16\) GiB.

Linear layer with \(H = 32\) heads and \(d_k = d_v = 128\): the state is \(32 \cdot 128 \cdot 128 \cdot 4\ \text{B} = 2\) MiB in fp32, independent of \(T\) (1 MiB in bf16).

1:7 hybrid: 4 attention layers and 28 linear layers. KV \(= 4 \cdot 512\) MiB \(= 2\) GiB, state \(= 28 \cdot 2\) MiB \(= 56\) MiB, total 2.055 GiB, a 7.79x reduction. Pure linear: \(32 \cdot 2\) MiB \(= 64\) MiB, 256x smaller. The 1:3 hybrid gives 4.047 GiB (3.95x).

Comments a strong answer adds: the state equals the KV cache at \(2\ \text{MiB}/4096\ \text{B} = 512\) tokens, so the advantage exists only at long context; the hybrid's saving is essentially its ratio because state is negligible; at 1M tokens the full stack is 128 GiB and the 1:7 hybrid still 16 GiB, so real designs stack a second reduction (MLA, compression).

Core Derive the recurrent form of causal linear attention. What is the state size?

Causal softmax attention is \(o_t = \sum_{s\le t} \exp(q_t k_s^\top/\sqrt{d})\, v_s \big/ \sum_{s\le t} \exp(q_t k_s^\top/\sqrt{d})\). Replace the exponential of a dot product with a factorizable kernel, \(\operatorname{sim}(q,k) = \phi(q)\phi(k)^\top\) with \(\phi\) positive (for example \(\operatorname{elu}+1\)). Then

\[ o_t = \frac{\phi(q_t)\sum_{s\le t}\phi(k_s)^\top v_s}{\phi(q_t)\sum_{s\le t}\phi(k_s)^\top}, \]

because \((\phi(q_t)\phi(k_s)^\top)v_s = \phi(q_t)(\phi(k_s)^\top v_s)\) by associativity and \(\phi(q_t)\) does not depend on \(s\). The sums depend only on the prefix, so with \(S_t = \sum_{s \le t}\phi(k_s)^\top v_s\) and \(z_t = \sum_{s\le t}\phi(k_s)^\top\):

\[ S_t = S_{t-1} + \phi(k_t)^\top v_t, \quad z_t = z_{t-1} + \phi(k_t)^\top, \quad o_t = \frac{\phi(q_t) S_t}{\phi(q_t) z_t}. \]

State size: \(S_t \in \mathbb{R}^{d_k \times d_v}\), so \(d_k d_v\) numbers per head (16,384 for 128 by 128) plus \(d_k\) for the normalizer, constant in \(t\). Per-token cost \(O(d_k d_v)\). The parallel form \(((\phi(Q)\phi(K)^\top)\odot M)V\) with row normalization gives identical outputs at \(O(T^2 d)\); the chunkwise form uses the parallel form within chunks and passes \(S\) between them. Mention the memory-capacity reading: \(S\) is an associative memory that can store about \(d_k\) key-value pairs before interference, which sets up the next question.

Core Why do pure linear-attention and SSM models underperform on retrieval? What fixes it?

Three reasons. (1) Information: a fixed state of \(B\) bits cannot hold arbitrary context. Based proves any recurrent model needs \(\Omega(N)\) bits of state for MQAR over \(N\) tokens; Jelassi et al. show a fixed-state model copying a random string of length \(L\) errs more than half the time below \(L \log D - 1\) bits, while a two-layer transformer copies exponentially long strings. (2) Interference and contrast: reads \(\phi(q)S\) sum over all stored pairs, with a positive kernel every pair contributes, and there is no exponential to sharpen the best match. (3) No editing: additive writes cannot overwrite.

Empirically, Zoology found 82% of the perplexity gap between attention-free models and attention comes from associative recall; a 70M attention model beat a 1.4B gated-convolution model on recall. Pure Mamba and Mamba-2 lag at 8B on 5-shot MMLU and phonebook lookup.

Fixes at two levels. Within the layer: decay and gates to free capacity (Mamba-2, GLA), the delta rule to overwrite (Gated DeltaNet, KDA), larger states (Mamba-2 allows 8x). These help but do not close the gap: Gated DeltaNet still retrieves under 30% on S-NIAH-2 at 8K at 1.3B. Across layers: keep a minority of softmax layers, 1 in 4 to 1 in 8. A 7% attention hybrid beat the Transformer on all 12 tasks in NVIDIA's 8B study, and Jamba's pure Mamba failed in-context formatting where a 1-in-8 hybrid succeeded. Or use a tiny window plus linear attention (Based).

Core Explain DeepSeek Sparse Attention. What does it save and what does it not?

A lightning indexer scores every earlier token for query \(t\): \(I_{t,s} = \sum_{j=1}^{H^I} w^I_{t,j}\operatorname{ReLU}(q^I_{t,j}\cdot k^I_s)\), with few heads (64), small dimension (128), ReLU, FP8. Top-\(k\) selection (\(k=2048\)) keeps those key-value entries, and MLA in its MQA mode attends only to them, so core attention is \(O(Lk)\) instead of \(O(L^2)\). The indexer is trained as a student of the dense attention: a dense warm-up with all else frozen minimizing \(\mathrm{KL}(p_t \| \softmax(I_t))\) (2.1B tokens), then sparse training with the indexer detached from the language-modeling loss (943.7B tokens).

Saves: core attention FLOPs and the bytes read per decoded token. My estimate for V3.2 shapes at 128K: 13.4x fewer FLOPs per layer (36.5 GFLOP dense versus 0.57 core plus 2.15 indexer) and 7.9x fewer bytes.

Does not save: (a) the KV cache, since every token must stay selectable, plus the indexer's own keys; (b) the indexer is still \(O(L^2)\): 16,384 FLOPs per key versus 278,528 for dense MLA core attention, so the total saving saturates at about 17x and the indexer is 30x the sparse core at 1M. That is why V4 compresses before indexing and Qwen pools its indexer. Also note discontinuity: top-\(k\) selection caused RL instability until GLM-5 used a deterministic top-\(k\) and froze the indexer.

Core Mamba versus linear attention versus Gated DeltaNet: what distinguishes them?

All three carry a matrix-valued state written with a key-value outer product and read with a query. They differ in how the old state is transformed before the write (Table 5).

  • Linear attention: \(S_t = S_{t-1} + k_t^\top v_t\). No decay, no editing; the state saturates and cross-talks.
  • Mamba (selective SSM): input-dependent \(\Delta_t, B_t, C_t\) and a diagonal \(A\); the decay \(\exp(\Delta_t A)\) is content-dependent and per state channel, so Mamba can reset or persist based on the token. It forgets but never edits. Per-channel time-varying dynamics cannot be written as matmuls, so it needs a hardware-aware parallel scan. Mamba-2 restricts \(A\) to a scalar per head, which makes the layer masked linear attention with a decay mask (queries \(C\), keys \(B\), values \(x\)) and allows chunked matmul training and larger states.
  • Gated DeltaNet: \(S_t = \alpha_t(I - \beta_t k_t^\top k_t)S_{t-1} + \beta_t k_t^\top v_t\). The delta-rule term reads what the memory holds for \(k_t\) and writes only the error (an online SGD step on \(\tfrac12\|k S - v\|^2\)), so it can overwrite and keeps orthogonal keys from interfering. The scalar gate \(\alpha_t\) clears memory wholesale. Trained by a chunkwise WY/UT algorithm.

Evidence: at 1.3B on S-NIAH, delta-only is strong on a single needle but drowns in distractors (14.4% on number-in-haystack at 8K), decay-only forgets the needle (30.4% pass-key at 8K), and the combination is best (91.8% and 29.6%). KDA further makes the decay per key dimension.

Core Compute the prefill FLOPs ratio of full attention versus a sliding window (W = 4096) at T = 128K for Llama-3-8B. Why is the whole-model saving so much smaller than the attention saving?

Causal pairs: full \(T(T+1)/2 = 8{,}590{,}000{,}128\); window \(W(W+1)/2 + (T-W)W = 528{,}484{,}352\). Ratio 16.25 (not \(T/W = 32\), since causal full attention already skips half the square). Each pair costs \(4 n_h d_h = 16{,}384\) FLOPs per layer, so attention is \(4.50\times10^{15}\) versus \(2.77\times10^{14}\) over 32 layers.

Windowing does not touch the projections and MLP: \(2NT = 2 \cdot 6{,}979{,}321{,}856 \cdot 131072 = 1.83\times10^{15}\) FLOPs, where \(N\) counts matmul parameters excluding embeddings. Totals: \(6.33\times10^{15}\) versus \(2.11\times10^{15}\), a 3.01x ratio. Attention is only 71% of full prefill at 128K, so removing nearly all of it leaves the dense matmuls.

Follow-up points: the whole-model gain grows with \(T\) (1.41x at 32K where attention is 38% of prefill, 17.9x at 1M where it is 95%) and shrinks with model width. Decoding is different, because reads are dominated by the cache: there the window cuts bytes by \(T/W = 32\) for that layer.

Core Write the DeltaNet update, say why it improves recall, and explain how it is trained in parallel.

With \(S \in \mathbb{R}^{d_k\times d_v}\) and row vectors (state the convention first): \(S_t = S_{t-1} + \beta_t k_t^\top (v_t - k_t S_{t-1}) = (I - \beta_t k_t^\top k_t)S_{t-1} + \beta_t k_t^\top v_t\), \(o_t = q_t S_t\). It is one SGD step with rate \(\beta_t\) on \(\tfrac12\|k_t S - v_t\|^2\): read the current prediction \(k_t S_{t-1}\), and write the error along \(k_t\).

Why recall improves: with \(\|k_t\| = 1\) and \(\beta_t = 1\), \(k_t S_t = v_t\) exactly, so re-writing a key replaces the old value instead of adding to it; keys orthogonal to \(k_t\) are unchanged, so \(d_k\) orthonormal pairs coexist without cross-talk. Stability needs \(\|k\|=1\) and \(\beta\in(0,1)\) because the transition's eigenvalues are 1 and \(1-\beta\|k\|^2\).

Parallel training: unrolling gives \(S_t = \sum_{i\le t}k_i^\top u_i\) with pseudo-values \(u_i = \beta_i(v_i - \sum_{j\lt i}(k_ik_j^\top)u_j)\). Within a chunk of \(C\) tokens with incoming state \(S_0\): \(T = I + \operatorname{diag}(\beta)\operatorname{StrictTril}(KK^\top)\), \(U = T^{-1}\operatorname{diag}(\beta)(V - KS_0)\), \(O = QS_0 + (QK^\top\odot M)U\), \(S_C = S_0 + K^\top U\). The triangular inverse comes from the WY representation of Householder-like products, and the UT transform computes it with few non-matmul FLOPs. Cost is linear-attention cost plus a \(C\times C\) triangular solve.

Core MiniMax used a 7:1 lightning-attention hybrid in MiniMax-01, full attention in M2, and sparse attention in M3. What happened, and what does it teach about evaluating architectures?

MiniMax-01 (Jan 2025) found pure lightning attention had "limited retrieval capabilities", interleaved a softmax layer every 8, and showed hybrid-lightning beating hybrid-SWA on needle retrieval at 1B and 3B. For M2 the pre-training lead wrote (Oct 2025; the 2026 report repeats it) that they found no efficient variant that reliably matched full attention in production settings, for three reasons. Evaluation: hybrids matched on MMLU, BBH, MATH, and LongBench at small scale, but at larger scale showed clear deficits on multi-hop reasoning, and proxy metrics were fragile. Infrastructure: linear layers are memory-bound even in training, sensitive to low-precision storage, and awkward with prefix caching and speculative decoding. SWA hybrids: extensively tested with hundreds of billions to trillions of tokens, they degraded retrieval, multi-hop, and in-context learning, and after SFT were significantly worse beyond 32K. M3 then adopted MiniMax Sparse Attention (28.4x less attention compute at 1M in a 109B model).

Lessons. Standard benchmarks and perplexity do not discriminate: M2's Table 2 shows MMLU 85.5 versus 85.6 and equal 32K needles beside 90.0 versus 72.0 on 128K common-words extraction. Test at target length, after SFT, on multi-hop tasks. Infrastructure readiness is a first-class criterion. And it is not a verdict against linear hybrids: Kimi Linear and Qwen report wins under matched budgets, on different evaluations and recipes. The productive reading is that the conclusion depends on what you measure.

Deep-dive You are designing a 1M-context model. Which attention architecture would you choose and how would you validate it?

First pin down what binds: decode bandwidth (long agentic or RL rollouts, many concurrent sequences), prefill compute, or cache capacity. At 1M an 8B-class GQA stack needs 128 GiB per sequence, so capacity and bandwidth both bind, and I would not ship plain full attention.

Candidates, in order of risk. (1) Interleaved local/global at about 5:1 with small windows (128 to 1024) and sink logits on top of GQA or MLA: about 6x less cache, well understood. (2) A 3:1 Gated DeltaNet or KDA hybrid with MLA or GQA global layers, with a stacked reduction in the global layers: it makes 3/4 of layers constant-memory (Kimi K3: 27 GiB plus 0.4 GiB state at 1M). (3) Compressed sparse attention in the V4 style: the smallest cache (about 4.8 GiB at 1M by my estimate) but heavy engineering. I would pick (2) as the main bet with (1) as the low-risk arm, and keep a full-attention twin as the control.

Validation: same parameters and tokens; ablate ratio (1:1 to 15:1), placement, window and sinks, gate type and state size, NoPE versus RoPE. Evaluate in a ladder: MQAR and S-NIAH at small scale, RULER at 32K to 1M with per-length curves (not vanilla NIAH), position-wise loss, then after SFT and RL at 2 to 4 times the training length; use perplexity and MMLU only as regression checks. Compare on measured time per output token and prefill throughput with real kernels, and check prefix caching and speculative decoding work. Decide on the quality-versus-throughput Pareto frontier, with confidence intervals per length.

Deep-dive Compare DeepSeek-V4's CSA/HCA with a Gated-DeltaNet hybrid. What does each keep and what does each lose?

Both attack the sequence axis of the cache but differently. V4 keeps an addressable memory in every layer: CSA merges each 4 tokens into one entry with a learned softmax (overlapping windows) and selects the top 1024 (Pro) with a lightning indexer; HCA merges 128 tokens and attends densely; a 128-token window keeps recent tokens exact. Lost: within-block token identity, since a merged entry is a learned mixture (the window and the small \(m=4\) mitigate it), and the \(O(L^2/m)\) indexer remains. Cache still grows as \(T/4\) and \(T/128\); my estimate at 1M is 4.83 GiB for Pro, and the report gives 10% of V3.2's cache and 27% of its FLOPs. Costs: custom KV cache management (a separate state cache for the window and tail), FP8 and FP4 kernels.

A GDN hybrid makes 3 in 4 layers constant-memory with a fixed state (Qwen3.5: 180 MiB for 45 layers) and keeps every token exactly in the remaining global layers, so its cache is 1/4 of a full model's (30 GiB at 1M for Qwen3.5, 27 GiB for K3 with MLA). Lost: exact recall in the linear layers (fixed capacity), so retrieval must route through the global layers. Costs: recurrent-state infrastructure (prefix caching, precision) and chunkwise kernels; position-encoding choices.

Trade-off summary: V4 preserves exact-content addressing everywhere at reduced fidelity and has the smaller cache at 1M; the hybrid removes memory from most layers entirely and has cheaper layers, but relies on the few global layers for recall. There is no public equal-recipe comparison, so I would measure both on recall-heavy tasks at target length and on throughput before choosing.

Deep-dive Gemma 3 uses 5:1 local/global with a 1024-token window, MiMo-V2-Flash uses 5:1 with a 128-token window, and MiniMax found SWA hybrids degrade beyond 32K. How would you choose a window size, and what would you test?

The window is cheap: it costs \(4 n_h d_h W\) FLOPs and \(2 n_{kv}d_hW\) cache entries per layer, so even \(W=4096\) is 1/32 of full attention at 128K. The real question is what the local layers are for. MiMo's 32B dense ablation suggests they should be pure local mixers: with sinks, \(W=128\) and \(W=512\) look alike on general benchmarks, but after long-context extension \(W=512\) collapses (NoLiMa 38.5 versus 49.7 all-global, MRCR 19.6 versus 32.5) while \(W=128\) slightly beats all-global. Their hypothesis is a division of labor: a tight window forces long-range work into the global layers, while a medium window lets local layers half-solve it and blurs the split. Gemma 3's ablations found perplexity insensitive to the window from 4096 down to 512, which is exactly the metric that cannot see this.

MiniMax's negative results are compatible: their hybrids may have relied on SWA layers for some long-range work, and their evaluations go past 32K where MiMo's stop. I would test: (1) sink logits on and off; (2) window sizes 128, 512, 4096 and the global fraction (1:1 to 1:7), evaluated after context extension; (3) RULER and multi-hop tasks per length, out to well beyond 32K; (4) position-wise loss; (5) from scratch versus conversion. I would default to a small window, sinks, and a global layer every 4 to 6, and revise from the per-length curves.

Deep-dive Your hybrid matches the full-attention baseline on perplexity and MMLU but fails needle retrieval at 128K. How do you debug it?

Start by localizing. (1) Sweep length: does it fail from a certain length (and is that length beyond what training and extension covered)? (2) Sweep task type with RULER's categories: single needle, multi-key, multi-hop, aggregation. Single-needle failure points at the global layers not learning retrieval; multi-key or aggregation failure points at state capacity in linear layers.

Then test causes. Architecture: too few or badly placed global layers (try 1:3 and even spacing), or a window in local layers so large that it blurs the division of labor (MiMo). Position: global layers with RoPE trained only to short lengths, or NoPE versus RoPE mismatch; check extension recipe (page 10). Numerics: state precision (linear layers are sensitive to low-precision storage), gate initialization that forgets too fast (\(\alpha\) near 0), missing L2 normalization of keys in delta-rule layers, chunk-size or kernel bugs; verify recurrent and chunkwise forms match token by token, as the drill does. Data: too little long-range-dependent data. Inference: prefix caching or quantization corrupting states.

Probes: check attention heads in the global layers for retrieval behavior (do they attend to the needle?); replace linear layers by full attention in a small ablation to see how much recall returns; compare with the full-attention twin trained on the same tokens. Only after such controls decide whether to change the ratio, the layer type, or the training data.

Hands-on

Beyond full attention. One module with six pieces, all on small tensors, all testable on CPU: sliding_window_mask and sliding_window_attention (window counts keys including the query, so it matches a rolling buffer), linear_attention_parallel and linear_attention_recurrent (causal, \(\operatorname{elu}+1\) feature map, with normalizer; the tests assert the two forms agree), delta_rule_recurrent (DeltaNet, row-vector convention, no normalizer, checked against a naive loop and against the overwrite property), and topk_sparse_attention (causal attention over the top-\(k\) keys chosen by given index scores, the core-attention half of DSA). exercises/drills/efficient_attention.py

The tests include a receptive-field check (two stacked window-3 layers reach 4 positions back and no further) and a no-future-leakage check for top-\(k\).

Cheat sheet

  • Three savings: FLOPs (prefill), bytes read per decoded token, resident memory. Sparse top-k saves the first two; windows, MLA, compression, and fixed states save memory too.
  • Llama-3-8B at 128K: cache 4096 B per token per layer, 512 MiB per layer, 16 GiB in total. Linear state 32 x 128 x 128 x 4 B = 2 MiB per layer. Hybrids: 1:3 gives 4.047 GiB (3.95x), 1:7 gives 2.055 GiB (7.79x), pure linear 64 MiB.
  • Window: \(W\) keys including self; cache slot \(i \bmod W\); receptive field about \(\ell(W-1)\), a bound only. Causal pairs: full \(T(T+1)/2\), window \(W(W+1)/2 + (T-W)W\). At 128K, W=4096: 16.25x fewer pairs, 3.01x fewer total prefill FLOPs (attention is 71% of prefill).
  • Configs: Gemma 2 alternates 1:1 (window 4096); Gemma 3 5:1, window 1024; gpt-oss alternates with banded 128; MiMo-V2-Flash 5:1, window 128 with sink bias.
  • Sinks: softmax must sum to 1; keep ~4 initial KV plus a rolling window; positions within the cache; \(s = e^{z_j}/(\sum_k e^{z_k} + e^{z'_h})\) for a learned sink logit. Llama-2-13B: 5158 versus 5.40 perplexity.
  • Linear attention: \(S_t = S_{t-1} + \phi(k_t)^\top v_t\), \(z_t = z_{t-1} + \phi(k_t)^\top\), \(o_t = \phi(q_t)S_t/\phi(q_t)z_t\); state \(d_k \times d_v\). Decay: RetNet \(\gamma S\), GLA \(\operatorname{Diag}(\alpha_t)S\), Mamba-2 \(a_t S\).
  • Mamba-2 (SSD): \(M = L \circ (CB^\top)\), \(L_{ji} = a_{j:i}\); \(C, B, x \leftrightarrow q, k, v\).
  • DeltaNet (row convention): \(S_t = (I - \beta k^\top k)S_{t-1} + \beta k^\top v\); GDN adds \(\alpha_t\); KDA uses \(\operatorname{Diag}(\alpha_t)\). Need \(\|k\|=1\), \(\beta \in (0,1)\). Chunkwise: \(U = T^{-1}\operatorname{diag}(\beta)(V - KS_0)\).
  • Recall: exact recall of \(N\) tokens needs \(\Omega(N)\) bits (Based Thm. 3.1); keep 1 in 4 to 1 in 8 layers as full attention. Kimi Linear val PPL: 3:1 5.65, 7:1 5.70, 15:1 5.82, pure MLA 5.77.
  • DSA: \(I_{t,s}=\sum_j w_j \operatorname{ReLU}(q_j\cdot k_s)\), top-2048, MQA-mode MLA; warm-up 2.1B tokens (KL), sparse 943.7B. Saves core FLOPs and bytes; not cache; indexer \(O(L^2)\), saving capped near 17x.
  • NSA: compressed + selected + window, gated; 11.6x decode at 64K (5,632 versus 65,536 tokens read). MoBA: top-k blocks by mean-pooled key. MSA: per-GQA-group block selection, 28.4x attention compute at 1M.
  • DeepSeek-V4: CSA (merge 4, top-k 1024 Pro or 512 Flash) and HCA (merge 128, dense), 128-token window, shared 512-dim KV entries, sink logits; 1M tokens: 27% of V3.2 FLOPs, 10% of cache, about 2% of a GQA-8 BF16 baseline.
  • Conflicting evidence: Kimi Linear (3:1 KDA beats MLA at 1.4T tokens) and Qwen (GDN hybrid beats full attention at 25B-A3B) versus MiniMax-M2 (SWA hybrids degrade beyond 32K) and GLM (conversions lose accuracy). Perplexity and MMLU do not discriminate.
  • Validate with: MQAR and S-NIAH (small), RULER per length (13 tasks, 4 categories), position-wise loss, post-SFT and post-RL tests at 2 to 4 times training length, and measured decode throughput.
