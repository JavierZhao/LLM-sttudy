RL foundations for LLMs: policy gradient to PPO

P0 ~70 min Prereqs: 01 Big picture, 06 Decoding, 21 Preference optimization

Every RL method used to post-train language models (PPO, RLOO, GRPO and its successors) is a small variation on one estimator: sample a response, score it, and raise the log-probability of its tokens in proportion to how much better than expected it was. This page derives that estimator from scratch, then builds each piece that turns it into a stable algorithm: baselines, GAE, importance ratios, the PPO clip, and the KL penalty with its three sampling estimators.

  • GAE and its knobs: the formula, the telescoping argument, what \(\gamma\) and \(\lambda\) each trade, and what happens in the LLM setting (\(\gamma = 1\), reward only on the last token) when responses are thousands of tokens long.

  • KL control: reward shaping versus a loss term, and k1, k2, k3 with the correct sampling distribution, bias, variance and the gradient each one produces when you call .backward().
  • Token versus sequence level: the bandit view of RLHF, what it implies for credit assignment, and where the ratio and the loss are aggregated.
  • Implementation fluency: write gae, the PPO loss and the KL estimators from memory, with masks and without off-by-one errors.

Language generation as a Markov decision process

Reinforcement learning 强化学习 studies an agent that picks actions, observes rewards, and improves a policy 策略, a distribution over actions given a state, to maximize expected total reward. A language model already is such a policy. Take a prompt \(x\) drawn from a dataset \(\mathcal D\) and let the model write a response \(y = (y_1, \dots, y_T)\) token by token (page 01, page 06). The mapping to RL vocabulary is exact:

Two design choices in this table deserve a why.

  • Why \(\gamma = 1\). The horizon is finite (EOS or a length cap), so the return is finite without discounting. Discounting would be harmful, not neutral: with a terminal reward, \(\gamma < 1\) turns \(R\) into \(\gamma^{T-1} R\), which silently rewards short responses. The GAE paper's point about \(\gamma\) applies fully here: a discount below 1 biases the gradient of the objective you actually care about, whatever the value function [Schulman et al. 2016, §3].
  • Why deterministic transitions matter. In a general MDP the policy gradient needs no model of the dynamics either, but \(Q(s,a)\) is an expectation over random next states that must be estimated. Here \(s_{t+1}\) is a function of \((s_t, a_t)\), so \(Q(s_t, a_t) = r_t + V(s_{t+1})\) exactly. We use this in the baseline section.

Token-level MDP versus bandit

There is a coarser description of the same problem. Treat the entire response as one action: state = prompt, action = \(y \in \mathcal V^{\le T_{\max}}\), reward \(R(x,y)\), episode ends after one step. That is a contextual bandit. InstructGPT states it explicitly: "The environment is a bandit environment which presents a random customer prompt and expects a response to the prompt. Given the prompt and response, it produces a reward determined by the reward model and ends the episode" [Ouyang et al. 2022, §3.5], and then adds a per-token KL penalty on top, which reintroduces token-level structure.

These are not two models of the world but two estimators of the same gradient. PPO adds a learned value function \(V_\phi(s_t)\), the critic 评论家, a scalar head that predicts expected future reward from each prefix; Figure 1 shows where it reads. That is one group's evidence on 6.9B and 7B models with their PPO implementation, and later long-CoT work reports the opposite ordering when the critic is handled carefully (below).

From your jet tagger

Your classifier minimized \(-\log p_\theta(\text{label} \mid x)\) against a label the dataset provided. Here there is no label: the "target" is a token sampled from the model itself, and its quality is judged after the fact by a black box that cannot be differentiated. Two consequences drive everything below. The gradient must go through the sampling distribution, not through the reward. And the data distribution depends on \(\theta\), so the moment you update, the samples you hold are slightly stale.

The policy gradient theorem, for sequences

We want \(\nabla_\theta J\), but \(R\) is a black box (a neural reward model sampled at discrete tokens, or a program that checks an answer), and the sample space \(\mathcal V^T\) is astronomically large. The policy gradient 策略梯度 theorem removes both obstacles with one identity. Write \(\tau = (x, y_1, \dots, y_T)\) for a trajectory and \(p_\theta(\tau) = \mathcal D(x)\prod_t \pi_\theta(a_t \mid s_t)\) for its probability (the deterministic transitions contribute factors of 1).

  1. Log-derivative trick. \(J = \sum_\tau p_\theta(\tau) R(\tau)\), and \(\nabla p_\theta = p_\theta \nabla \log p_\theta\), so \[ \nabla_\theta J = \sum_\tau p_\theta(\tau)\,\nabla_\theta \log p_\theta(\tau)\, R(\tau) = \E_{\tau \sim p_\theta}\big[ R(\tau)\, \nabla_\theta \log p_\theta(\tau) \big]. \] A gradient of an expectation became an expectation of a gradient, which we can estimate by sampling. \(R\) is only evaluated, never differentiated.
  2. Token factorization. \(\log p_\theta(\tau) = \log \mathcal D(x) + \sum_t \log \pi_\theta(a_t \mid s_t)\). The prompt term does not depend on \(\theta\), so \[ \nabla_\theta \log p_\theta(\tau) = \sum_{t=1}^{T} \nabla_\theta \log \pi_\theta(a_t \mid s_t). \]
\[ \nabla_\theta J \;=\; \E\Big[ R(x,y) \sum_{t=1}^{T} \nabla_\theta \log \pi_\theta(y_t \mid x, y_{<t}) \Big] \;=\; \E\big[ R(x,y)\, \nabla_\theta \log \pi_\theta(y \mid x) \big] \]
Sequence-level REINFORCE [Williams 1992]: this is already the bandit gradient, and it holds for any reward function

The variance of this estimator is the whole problem, and the next steps reduce it without changing its mean. They all rest on one lemma.

Lemma: the score function has zero mean

For any state \(s\): \(\E_{a \sim \pi(\cdot|s)}[\nabla_\theta \log \pi_\theta(a|s)] = \sum_a \nabla_\theta \pi_\theta(a|s) = \nabla_\theta \sum_a \pi_\theta(a|s) = \nabla_\theta 1 = 0\). Any quantity that is fixed once \(s_t\) is fixed, multiplied by \(\nabla\log\pi(a_t|s_t)\), has zero expected contribution. Causality, baselines, and the KL-penalty derivation below are three uses of this line.

  1. Causality (reward-to-go). The action \(a_t\) cannot change a reward received earlier. For \(t' < t\), the reward \(r_{t'}\) is determined by \(s_t\) (it is a function of earlier states and actions, all contained in the prefix), so \[ \E\big[ r_{t'}\, \nabla\log\pi(a_t|s_t) \big] = \E\Big[ r_{t'}\; \underbrace{\E_{a_t}\big[\nabla\log\pi(a_t|s_t)\big]}_{=\,0} \Big] = 0. \] Dropping those terms replaces the full return by the reward-to-go \(G_t = \sum_{t' \ge t} \gamma^{t'-t} r_{t'}\):
\[ \nabla_\theta J \;=\; \E\Big[ \sum_{t=1}^{T} \nabla_\theta \log \pi_\theta(a_t \mid s_t)\; G_t \Big] \]
Policy gradient theorem, trajectory form. Conditioning \(G_t\) on \((s_t,a_t)\) gives \(Q^\pi(s_t,a_t)\), the form in [Sutton et al. 1999]

Notice what is missing: no term differentiates how often each state is visited, and no term needs the dynamics. Changing \(\theta\) changes which states we reach, but the identity accounts for that through the sampling distribution itself.

Terminal reward makes the two views coincide. If \(r_t = 0\) for \(t < T\) and \(\gamma = 1\), then \(G_t = R\) for every \(t\), so the token-level estimator \(\sum_t \nabla\log\pi_t\, G_t\) equals the sequence-level one \(R \sum_t \nabla\log\pi_t\) sample by sample, not just in expectation. Reward-to-go only changes anything when rewards appear earlier, as they do with the per-token KL of the KL section.

What the gradient does to the logits

For a softmax policy with logits \(z\), \(\partial \log\pi(a|s)/\partial z = e_a - \pi(\cdot|s)\). So a single token contributes \(G_t\,(e_{a_t} - \pi)\): the sampled token's logit goes up, every other logit goes down in proportion to its current probability, and the whole thing is scaled by how good the continuation was. Sign matters: a negative \(G_t\) pushes the sampled token down. Since \(e_a - \pi\) sums to zero, the update never changes the logits' overall shift. Averaged over \(a \sim \pi\), the update is \(\sum_a \pi(a)\,Q(s,a)\,(e_a - \pi)\), the covariance between the action-value and the one-hot token, which is why the expected update raises the probability of actions with above-average value.

In code: a weighted cross-entropy on your own samples

The only LLM-specific work is bookkeeping. Position \(t\) of the logits predicts token \(t+1\), and the loss must ignore prompt tokens and padding. In fact \(\log\pi\) of the sampled token is minus the cross-entropy you already know from pretraining:

import torch, torch.nn.functional as F

def response_logprobs(model, input_ids, response_mask):
    # input_ids: (B, L) prompt + response, right-padded; response_mask: (B, L), 1 on response tokens only
    logits = model(input_ids).logits[:, :-1]                           # (B, L-1, V): position t predicts token t+1
    logp = -F.cross_entropy(logits.transpose(1, 2), input_ids[:, 1:], reduction="none")  # (B, L-1)  log pi(a_t | s_t)
    return logp, response_mask[:, 1:]                                  # exclude prompt tokens and padding

def reinforce_loss(logp, rewards, baseline, mask):
    # logp, rewards, baseline, mask: (B, L-1), rewards and baseline are zero outside the response
    G = (rewards * mask).flip(1).cumsum(1).flip(1)                     # reward-to-go, gamma = 1
    adv = (G - baseline).detach()                                      # a constant weight: the reward is never differentiated
    return -(adv * logp * mask).sum() / logp.shape[0]                  # sum over tokens, mean over responses

If you sample with temperature \(\tau \ne 1\), the policy is \(\softmax(z/\tau)\) and \(\log\pi\) must be computed from those scaled logits (page 06), otherwise you differentiate a distribution you did not sample from. A simplified form of the drill's reinforce_loss in exercises/drills/pg.py, which adds discounting and per-token baselines.

Key idea

Policy gradient is advantage-weighted maximum likelihood on the model's own samples. Set the weight to 1 on demonstrations from a dataset and you have SFT (page 19). Set it to a reward-based weight on samples drawn from the current policy and you have RL. Everything else on this page is about choosing that weight to have low variance and small bias, and about safely reusing the samples for more than one step.

Baselines, the value function and the advantage

The estimator above is unbiased but noisy. If rewards are all positive (a 0/1 verifier, or a reward model whose scores are mostly above zero), every sampled token gets pushed up, and only the relative sizes of the pushes carry signal. The fix is to subtract a baseline 基线 \(b\) from the return.

\[ \nabla_\theta J = \E\Big[ \sum_t \nabla\log\pi_\theta(a_t|s_t)\,\big(G_t - b(s_t)\big) \Big] \qquad \text{for any } b \text{ that does not depend on } a_t \text{ or later tokens} \]
Baselines change the variance, never the mean

Proof. The subtracted term is \(\E[\nabla\log\pi(a_t|s_t)\, b(s_t)] = \E\big[ b(s_t)\, \E_{a_t}[\nabla\log\pi(a_t|s_t)] \big] = 0\) by the lemma, because \(b(s_t)\) is a constant once the prefix is fixed. The proof uses only that \(b\) is independent of \(a_t\), so \(b\) may depend on the prompt, on the whole prefix, and on any randomness that is independent of \(a_t\) [Schulman et al. 2016, Prop. 1]. It may not depend on \(a_t\), on later tokens, or on the outcome of the sample it multiplies.

Which baseline is best

For one token, the second moment of the gradient term is \(\E[(G - b)^2\,\|\nabla\log\pi(a|s)\|^2 \mid s]\). Differentiating with respect to \(b\) and setting the result to zero gives

\[ b^\star(s) = \frac{\E\big[\|\nabla\log\pi\|^2\, G \mid s\big]}{\E\big[\|\nabla\log\pi\|^2 \mid s\big]}, \]

a return average weighted by the squared score norm [Greensmith et al. 2004]. If the score norm is roughly independent of the return, \(b^\star\) reduces to \(\E[G_t \mid s_t]\), the value function 价值函数. That is why the value function is the default: it is the mean-return baseline, and the GAE paper calls the resulting advantage "almost the lowest possible variance" [Schulman et al. 2016, §2]. Define

\[ V^\pi(s_t) = \E[G_t \mid s_t], \qquad Q^\pi(s_t, a_t) = \E[G_t \mid s_t, a_t], \qquad A^\pi(s_t, a_t) = Q^\pi(s_t,a_t) - V^\pi(s_t). \]

The advantage 优势函数 measures how much better token \(a_t\) is than the policy's average token in that state, and by construction \(\E_{a \sim \pi}[A^\pi(s,a)] = 0\). The policy gradient becomes \(\nabla_\theta J = \E[\sum_t \nabla\log\pi(a_t|s_t)\, A^\pi(s_t,a_t)]\), and a positive advantage raises the token's probability while a negative one lowers it.

What the advantage is in an LLM

Because the next state is a deterministic function of \((s_t, a_t)\) and the reward is a deterministic function of the sequence, \(Q^\pi(s_t,a_t) = r_t + V^\pi(s_{t+1})\) with no expectation left. Therefore

\[ A^\pi(s_t, a_t) = r_t + V^\pi(s_{t+1}) - V^\pi(s_t) =: \delta_t, \qquad V^\pi(s_{T+1}) = 0 \]
With the true value function, the one-step TD residual is the advantage (no Q-network needed)

With a stochastic reward (a sampled LLM judge) \(\delta_t\) is an unbiased estimate of \(A_t\) instead. For a verifier with reward in \(\{0,1\}\) this has a clean reading: \(V(s_t)\) is the probability, after prefix \(s_t\), that the final answer will be judged correct, and the advantage of a token is how much that token moved the predicted success probability. A token that opens a dead-end derivation has negative advantage before anyone knows the answer is wrong. This is exactly the credit assignment a critic can provide and a single outcome number cannot.

Worked numbers: exact gradient and three estimators on a two-token MDP

Take the smallest response that has structure: two binary tokens. Token 1 is \(a_1 \sim \text{Bernoulli}(\sigma(z_0))\). Token 2 depends on token 1: \(a_2 \sim \text{Bernoulli}(\sigma(z_A))\) if \(a_1 = 0\) and \(\text{Bernoulli}(\sigma(z_B))\) if \(a_1 = 1\). Three logits \(\theta = (z_0, z_A, z_B)\). A verifier pays \(R = 1\) only for the response "11". Start at \(\theta = 0\), so every probability is \(\tfrac12\) and each of the four responses has probability \(\tfrac14\).

Exact gradient. \(J = \sigma(z_0)\,\sigma(z_B)\), so \(\partial J/\partial z_0 = \sigma(z_0)(1-\sigma(z_0))\,\sigma(z_B) = \tfrac14\cdot\tfrac12 = 0.125\), \(\partial J/\partial z_B = \sigma(z_0)\,\sigma(z_B)(1-\sigma(z_B)) = 0.125\), and \(\partial J/\partial z_A = 0\). So \(\nabla J = (0.125,\ 0,\ 0.125)\).

Estimators. For a Bernoulli logit, \(\partial\log\pi(a)/\partial z = a - p\), so the score of a response is \(\big(a_1 - \tfrac12,\ (1-a_1)(a_2 - \tfrac12),\ a_1(a_2 - \tfrac12)\big)\) (only the logit that was used gets a term). The per-response gradient estimate is \(\hat g = \sum_t \text{score}_t\,(G_t - b_t)\). The critic's baseline is \(V(s_1) = J = 0.25\) at the prompt and \(V(s_2) = 0\) after "0", \(0.5\) after "1".

Actor-critic and generalized advantage estimation

A learned value function lets us replace the noisy return \(G_t\) with something built from a few real rewards plus a prediction. This is the actor-critic 演员-评论家 idea: the policy is the actor, the value model \(V_\phi\) is the critic. The building block is the TD residual 时序差分残差

\[ \delta_t = r_t + \gamma V_\phi(s_{t+1}) - V_\phi(s_t), \qquad V_\phi(s_{T+1}) := 0 \]

which, as shown above, equals the advantage when \(V_\phi = V^\pi\). Summing \(k\) discounted residuals telescopes into a \(k\)-step estimate:

\[ \hat A^{(k)}_t = \sum_{l=0}^{k-1} \gamma^l \delta_{t+l} = \underbrace{r_t + \gamma r_{t+1} + \dots + \gamma^{k-1} r_{t+k-1}}_{k \text{ real rewards}} + \gamma^k V_\phi(s_{t+k}) - V_\phi(s_t). \]

\(k = 1\) is \(\delta_t\): one real reward, then trust the critic, so variance is small but any critic error becomes bias. \(k \to \infty\) is the Monte-Carlo return minus \(V_\phi(s_t)\): no critic error enters except through the baseline (which never biases), but every future random choice adds variance. Generalized advantage estimation (GAE) 广义优势估计 averages all of them with geometric weights [Schulman et al. 2016, Eq. 16]:

\[ \hat A^{\text{GAE}(\gamma,\lambda)}_t = (1-\lambda)\sum_{k \ge 1} \lambda^{k-1} \hat A^{(k)}_t = \sum_{l=0}^{T-t} (\gamma\lambda)^l\, \delta_{t+l} = \delta_t + \gamma\lambda\, \hat A_{t+1} \]
GAE as an exponentially weighted sum of TD residuals, and its backward recursion (the implementation)

Why the two forms agree. Substitute \(\hat A^{(k)}_t = \sum_{l<k}\gamma^l\delta_{t+l}\) and collect the coefficient of \(\delta_{t+l}\): it is \(\gamma^l (1-\lambda)\sum_{k > l}\lambda^{k-1} = \gamma^l (1-\lambda)\,\lambda^l/(1-\lambda) = (\gamma\lambda)^l\). The recursion \(\hat A_t = \delta_t + \gamma\lambda\hat A_{t+1}\) then gives an \(O(T)\) backward loop.

What \(\gamma\) and \(\lambda\) each do

  • \(\lambda = 0\): \(\hat A_t = \delta_t\). Lowest variance, biased unless \(V_\phi = V^\pi\).
  • \(\lambda = 1\): \(\hat A_t = \sum_l \gamma^l r_{t+l} - V_\phi(s_t)\), the Monte-Carlo return minus a baseline. Unbiased whatever \(V_\phi\) is, highest variance.
  • \(\gamma\) versus \(\lambda\) are different knobs. "Taking \(\gamma < 1\) introduces bias into the policy gradient estimate, regardless of the value function's accuracy. On the other hand, \(\lambda < 1\) introduces bias only when the value function is inaccurate" [Schulman et al. 2016, §3]. The paper's experiments favored intermediate values (\(\gamma \in [0.96, 0.99]\) and \(\lambda \in [0.92, 0.99]\) on cart-pole, \(\lambda \in [0.9, 0.99]\) in its discussion) and it remarks that the best \(\lambda\) tends to sit below the best \(\gamma\) because \(\lambda\) adds far less bias when the critic is reasonable. PPO's MuJoCo settings are \(\gamma = 0.99\), \(\lambda = 0.95\) [Schulman et al. 2017, Tab. 3].
  • Reward-shaping view. \(\delta_t\) is the reward of a modified MDP, \(\tilde r_t = r_t + \gamma\Phi(s_{t+1}) - \Phi(s_t)\), with potential \(\Phi = V_\phi\). Such shaping leaves the advantage function unchanged, and GAE is the \((\gamma\lambda)\)-discounted return of the shaped reward. A good critic makes the shaped reward nearly immediate, so a steep extra discount \(\lambda\) discards little.
def gae(rewards, values, gamma, lam, mask, last_value=None):
    # rewards, values, mask: (B, T), right-padded; values[:, t] = V(s_t). Returns (advantages, returns) of shape (B, T).
    B, T = rewards.shape
    nxt = torch.zeros_like(values)
    nxt[:, :-1] = values[:, 1:] * mask[:, 1:]              # V(s_{t+1}); 0 after the last real token (EOS terminates)
    if last_value is not None:
        nxt[:, -1] = last_value * mask[:, -1]              # rows cut off at the length limit are bootstrapped
    delta = (rewards + gamma * nxt - values) * mask        # TD residuals
    adv, acc = torch.zeros_like(delta), torch.zeros(B)
    for t in reversed(range(T)):                           # A_t = delta_t + gamma * lam * A_{t+1}
        acc = (delta[:, t] + gamma * lam * acc) * mask[:, t]
        adv[:, t] = acc
    return adv, (adv + values) * mask                      # returns = A + V: the critic's regression target

This is the drill's gae. The "terminal bootstrap convention" is the two lines that set nxt: EOS means the next value is zero, a truncated row bootstraps from the critic. Many RLHF codebases instead give truncated responses a fixed penalty (Ziegler et al. use \(-1\)), which avoids asking the critic about an unfinished state [Huang et al. 2024, Detail 23].

The LLM setting: \(\gamma = 1\), one reward at the end

Set \(\gamma = \lambda = 1\) with only a terminal reward \(R\): GAE collapses to \(\hat A_t = R - V(s_t)\), REINFORCE with a learned per-token baseline, and with \(V \equiv 0\) to the plain bandit gradient. With \(\lambda < 1\) the picture changes. Take \(r_t = 0\) for \(t < T\) and \(\gamma = 1\): the residuals are \(\delta_t = V(s_{t+1}) - V(s_t)\) for \(t < T\) and \(\delta_T = R - V(s_T)\). Suppose the critic is untrained and outputs 0. Then every \(\delta_t\) before the end is zero, and

\[ \hat A_t = \lambda^{\,T-t}\, R. \]

The terminal reward decays geometrically as it travels backward. The half-life of the signal is \(\ln 0.5 / \ln\lambda\) tokens: 13.5 for \(\lambda = 0.95\), 69 for 0.99, 693 for 0.999. For a token 1,000 positions before the end, \(0.95^{1000} = 5.3\times10^{-23}\) and even \(0.99^{1000} = 4.3\times10^{-5}\). Such a token receives essentially no direct credit, and its advantage is whatever the critic's bootstrapped predictions imply. That is fine when the critic is good (the worked numbers below) and disastrous when it is not.

ByteDance's VC-PPO analysis of long chain-of-thought RL makes this concrete. Two defaults inherited from RLHF and control, GAE with \(\lambda = 0.95\) and a value model initialized from the reward model, produce a systematic bias: the reward model is trained to score only the EOS token, so it assigns lower values to earlier (more incomplete) prefixes, the advantage is positively biased and correlated with token position, and the policy learns to emit shorter responses until output length collapses. Their fixes are value pretraining (fit the critic to Monte-Carlo returns of a fixed policy before RL) and decoupled GAE: \(\lambda_{\text{critic}} = 1\) for the critic's regression target (no reward decay, no bootstrapped target) and \(\lambda_{\text{actor}} = 0.95\) for the policy advantage [Yuan et al. 2025, §3.2-3.3]. VAPO adds a length-adaptive \(\lambda_{\text{policy}} = 1 - 1/(\alpha\ell)\) with \(\alpha = 0.05\), which is 0.8 at \(\ell = 100\) tokens and 0.98 at 1,000. The number of residuals GAE effectively sums, \(1/(1-\lambda) = \alpha\ell\), then grows with the response length (5, then 50) instead of being fixed at 20 for every length; the authors' stated aim is a more uniform spread of TD errors across short and long responses [Yue et al. 2025, §4.2].

The value head and its loss

The critic is a scalar head on a transformer: a linear map \(d \to 1\) on the final hidden states, exactly the shape of the reward-model head of page 21. Alignment is the classic off-by-one: \(V(s_t)\) must be read at the position that produces the logits for \(a_t\), the last token of \(s_t\) (for \(t = 1\), the last prompt token), so one forward pass gives both \(\pi(\cdot|s_t)\) and \(V(s_t)\). The critic is usually a separate model. InstructGPT used a 6B reward model and a 6B value function, initialized from the reward model, for policies of every size [Ouyang et al. 2022, App. C.4]. Warm-starting from the RM is standard [Huang et al. 2024, Detail 22], but see the failure mode above.

The critic is trained by regression onto the \(\lambda\)-return \(\hat R_t = \hat A_t + V_{\text{old}}(s_t)\), where \(V_{\text{old}}\) is the critic that produced the rollout's values:

\[ L^{V}(\phi) = \tfrac12\, \E_t\Big[ \big(V_\phi(s_t) - \hat R_t\big)^2 \Big], \qquad L^{V}_{\text{clip}} = \tfrac12\,\E_t\Big[\max\Big( (V_\phi - \hat R_t)^2,\ \big(\clip(V_\phi,\, V_{\text{old}}-\epsilon_v,\, V_{\text{old}}+\epsilon_v) - \hat R_t\big)^2 \Big)\Big]. \]

Advantages must be computed with \(V_{\text{old}}\), not the freshly updated critic: in the extreme, an over-fit critic drives every residual to zero and with it the policy gradient [Schulman et al. 2016, §6.1]. The clipped variant is a code-level addition of the OpenAI baselines implementation, not in the PPO paper [Engstrom et al. 2020, §3]. Its value is contested: Andrychowicz et al. found it hurts performance on continuous control [§3.4], Ahmadian et al. disabled it without effect, and Huang et al. keep it with \(\epsilon_v = 0.2\) and coefficient \(c_1 = 0.1\) [Tab. 7]. A useful health metric is the critic's explained variance, \(1 - \mathrm{Var}(\hat R - V)/\mathrm{Var}(\hat R)\).

From your jet tagger

A value head looks like the classification or regression head you attached to your encoder, but the analogy stops at the architecture. Your labels were fixed, so regression converged to a stationary target. The critic's targets \(\hat R_t\) are the return of the current policy, which the actor changes every step, so the critic chases a moving target, and its errors feed back into the actor's advantages. That is why critic learning rate, initialization and \(\lambda\) matter far more here than head design.

From importance sampling to the PPO clip

Why we reuse samples, and what it costs

Generating a batch of responses is expensive: it is autoregressive decoding (page 06) on a model that will then be updated. We would like to take several gradient steps on each batch. But the policy gradient is an expectation over samples from the current policy. After one step, \(\theta \ne \theta_{\text{old}}\) and our tokens came from \(\pi_{\theta_{\text{old}}}\). InstructGPT splits each batch of 512 responses into 8 minibatches of 64 and makes one pass, so minibatch 1 is exactly on-policy and minibatches 2 to 8 are progressively stale [Ouyang et al. 2022, App. C.4]. Ziegler et al. take 4 PPO epochs over each batch [Ziegler et al. 2019, §2.2].

Importance sampling 重要性采样 repairs the mismatch for one decision: for any function \(f\), \(\E_{a \sim \pi_\theta}[f(a)] = \E_{a \sim \pi_{\text{old}}}[\rho\, f(a)]\) with the probability ratio

\[ \rho_t(\theta) = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_{\text{old}}}(a_t \mid s_t)} = \exp\big(\log\pi_\theta(a_t|s_t) - \log\pi_{\theta_{\text{old}}}(a_t|s_t)\big). \]

The surrogate objective is \(L^{\text{IS}}(\theta) = \E_{t}[\rho_t(\theta)\,\hat A_t]\), with tokens and advantages from the rollout policy. Its gradient is \(\rho_t \hat A_t \nabla\log\pi_\theta(a_t|s_t)\) (because \(\nabla\rho = \rho\,\nabla\log\pi_\theta\)), and at \(\theta = \theta_{\text{old}}\) we have \(\rho = 1\): the first step is exactly the on-policy gradient. Away from \(\theta_{\text{old}}\) it is an approximation, and it is worth knowing which one.

Where the surrogate comes from. Kakade and Langford's identity says that the exact improvement of a new policy over an old one is the old policy's advantage accumulated along the new policy's trajectories: \(J(\theta) - J(\theta_{\text{old}}) = \E_{\tau \sim \pi_\theta}[\sum_t A^{\pi_{\text{old}}}(s_t, a_t)]\) [Schulman et al. 2015, Eq. 1]. The trouble is that states \(s_t\) are drawn from \(\pi_\theta\). The surrogate replaces them by states from \(\pi_{\text{old}}\), which is what we have samples of. That is the only approximation, and it matches \(J\) in value and gradient at \(\theta_{\text{old}}\) [Eq. 4]. For an LLM it has a clear meaning: the ratio \(\rho_t\) corrects how likely token \(a_t\) is given its prefix, but ignores that changing earlier tokens changes which prefixes are visited at all.

How far can we trust it? TRPO proves a lower bound, \(J(\theta) \ge L(\theta) - C\, D_{\text{KL}}^{\max}(\theta_{\text{old}}, \theta)\) with \(C = 4\varepsilon\gamma/(1-\gamma)^2\), where \(\varepsilon = \max|A|\). The proof sums \(\varepsilon\,\gamma^t\,4\alpha\,(1-(1-\alpha)^t)\) over time steps, where \(\alpha\) is the maximum total-variation distance between the policies, and \(\alpha^2 \le D_{\text{KL}}\) converts the result to KL [Schulman et al. 2015, Thm. 1, App. A]. The constant explodes as \(\gamma \to 1\), which is our regime. Redoing the same sum with \(\gamma = 1\) over a horizon \(T\), and using \(1-(1-\alpha)^t \le t\alpha\), gives \(\sum_{t=0}^{T-1} 4\alpha\,(1-(1-\alpha)^t) \le 4\alpha^2\sum_{t} t = 2\alpha^2 T(T-1)\), so \(J(\theta) \ge L(\theta) - 2\varepsilon\,T(T-1)\,D_{\text{KL}}^{\max}\) (our derivation from their proof, not a stated result). At \(T = 10^3\) the coefficient is about \(2\times10^{6}\,\varepsilon\): useless as a numeric guarantee, but it says the right thing qualitatively. A policy change compounds over the length of the sequence, so the safe step shrinks with response length and we need a trust region 信任区域.

TRPO enforces one exactly: maximize \(L(\theta)\) subject to a bound \(\delta\) on the average KL between old and new policies (the theory's penalty coefficient \(C\) would give "very small" steps), solved with conjugate gradient and a line search. That works, but it is second-order machinery that does not combine cleanly with dropout or parameters shared between actor and critic [Schulman et al. 2017, §1]. PPO keeps the idea and drops the machinery.

The clipped objective

Proximal policy optimization 近端策略优化 (PPO) clips the ratio inside the objective [Schulman et al. 2017, Eq. 7]:

\[ L^{\text{CLIP}}(\theta) = \E_t\Big[ \min\big( \rho_t(\theta)\,\hat A_t,\ \ \clip(\rho_t(\theta),\, 1-\epsilon,\, 1+\epsilon)\,\hat A_t \big) \Big], \qquad \epsilon = 0.2 \text{ typically} \]
Maximize \(L^{\text{CLIP}}\) (the code minimizes its negative). At \(\rho = 1\) it equals the plain surrogate to first order

The first term inside the min is the surrogate \(\rho\hat A\). The second removes the incentive to move \(\rho\) outside \([1-\epsilon, 1+\epsilon]\). Taking the minimum makes the whole objective a pessimistic bound on the surrogate. In the paper's words, "we only ignore the change in probability ratio when it would make the objective improve, and we include it when it makes the objective worse". Clipping alone, \(\clip(\rho, 1-\epsilon, 1+\epsilon)\hat A\), has zero gradient whenever \(\rho\) is outside the band, on either side.

Outside the band on the improving side the clipped term is smaller, so it wins and the gradient vanishes (no incentive to go further). On the worsening side the unclipped term is smaller, so it wins and the gradient stays (the step is corrected).

What the clip does not do

  • It is not a constraint. The clip only zeroes the gradient of tokens already outside the band. Engstrom et al. found that the maximum ratio during PPO training on MuJoCo consistently violates the \(1+\epsilon\) line, and that with tuning a PPO variant without clipping often matched PPO with it. Their account: the first step is identical to an unclipped step, and the trust region that emerges depends on how the objective is optimized (learning rate, momentum) rather than on the objective itself [Engstrom et al. 2020, §4-5].
  • It is per token, but parameters are shared. A token inside the band can still be dragged outside by the gradients of other tokens.
  • It is often inactive. In their RLHF runs Ahmadian et al. found the loss clipped on average under 5% of the time, and removing clipping (and then the ratio itself) changed nothing [§3.2]. With one update per batch, DeepSeekMath's own analysis sets \(\pi_{\text{old}} = \pi_\theta\) and drops both the min and the clip [Shao et al. 2024, App. A.1.5]. Clipping earns its keep when data are reused or arrive asynchronously (page 25).
  • It bounds relative, not absolute, probability change. A token can move by a factor \(1\pm\epsilon\): \(0.01 \to 0.012\), \(0.10 \to 0.12\), \(0.50 \to 0.60\), and \(0.90 \to 1.08\), which exceeds 1 and so never binds. Rare "exploration" tokens with positive advantage are therefore held back most tightly, the observation behind DAPO's Clip-Higher (\(\epsilon_{\text{low}} = 0.2\), \(\epsilon_{\text{high}} = 0.28\)) [Yu et al. 2025, §3.1]. The drill's eps_high argument implements it.

Monitor three numbers in any PPO run: the fraction of tokens clipped, an approximate KL between old and new policies (the k3 estimator below, with \(r = \rho_t\), estimates \(\KL(\pi_{\text{old}}\|\pi_\theta)\) from the rollout tokens), and the maximum ratio. A ratio that is not exactly 1 on the first minibatch is a bug or a numerics mismatch (dropout left on, or old log-probabilities taken from a sampler whose kernels differ from the trainer's, page 25), which is why Huang et al. disable dropout during RLHF [Detail 7].

The full objective and one PPO iteration

PPO's objective for a shared actor-critic network adds a value loss and an entropy bonus [Schulman et al. 2017, Eq. 9]: \(L = L^{\text{CLIP}} - c_1 L^{V} + c_2 S[\pi_\theta]\). With separate actor and critic models (the LLM norm) no parameters are shared, and \(c_1\) only rescales the critic's step relative to the actor's. The RLHF recipes cited on this page list no entropy term, because the KL penalty already keeps entropy from collapsing: Ziegler et al. say it "plays the role of an entropy bonus" [§2]. One iteration, in the order that matters:

def ppo_iteration(policy, ref, critic, reward_fn, prompts, K=4, beta=0.05, eps=0.2, gamma=1.0, lam=0.95):
    resp, mask = policy.generate(prompts)                   # (B, T) tokens and 0/1 response mask
    with torch.no_grad():                                   # 1) everything below is frozen at rollout time
        logp_old = policy.logprobs(prompts, resp)           # (B, T) log pi_old(a_t | s_t), recomputed by the trainer
        logp_ref = ref.logprobs(prompts, resp)              # (B, T)
        values   = critic.values(prompts, resp)             # (B, T) V_old(s_t)
        rewards  = -beta * (logp_old - logp_ref) * mask     # 2) KL shaping on every token: -beta * k1
        last     = mask.sum(1).long() - 1
        rewards[torch.arange(len(last)), last] += reward_fn(prompts, resp)   # task reward on the last real token
        adv, ret = gae(rewards, values, gamma, lam, mask)   # 3) advantages and critic targets
        adv      = masked_whiten(adv, mask)                 #    normalize advantages over the batch
    for _ in range(K):                                      # 4) K passes over the same batch
        logp = policy.logprobs(prompts, resp)               #    with grad
        loss_pi = ppo_clip_loss(logp, logp_old, adv, eps, mask)
        loss_v  = 0.5 * ((critic.values(prompts, resp) - ret).pow(2) * mask).sum() / mask.sum()
        policy.step(loss_pi); critic.step(loss_v)           #    separate optimizers for actor and critic

Deleting the critic (let values be a per-prompt mean reward and set \(\lambda = 1\)) and using \(K = 1\) turns this loop into REINFORCE or RLOO training with a KL-shaped reward. Real implementations split each pass into minibatches. The drill implements gae, masked_whiten and ppo_clip_loss.

Pitfall: implementation details are part of the algorithm

In continuous control, "code-level optimizations" (value clipping, reward scaling, initialization, learning-rate annealing) mattered more for final reward than the choice between PPO and TRPO [Engstrom et al. 2020, §3, §5], and Huang et al. list over 20 such details for RLHF [Details 7 to 25]. When someone reports that PPO "does not work", ask which of these were set.

KL control: the penalty and its estimators

Why penalize distance from the reference policy

A reward model is a proxy fit on responses from roughly the SFT policy \(\pi_{\text{ref}}\). Far from that distribution its scores are unreliable, and an optimizer will find the unreliable spots (page 21 quantifies this). The penalty keeps the policy where the reward is trustworthy. Ziegler et al. list three roles: it "plays the role of an entropy bonus, it prevents the policy from moving too far from the range where \(r\) is valid", and for their style tasks it is part of the task definition, since humans judged style and the KL term supplied coherence [Ziegler et al. 2019, §2]. They also recount a sign-flip bug that flipped the reward and the KL term: the model optimized for maximally bad output while staying fluent, a reminder that the KL term pulls toward the reference, not toward good behavior.

How large is too far? Huang et al.'s 1B policies that reached a summed per-token KL of about 50 and 85 nats did raise the RLHF reward, and GPT-3.5 judged them worse than reference summaries more than 80% of the time; the policies had learned to concatenate words without spaces [§7.1]. InstructGPT found the best \(\beta\) around 0.01 to 0.02, and both \(\beta = 0\) and \(\beta = 2\) gave poor results; raising \(\beta\) 100-fold to 2.0 did not repair regressions on public benchmarks, which needed the pretraining-mix term instead [Ouyang et al. 2022, App. E.6-E.7].

The regularized objective is the one from page 21, \(J_\beta(\theta) = \E[R(x,y)] - \beta\,\KL(\pi_\theta \| \pi_{\text{ref}})\). The KL is over whole sequences, and by the chain rule it is the expected sum of per-token KLs:

\[ \KL(\pi_\theta \| \pi_{\text{ref}}) = \E_{y \sim \pi_\theta}\Big[\log\frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)}\Big] = \E\Big[\sum_{t=1}^{T} \ell_t\Big], \qquad \ell_t := \log\pi_\theta(a_t|s_t) - \log\pi_{\text{ref}}(a_t|s_t). \]

Where it enters: in the reward or in the loss

In the reward (InstructGPT, Ziegler et al., Huang et al.'s PPO recipe; DeepSeekMath calls it PPO's standard approach [Shao et al. 2024, Eq. 2]). Each token gets \(\tilde r_t = -\beta\,\ell_t\), and the last token also gets the reward-model score. This is the "per-token KL penalty from the SFT model at each token" of InstructGPT [§3.5], and it is the sequence-level reward \(R(x,y) = r(x,y) - \beta\log\pi(y|x)/\rho(y|x)\) of Ziegler et al. written token by token [Eq. 2]. It flows through returns and GAE like any other reward. For on-policy samples this gives the exact gradient of \(J_\beta\). Differentiating the KL term directly,

\[ \nabla\,\E\Big[\sum_t \ell_t\Big] = \E\Big[\sum_t \nabla\log\pi(a_t|s_t)\sum_{s \ge t}\ell_s\Big] + \E\Big[\sum_t \underbrace{\nabla\ell_t}_{=\nabla\log\pi(a_t|s_t)}\Big], \]

where the second expectation is zero by the lemma. So treating \(\ell_t\) as a fixed reward and running the policy gradient, which uses reward-to-go \(\sum_{s\ge t}\ell_s\), is exact. The single-sample k1 is all you need.

In the loss (GRPO). The advantage stays the outcome advantage, and a separate term \(+\beta\,k_3(a_t)\) is added to the per-token loss, "avoiding complicating the calculation of \(\hat A_{i,t}\)" [Shao et al. 2024, §4.1.1] (\(\beta = 0.04\) in DeepSeekMath). DeepSeek-V3.2 still uses this form, with a correction discussed below [§3.1]. Long-CoT recipes with verifiable rewards often drop the term entirely: DAPO argues the model may legitimately drift far from the initial one, and Dr. GRPO assumes \(\beta = 0\), which also frees the memory of the reference model [Yu et al. 2025, §2.3] [Liu et al. 2025, §3].

Choosing \(\beta\); and not confusing two KLs

Fixed \(\beta\) values in the literature: 0.1 and 0.03 (Ziegler et al., CNN/DM and TL;DR), 0.02 (InstructGPT), 0.05 (Huang et al.), 0.04 (DeepSeekMath's GRPO), 0 for verifier-reward long-CoT runs. Because different seeds with the same \(\beta\) end at different KLs, Ziegler et al. also use a log-space proportional controller that steers the KL to a target (6 nats for their descriptiveness task, 10 for sentiment):

\[ e_t = \clip\!\Big(\frac{\KL(\pi_t\|\rho) - \KL_{\text{target}}}{\KL_{\text{target}}},\ -0.2,\ 0.2\Big), \qquad \beta_{t+1} = \beta_t\,(1 + K_\beta\, e_t), \quad K_\beta = 0.1 \]

so \(\beta\) changes by at most \(0.1 \times 0.2 = 2\%\) per update [Ziegler et al. 2019, §2.2, §3.1.2].

Pitfall: two different KLs are called "the KL"

The KL to the reference policy \(\KL(\pi_\theta\|\pi_{\text{ref}})\) accumulates over the whole run and reaches tens of nats. The KL between old and new policy \(\KL(\pi_{\text{old}}\|\pi_\theta)\) is the per-update trust-region quantity: about 0.02 at the maximizer of the PPO surrogate on the first Hopper update, in the PPO paper's Figure 2, and it is what TRPO constrains and what PPO's own adaptive-KL variant targets (\(d_{\text{targ}} = 0.003\) to 0.03, with \(\beta\) halved or doubled when the measured KL falls below \(d_{\text{targ}}/1.5\) or exceeds \(1.5\,d_{\text{targ}}\)) [Schulman et al. 2017, §4, Fig. 2]. They have different scales, different purposes, and different \(\beta\)s.

Estimating KL from samples: k1, k2, k3

For one token position we could compute \(\KL\) exactly, \(\sum_a \pi_\theta(a|s)\log\frac{\pi_\theta(a|s)}{\pi_{\text{ref}}(a|s)}\), but that needs both full \(V\)-dimensional distributions at every position, and the sequence-level KL has no such shortcut. What we always have are the two log-probabilities of the sampled token. Schulman's note "Approximating KL Divergence" gives three estimators of \(\KL[q,p] = \E_{x\sim q}[\log q/p]\) from \(x \sim q\), with \(r = p(x)/q(x)\) [Schulman 2020]. In our setting the sampling distribution is the policy, \(q = \pi_\theta\), and \(p = \pi_{\text{ref}}\), so \(r = \pi_{\text{ref}}(a|s)/\pi_\theta(a|s)\) and \(\log r = -\ell_t\):

\[ k_1 = -\log r = \ell_t, \qquad k_2 = \tfrac12 (\log r)^2, \qquad k_3 = (r - 1) - \log r, \qquad r = \frac{\pi_{\text{ref}}(a|s)}{\pi_\theta(a|s)},\ \ a \sim \pi_\theta \]
The samples come from \(\pi_\theta\), the target is \(\KL(\pi_\theta\|\pi_{\text{ref}})\). Getting the sampling distribution wrong is the common error
  • k1 is unbiased and noisy. \(\E_q[-\log r] = \KL\) by definition. But the KL is nonnegative while \(k_1\) is negative whenever the sampled token is more likely under \(\pi_{\text{ref}}\) than under \(\pi_\theta\), which is about half the tokens when the policies are close. Its standard deviation is 20 times the true KL when the KL is 0.005.
  • k2 is a biased, low-variance estimator with a principled reason. \(\E_q[\tfrac12(\log r)^2]\) is an \(f\)-divergence with \(f(x) = \tfrac12(\log x)^2\), and all differentiable \(f\)-divergences agree with KL to second order when \(q \approx p\) (here \(f''(1) = 1\) for both). So the bias is tiny for nearby policies and grows as they separate.
  • k3 is k1 plus a control variate. Since \(\E_q[r] = \sum_x p(x) = 1\), the term \(\lambda(r-1)\) has mean zero, so \(-\log r + \lambda(r-1)\) is unbiased for every \(\lambda\). Choosing \(\lambda = 1\) makes it nonnegative because \(\log r \le r - 1\): \(k_3\) is the vertical gap between \(\log r\) and its tangent at \(r = 1\), a Bregman divergence (in Figure 4's coordinates \(x = \log r\), the gap between \(e^x\) and its tangent \(1 + x\)). Unbiased, never negative, and usually low variance.

An estimator is not its gradient

The estimators are unbiased values of the KL (k2 nearly so). When you add \(\beta k(a_t)\) to a loss and call backward(), autodiff treats the sampled token \(a_t\) as fixed and differentiates only the integrand. The true gradient has two parts [Tang and Munos 2025, App. B]:

\[ \nabla_\theta\, \E_{a\sim\pi_\theta}[k(a)] = \underbrace{\E[\nabla_\theta k(a)]}_{\text{what autodiff computes}} + \underbrace{\E[k(a)\,\nabla_\theta\log\pi_\theta(a)]}_{\text{score-function part, missing}}. \]

Work out what the first term is for each estimator, using \(\nabla r = -r\,\nabla\log\pi_\theta\) and the lemma \(\E_\pi[\nabla\log\pi] = 0\):

  • \(\nabla k_1 = \nabla\log\pi_\theta\), whose expectation is 0. A k1 loss adds noise and no regularization.
  • \(\nabla k_2 = \log r\,\nabla\log r = \ell\,\nabla\log\pi_\theta\), and \(\E_\pi[\ell\,\nabla\log\pi] = \nabla\KL(\pi_\theta\|\pi_{\text{ref}})\) exactly. k2 as a loss has the correct gradient.
  • \(\nabla k_3 = (1 - r)\,\nabla\log\pi_\theta\), and \(\E_\pi[(1-r)\nabla\log\pi] = -\sum_a \pi_{\text{ref}}\nabla\log\pi_\theta = \nabla\KL(\pi_{\text{ref}}\|\pi_\theta)\). k3 as a loss descends the other direction of the KL, \(\KL(\pi_{\text{ref}}\|\pi_\theta)\), not the one it estimates.

The sequence problem. There is a second gap. The full sequence-level gradient is \(\E[\sum_t \nabla\log\pi_t \sum_{s\ge t}\ell_s]\), while a per-token loss at best delivers the \(s = t\) terms: the effect of token \(a_t\) on later tokens' KL is dropped [Tang and Munos 2025, §4]. The shaped-reward route of the previous subsection keeps all of them. For on-policy data, putting the estimator in both the reward (with stop-gradient) and the loss reproduces the full gradient for any unbiased estimator, and Shah et al. confirm that such configurations beat k3-in-loss [App. D.2].

Off-policy. The samples usually come from \(\pi_{\text{old}}\), not \(\pi_\theta\), so even the value of k3 is estimated under the wrong distribution after the first minibatch. DeepSeek-V3.2 multiplies k3 by the ratio \(\pi_\theta/\pi_{\text{old}}\), which restores an unbiased KL and gradient estimate for the sampling distribution it actually has [§3.1, Eq. 7]. In short: k1 in the reward is the safe default, k3 in the loss is a common regularizer that is not the gradient of what it claims, and k2 is the one whose autodiff gradient is right.

Token level versus sequence level: credit, ratio and loss

"Token-level" versus "sequence-level" names three separate choices that are often conflated. Keep them apart, because page 24 is built on exactly these distinctions.

1. Credit: one advantage per response, or one per token

With outcome supervision and a group baseline (GRPO, RLOO), the advantage of every token in response \(i\) is the same number: \(\hat A_{i,t} = \hat A_i\) [Shao et al. 2024, §4.1.2]. This is what "bandit-like" means in practice. The consequences for credit assignment:

  • Nothing in one sample says which tokens caused the outcome. A token's update is the correlation between "this choice appeared" and "the outcome was good", and it only becomes informative by averaging over many samples of the same prompt. The signal-to-noise ratio of a prompt's gradient grows roughly like the square root of the group size.
  • Most tokens of a long derivation do not decide the outcome, so their gradient terms are noise. The estimator's variance grows with response length, which is one reason RL learning rates are small (\(10^{-6}\) in the recipes above).
  • A critic can in principle localize credit, since \(A_t = \delta_t\) is the change in predicted success caused by token \(t\). DeepSeekMath's argument against a critic is that with only the last token rewarded it "may complicate the training of a value function that is accurate at each token" [§4.1.1]; VAPO's answer is that a well-engineered critic has a "higher performance ceiling" [Yue et al. 2025, §1]. That is a claim from one group, so treat it as open. Process reward models (page 23) attack the same problem from the reward side.

2. Importance ratio: per token or per sequence

PPO and GRPO use the token ratio \(\rho_t = \pi_\theta(y_t|s_t)/\pi_{\text{old}}(y_t|s_t)\). A sequence-level ratio is the product \(\prod_t \rho_t = \pi_\theta(y|x)/\pi_{\text{old}}(y|x)\). GSPO uses its length-normalized geometric mean, and clips whole responses [Zheng et al. 2025, Eq. 5-7]:

\[ s_i(\theta) = \Big(\frac{\pi_\theta(y_i|x)}{\pi_{\text{old}}(y_i|x)}\Big)^{1/|y_i|} = \exp\Big(\frac{1}{|y_i|}\sum_{t=1}^{|y_i|}\log\rho_{i,t}\Big). \]

Their argument is that importance sampling needs many samples of the behavior distribution to correct a mismatch, whereas a token ratio is computed from a single sample of each next-token distribution, so it "introduces high-variance noise" that accumulates with length, and "the unit of optimization objective should match the unit of reward". They report clipped-token fractions differing by two orders of magnitude (0.0013 for GSPO against 0.15 for GRPO) and more stable MoE training, where about 10% of activated experts change after each update on Qwen3-30B-A3B-Base [§3, §5.2-5.3]. Read this alongside the surrogate derivation: the token ratio is the principled object when we want the first-order Kakade-Langford surrogate, and the product is the exact sequence-level importance weight but with variance that grows with length. Which is better in practice depends on how off-policy your data are, and the evidence so far comes from one group's MoE setting.

3. Loss normalization: how per-token terms are averaged

The exact policy-gradient estimator sums token terms and averages over responses. Implementations divide by something, and the divisor changes the weight each token's gradient gets. For response \(i\) with advantage \(A_i\) and \(|o_i|\) tokens, in a group of \(G\), the weight on \(\nabla\log\pi\) of each of its tokens is, up to a factor \(1/G\) common to all rows:

Worked example. Two responses to one prompt: a correct one with 2 tokens (\(A = +1\)) and an incorrect one with 8 tokens (\(A = -1\)). The exact estimator weights every token by \(|A| = 1\), so the totals per response are 2 and 8. Liu et al. show this pushes toward longer wrong answers, because for negative advantages a larger \(|o_i|\) means a smaller penalty per token [§3.1]. Under token-mean the mean length is \(\overline{|o|} = 5\), every token has weight \(1/5\), the totals are 0.4 and 1.6, and the long response holds 80% of the weight. Liu et al. also checked several open PPO implementations (TRL, OpenRLHF, verl, SimpleRL-Zero, Open-Reasoner-Zero) and found all of them normalize by response length, so the "formulation-implementation misalignment" predates GRPO [§3.1, Tab. 2]. DAPO reports that moving GRPO to a token-level loss lifted AIME 2024 from 41 to 42 (avg@32) and, more importantly, made length and entropy growth healthier [Tab. 1, §3.3]. The drill's ppo_clip_loss takes agg="token" or "seq" for exactly this reason. The normalizer is a design choice with consequences, not a cosmetic detail: pick one deliberately and log response length.

Practicalities: whitening, scales, conventions, and the four-model footprint

Most of what separates a PPO run that learns from one that does not is in this list. Each item has a reason, and each was learned the hard way.

  • Whiten advantages over the batch. Subtract the (masked) mean and divide by the standard deviation across all response tokens in the batch (masked_whiten in the drill). This makes the update invariant to a global rescaling of all rewards, so the learning rate need not be retuned when the rewards change units (the relative size of the reward-model score and \(\beta\ell_t\) still matters) [Huang et al. 2024, Detail 25]. Do it across the batch, not per prompt: Liu et al. show that dividing by the per-prompt standard deviation gives prompts with near-uniform outcomes (too easy or too hard) higher weight, a "difficulty bias", whereas batch-level normalization is the standard trick [§3.1]. In continuous control, per-minibatch advantage normalization "seems not to affect the performance too much" [Andrychowicz et al. 2021, §3.3].
  • Fix the reward scale and offset. A reward model's output is defined only up to a shift, so InstructGPT adds a bias so that labeler demonstrations score 0 on average before RL [§3.5], and Ziegler et al. normalize to mean 0 and variance 1 on reference samples [§2]. The scale relative to \(\beta\,\ell_t\) is what sets the effective KL strength. Reward whitening is optional; in Huang et al.'s ablation it made responses shorter and lowered the GPT-judged win rate, though length-controlled comparisons looked similar [Detail 24, §7.1].
  • Reward at EOS, and what a truncated response gets. The reward model reads the EOS token, so a response without EOS has no defined score. Huang et al. assign a constant \(-1\) in that case, which also discourages rambling [Details 12, 23]. The alternative is to bootstrap from the critic (the last_value argument of gae).
  • Critic initialization and learning rate. Warm-starting the critic from the reward model is standard and can bias early advantages on long responses (above). In VC-PPO and VAPO the critic gets twice the actor's learning rate (2e-6 against 1e-6), because it must keep pace with a moving policy.
  • Turn dropout off. With dropout the log-probabilities of the same tokens differ between passes, so \(\rho\) is not 1 on the first minibatch and the KL penalty is noisy [Huang et al. 2024, Detail 7].
  • Compute \(\log\pi_{\text{old}}\) with the trainer's forward pass, as is typical [Zheng et al. 2025, §5.4], and with the same temperature and sampling mask as the sampler. Truncated sampling (top-p, top-k) makes \(\pi_{\text{old}}\) live on a different action set from \(\pi_\theta\), which breaks importance sampling; DeepSeek-V3.2 saves the truncation masks at sampling time and reapplies them in training ("Keep Sampling Mask") [§3.1]. Rollout engine versus trainer numerics is the subject of page 25.
  • Mask carefully. The response mask must exclude the prompt and padding, include the EOS token (it is an action and carries the reward), and be used identically in the ratio, the KL, the value loss and the whitening statistics.
  • Watch a handful of numbers: mean reward, KL to the reference (per token and per sequence), fraction of clipped tokens, old-versus-new approximate KL, response length, critic explained variance, and policy entropy. Length collapse or explosion and entropy collapse are the classic failure signatures.

As of September 2026

Most publicly documented reasoning-RL recipes are critic-free, group-baseline methods: DeepSeekMath introduced GRPO, DeepSeek-V3.2 still trains with it (adding an off-policy correction to k3, sequence masking of stale negative samples, and "Keep Routing" for MoE models [DeepSeek-V3.2, §3.1]), and DAPO, Dr. GRPO and GSPO are variants of it. Critic-based PPO remains alive where teams engineer the critic: VAPO reports 60.4 on AIME 2024 with Qwen2.5-32B, against 50 for DAPO in the same setup [Yue et al. 2025]. Neither camp has settled the question, and every number here is from a single lab's runs on a small benchmark. The derivations on this page apply to both: GRPO is REINFORCE with a group baseline, a token-level PPO clip and, optionally, a k3 loss.

Common misconceptions

  • "Subtracting a baseline changes what you optimize." It changes only the variance. Any \(b\) that is fixed before the token is chosen has zero expected contribution (the score function has zero mean). What does bias the gradient is a baseline that peeks at the action or the outcome: a sample's own reward gives a rescaled \((1-1/G)\) gradient, and \(b = G_t\) gives zero.
  • "PPO's clip keeps the ratio inside \([1-\epsilon, 1+\epsilon]\)." The clip only zeroes the gradient of tokens that have already moved outside on the improving side. The first minibatch is unclipped by construction, tokens share parameters, momentum carries on, and measured maximum ratios exceed the band. Track the clip fraction and the approximate KL instead of assuming a trust region.
  • "GAE with \(\lambda = 0.95\) is a harmless default." It was tuned on locomotion with dense rewards. With \(\gamma = 1\), a terminal reward and thousands of tokens, the reward reaches token \(t\) scaled by \(\lambda^{T-t}\), essentially zero far from the end, so early tokens depend on the critic's bootstrapped predictions. Also keep \(\gamma = 1\): \(\gamma < 1\) turns a terminal reward into an implicit length penalty \(\gamma^{T-1}\).
  • "Adding \(\beta\,k_3\) to the loss minimizes \(\beta\,\KL(\pi_\theta\|\pi_{\text{ref}})\)." Autodiff of a k3 loss gives the gradient of \(\KL(\pi_{\text{ref}}\|\pi_\theta)\), per token, and misses the effect of a token on later tokens' KL. A k1 loss has zero expected gradient. Only k1 in the reward (or k2 as a token-level loss) has the right gradient.
  • "k3 is strictly better than k1." It is unbiased, nonnegative and far less noisy when the policies are close. When the sampled token has \(\pi_\theta \ll \pi_{\text{ref}}\), \(r\) is large and k3's variance and gradient weights blow up (3-token example above: std 0.87 versus 0.52).
  • "There is one KL in RLHF." The KL to the reference accumulates over a run (tens of nats) and is a regularizer. The KL between the old and the new policy is a per-update trust-region quantity (about 0.02 nats in the PPO paper's example). They have different scales and different coefficients.
  • "PPO is an off-policy algorithm." It is near-on-policy: samples come from \(\pi_{\text{old}}\), the ratio corrects the action probabilities at the visited prefixes, and the clip limits how stale the data may become. The ratio does not correct the shift in which prefixes are visited, which is why the surrogate is only a local approximation.
  • "Dividing the loss by response length is cosmetic." It changes each token's weight: with \(1/|o_i|\), a token in a long wrong answer is penalized less than one in a short wrong answer, biasing toward longer errors, and many PPO code bases do it by default. Choose the normalizer deliberately and log lengths.

Interview questions

Warm-up Formulate LLM generation as an MDP. What are the state, action, transition and reward, and why is \(\gamma = 1\)?

State \(s_t = (x, y_{<t})\), the prompt plus the tokens so far. Action \(a_t = y_t\), the next token from the vocabulary; EOS is an action, so episode length is random. The policy \(\pi_\theta(a|s)\) is the LM's next-token distribution. The transition is deterministic: append the token. The reward is zero until the end, where a reward model or verifier scores the whole response; per-token KL terms may add small rewards along the way. The objective is \(J = \E_{x, y\sim\pi_\theta}[R(x,y)]\).

\(\gamma = 1\) because the horizon is finite and the reward is terminal: any \(\gamma < 1\) multiplies the reward by \(\gamma^{T-1}\), an accidental length preference, and it biases the gradient of the true objective regardless of the critic (GAE paper). InstructGPT and Ziegler et al. use no discount. The same problem is a contextual bandit if you call the whole response one action; with a terminal reward the two give the same expected gradient.

Warm-up What is the log-derivative trick and why does RL for LLMs need it?

\(\nabla p_\theta = p_\theta\,\nabla\log p_\theta\), so \(\nabla_\theta \E_{y\sim\pi_\theta}[R(y)] = \sum_y \nabla\pi_\theta(y) R(y) = \E_{y\sim\pi_\theta}[R(y)\,\nabla\log\pi_\theta(y)]\). It turns a gradient of an expectation into an expectation of a gradient that we can sample.

We need it for three reasons. The reward comes from a black box (a reward model evaluated on decoded text, or a program) and is not differentiable in \(\theta\). Sampling a discrete token is not differentiable either. And the sum over \(|\mathcal V|^T\) sequences cannot be enumerated. The estimator only evaluates \(R\) and differentiates \(\log\pi_\theta\), which factorizes into a sum over tokens. Its price is variance, which is what baselines and critics address.

Warm-up Why is a KL penalty to the reference model used in RLHF?

The reward model is a proxy trained on samples near the SFT policy. Away from that distribution its scores are unreliable, and an optimizer finds the unreliable region: reward rises while true quality falls (over-optimization). Huang et al.'s 1B policies at 50 to 85 nats of summed KL had higher RLHF reward but were judged worse than reference summaries over 80% of the time, with garbled strings. The penalty keeps the policy in the region where the reward is valid, preserves fluency, and acts like an entropy bonus so the policy does not collapse to a single mode [Ziegler et al.].

It also has a clean meaning: \(J_\beta = \E[R] - \beta\,\KL(\pi\|\pi_{\text{ref}})\) has the closed-form optimum \(\pi^\star \propto \pi_{\text{ref}}\exp(R/\beta)\) (page 21). The coefficient is a trade-off: InstructGPT's best values were around 0.01 to 0.02, \(\beta = 0\) drifts, and a 100-fold larger \(\beta\) did not fix benchmark regressions. With a verifier reward that is hard to hack, long-CoT recipes such as DAPO drop the term entirely.

Warm-up Where does the KL penalty enter in InstructGPT-style PPO, and where in GRPO?

PPO (InstructGPT): in the reward. Every token gets \(-\beta(\log\pi_\theta(a_t|s_t) - \log\pi_{\text{ref}}(a_t|s_t))\), the k1 estimator, and the last token also gets the reward-model score. These rewards pass through returns, GAE and the critic, so the policy gradient uses reward-to-go that includes future KL. That is the exact gradient of the KL-regularized objective.

GRPO: in the loss. The advantage is the group-normalized outcome reward, untouched by KL, and \(\beta\,k_3\) with \(k_3 = \frac{\pi_{\text{ref}}}{\pi_\theta} - \log\frac{\pi_{\text{ref}}}{\pi_\theta} - 1\) is added per token, \(\beta = 0.04\) in DeepSeekMath. It is simpler, but the gradient of a k3 loss is that of the other KL direction and per token only (see the deep-dive question). DeepSeek-V3.2 multiplies it by \(\pi_\theta/\pi_{\text{old}}\) because samples come from the old policy.

Core Derive the policy gradient. Why does subtracting a baseline not bias it?

Derivation. \(J = \sum_\tau p_\theta(\tau)R(\tau)\) with \(p_\theta(\tau) = \mathcal D(x)\prod_t\pi_\theta(a_t|s_t)\). Use \(\nabla p = p\nabla\log p\): \(\nabla J = \E_\tau[R(\tau)\nabla\log p_\theta(\tau)]\). The prompt term has no \(\theta\), so \(\nabla\log p_\theta(\tau) = \sum_t\nabla\log\pi_\theta(a_t|s_t)\). Causality: for \(t'<t\), \(\E[r_{t'}\nabla\log\pi(a_t|s_t)] = 0\) because \(r_{t'}\) is fixed by the prefix and \(\E_{a_t}[\nabla\log\pi(a_t|s_t)] = 0\). So \(\nabla J = \E[\sum_t\nabla\log\pi_\theta(a_t|s_t)\,G_t]\) with reward-to-go \(G_t\).

Baseline. For any \(b(s_t)\) independent of \(a_t\): \(\E[\nabla\log\pi(a_t|s_t)\,b(s_t)] = \E[b(s_t)\sum_a\nabla\pi(a|s_t)] = \E[b(s_t)\,\nabla 1] = 0\). Only the variance changes. It fails if \(b\) depends on \(a_t\) or on the sample's own outcome (\(b = G_t\) zeroes the estimator; a group mean including the sample rescales the gradient by \(1-1/G\)). The variance-minimizing scalar baseline is \(\E[\|\nabla\log\pi\|^2G]/\E[\|\nabla\log\pi\|^2]\), close to \(V(s_t)\) when the score norm is roughly independent of the return.

A sanity example: a 2-token MDP with reward 1 only for "11" has \(\nabla J = (0.125, 0, 0.125)\); the estimator's variance is 0.094 with no baseline, 0.0625 with \(b = J\) and 0.047 with \(b = V(s_t)\), all with the same mean.

Core What is the advantage function and how does GAE estimate it?

\(A^\pi(s,a) = Q^\pi(s,a) - V^\pi(s)\): how much better action \(a\) is than the policy's average action in \(s\). In an LLM the next state is a deterministic function of \((s,a)\), so \(Q(s_t,a_t) = r_t + V(s_{t+1})\) and \(A_t = \delta_t = r_t + V(s_{t+1}) - V(s_t)\) with the true \(V\). With a terminal verifier reward, \(A_t\) is the change in predicted success caused by token \(t\).

We only have a learned \(V_\phi\). The \(k\)-step estimate \(\hat A^{(k)}_t = \sum_{l<k}\gamma^l\delta_{t+l}\) trades bias (\(k\) small, critic errors) against variance (\(k\) large, noisy returns). GAE takes the geometric average \((1-\lambda)\sum_k\lambda^{k-1}\hat A^{(k)}\), which collapses to \(\hat A_t = \sum_{l\ge0}(\gamma\lambda)^l\delta_{t+l} = \delta_t + \gamma\lambda\hat A_{t+1}\), an \(O(T)\) backward recursion. \(\lambda = 0\) gives \(\delta_t\), \(\lambda = 1\) gives the Monte-Carlo return minus \(V\). The paper's key point: \(\gamma<1\) biases the objective whatever \(V\) is, while \(\lambda<1\) biases only through critic error. The critic is trained on \(\hat A + V_{\text{old}}\).

Core Explain PPO's clipped objective. What happens for positive and negative advantages?

With \(\rho_t = \pi_\theta(a_t|s_t)/\pi_{\text{old}}(a_t|s_t)\), the per-token objective is \(\min(\rho_t\hat A_t,\ \clip(\rho_t,1-\epsilon,1+\epsilon)\hat A_t)\), \(\epsilon\approx0.2\). It equals \(\rho\hat A\) near \(\rho=1\), so the first step is the ordinary policy gradient.

\(\hat A>0\): the objective is \(\hat A\min(\rho, 1+\epsilon)\). Once \(\rho>1+\epsilon\) it is flat: gradient zero, no reward for making a good token even more likely. If \(\rho<1-\epsilon\) (the good token got less likely) the unclipped term is the min, so the gradient stays and pushes it back up. \(\hat A<0\): mirror image. Below \(1-\epsilon\) it is flat (already pushed down enough); above \(1+\epsilon\) the unclipped term is smaller, so the gradient continues to push the token down. The min is what keeps the recovery direction alive: we ignore a ratio change only when it would improve the objective, never when it would worsen it, so the objective is a pessimistic lower bound on the surrogate.

Numerically with \(\epsilon=0.2\), \(A=+1\): \(\rho=1.3\) gives \(L=1.2\), gradient 0; \(\rho=0.5\) gives \(L=0.5\), gradient \(\rho A\). It does not enforce the band; it only removes the incentive.

Core Compare the k1, k2, k3 KL estimators.

Samples \(a\sim\pi_\theta\), \(r = \pi_{\text{ref}}(a|s)/\pi_\theta(a|s)\), target \(\KL(\pi_\theta\|\pi_{\text{ref}})\) (Schulman). k1 \(= -\log r\): unbiased, but negative whenever \(\pi_\theta<\pi_{\text{ref}}\) on the sample, so high variance (std 20 times the KL at KL 0.005). k2 \(= \frac12(\log r)^2\): nonnegative, low variance, biased, but small for nearby policies (0.2% of the KL at KL 0.005, 25% at KL 0.5) because its expectation is an \(f\)-divergence with \(f''(1)=1\), which agrees with the KL to second order. k3 \(= (r-1)-\log r\): k1 plus the zero-mean control variate \(r-1\); unbiased, nonnegative (\(\log r\le r-1\)), and about as low-variance as k2 (std 1.42 and 1.7 times the KL in the two Gaussian cases).

Caveats. When \(r\) can be large (policy suppressed tokens the reference likes) k3's tail is heavy: in a 3-token example its std was 0.87 against k1's 0.52. As gradients: a k1 loss has zero expected gradient, a k2 loss has the exact gradient of \(\KL(\pi_\theta\|\pi_{\text{ref}})\), a k3 loss has the gradient of \(\KL(\pi_{\text{ref}}\|\pi_\theta)\). Usage: k1 in the reward (PPO/InstructGPT), k3 in the loss (GRPO).

Core Why is RL on LLMs usually "bandit-like", and what does that imply for credit assignment?

The reward is attached to the whole response, and transitions are deterministic, so nothing in the environment differentiates between tokens. Formally, with \(\gamma=1\) and a terminal reward, \(G_t = R\) for every \(t\), and \(\E[\sum_t\nabla\log\pi_t\,R] = \E[R\,\nabla\log\pi(y|x)]\): the bandit gradient. InstructGPT literally describes its environment as a bandit. Ahmadian et al. argue partial sequences need not be modeled and get better results from REINFORCE/RLOO than from PPO in their RLHF setup.

The implication: with a group or moving-average baseline every token of a response gets the same advantage. A token's update is the correlation of its presence with the outcome, and it becomes informative only across many samples per prompt. Most tokens do not decide the outcome, so gradient noise grows with length. To localize credit you need something token-level: a critic (\(A_t=\delta_t\) is the change in predicted success, but the critic is hard to train on sparse terminal rewards, and \(\lambda<1\) starves early tokens), a process reward model, or per-token KL terms (which are token-level but carry no task information). VAPO argues an engineered critic reaches a higher ceiling; that is one group's result.

Core On-policy versus off-policy: where does PPO sit, and why does that matter for sample reuse?

The policy gradient theorem requires samples from the current policy: on-policy. PPO collects a batch with \(\pi_{\text{old}}\) and then takes several minibatch or epoch updates, during which \(\pi_\theta\) drifts from \(\pi_{\text{old}}\): mildly off-policy. The importance ratio \(\rho_t\) reweights each token to its probability under \(\pi_\theta\), and the clip limits how far the data may go stale. Exactly on-policy at the first update (\(\rho=1\)), increasingly off-policy afterwards.

It matters because generation is the expensive part: reuse divides the cost per update. InstructGPT takes 8 minibatches per batch, Ziegler et al. and Huang et al. 4 epochs. The costs: the ratio corrects only action probabilities at visited prefixes, not the shift in which prefixes occur (so the surrogate is first-order), stale samples need clipping or masking, and the mismatch is worse with asynchronous rollouts or different numerics in sampler and trainer (page 25). DeepSeekMath does a single update per batch, so the clip is inactive and the algorithm is on-policy.

Core Calculate: for a 4-token response with \(\gamma=1\), terminal reward 1 and critic values \(V(s_1..s_4)=0.4, 0.5, 0.6, 0.9\), compute GAE for \(\lambda=0.9\) and \(\lambda=1\). What changes if the critic outputs 0?

\(V(s_5)=0\). Residuals: \(\delta_1 = 0.5-0.4 = 0.1\), \(\delta_2 = 0.6-0.5 = 0.1\), \(\delta_3 = 0.9-0.6 = 0.3\), \(\delta_4 = 1+0-0.9 = 0.1\).

\(\lambda=0.9\), backward: \(\hat A_4 = 0.1\); \(\hat A_3 = 0.3+0.9\cdot0.1 = 0.39\); \(\hat A_2 = 0.1+0.9\cdot0.39 = 0.451\); \(\hat A_1 = 0.1+0.9\cdot0.451 = 0.5059\). \(\lambda=1\): \(\hat A_t = 1-V(s_t) = 0.6, 0.5, 0.4, 0.1\) (check: \(0.1+0.1+0.3+0.1 = 0.6\)).

If \(V\equiv0\), all intermediate residuals vanish, so \(\hat A_t = \lambda^{4-t}\): \(0.729, 0.81, 0.9, 1\) for \(\lambda=0.9\) and all ones for \(\lambda=1\); \(\lambda=0\) credits only the last token. The decay factor per token is \(\lambda\), which for a 1,000-token response with \(\lambda=0.95\) is \(5\times10^{-23}\): only bootstrapping through the critic can carry credit to early tokens.

Core Show that PPO with one update per batch reduces to vanilla policy gradient. When does the clip actually matter?

Before any update \(\theta = \theta_{\text{old}}\), so \(\rho_t = 1\) for every token, inside the band. The gradient of \(\rho_t\hat A_t\) is \(\rho_t\hat A_t\nabla\log\pi_\theta = \hat A_t\nabla\log\pi_\theta\): the policy gradient with advantage \(\hat A\). With a single update per batch the clip is never active, which is why DeepSeekMath's analysis sets \(\pi_{\text{old}} = \pi_\theta\) and drops the min and the clip. (In practice you need identical numerics between the pass that produced \(\log\pi_{\text{old}}\) and the training pass: dropout off, same kernels.)

The clip matters only when \(\rho\ne1\): several updates per batch, asynchronous or stale rollouts, or numerics mismatch. Ahmadian et al. measured clipping active on under 5% of tokens in RLHF and saw no loss when removing it. In the PPO paper's MuJoCo setup (10 epochs over each batch) it matters: with neither clip nor penalty the normalized score was \(-0.39\). Monitor the clip fraction: near zero means the clip is decorative, large means the updates are too aggressive for the data reuse.

Deep-dive Design question: a PPO run on a verifiable-reward reasoning task shows response length collapsing within a few hundred steps and validation accuracy falling. How do you diagnose and fix it?

Length collapse with a verifier means the policy is being paid to be short, and the KL is not the cause (\(\beta\) is 0 or tiny). Candidates, in order of what to check: (1) Advantage versus token position. Plot the mean advantage by position: VC-PPO found a strong positive bias at early tokens, growing toward the start. (2) Critic initialization: a critic copied from a reward model, trained only to score EOS, undervalues early prefixes, so \(\delta_t\) is positive on average and accumulates backward. (3) \(\lambda<1\): the terminal reward reaches early tokens as \(\lambda^{T-t}\), so the advantage is dominated by these biased bootstrap terms. (4) Loss normalization: \(1/|o_i|\) penalizes long wrong answers less per token.

Fixes: pretrain the critic on Monte-Carlo returns (\(\lambda=1\)) of a fixed policy until explained variance is high; decouple GAE (\(\lambda_{\text{critic}}=1\) for the regression target, \(\lambda_{\text{actor}}\approx0.95\) for the policy), or use a length-adaptive \(\lambda\); use a token-level or constant-normalized loss; verify truncation handling. In VC-PPO's 8k ablation, PPO reached 5.6 on AIME 2024, value pretraining alone 29.4 and with decoupled GAE 41.9, above GRPO's 35.8 (single lab, small benchmark). The fallback is to drop the critic for a group baseline.

Deep-dive Why does putting k3 in the loss not give the gradient of \(\KL(\pi_\theta\|\pi_{\text{ref}})\)? Derive it, and say what you would do instead.

Autodiff differentiates the integrand with the sampled token frozen, but \(\nabla\E_{a\sim\pi_\theta}[k] = \E[\nabla k] + \E[k\,\nabla\log\pi_\theta]\): it misses the score-function term. With \(r = \pi_{\text{ref}}/\pi_\theta\) and \(\nabla r = -r\nabla\log\pi_\theta\): \(\nabla k_3 = (1-r)\nabla\log\pi_\theta\), so \(\E_\pi[\nabla k_3] = -\E_\pi[r\nabla\log\pi] = -\sum_a\pi_{\text{ref}}(a)\nabla\log\pi_\theta(a) = \nabla\KL(\pi_{\text{ref}}\|\pi_\theta)\): the other direction. By contrast \(\nabla k_1 = \nabla\log\pi_\theta\) has zero mean, and \(\nabla k_2 = \ell\nabla\log\pi_\theta\) with \(\ell=\log(\pi_\theta/\pi_{\text{ref}})\) has expectation \(\nabla\KL(\pi_\theta\|\pi_{\text{ref}})\). A 3-token check: target gradient \((-0.0985,-0.1670,0.2655)\); k2 gives the same, k3 gives \((-0.0464,-0.1855,0.2319)\), which equals the reverse-direction KL gradient.

Two more gaps: a per-token loss omits the effect of \(a_t\) on later tokens' KL (the \(\sum_{s>t}\ell_s\) terms), and after the first minibatch the samples come from \(\pi_{\text{old}}\). Options: put k1 in the reward (exact on-policy, includes future KL via returns); or use the estimator in both reward and loss; or use k2 as a token-level loss; or keep k3 but multiply by \(\pi_\theta/\pi_{\text{old}}\) as DeepSeek-V3.2 does. Empirically (Shah et al.), k1-in-reward beat k3-in-loss, which was stable but consistently worse; at very small \(\beta\) the gaps are small.

Deep-dive What does the PPO clip not guarantee? How would you detect and fix ratio blow-ups in a large RL run?

It does not bound \(\rho\). It only zeroes the gradient of tokens that are already outside the band on the improving side. Engstrom et al. found the maximum ratio consistently exceeding \(1+\epsilon\) on MuJoCo and argued that the effective trust region depends on the optimizer. On the worsening side there is no cap at all: for \(\hat A<0\) and \(\rho>1+\epsilon\) the gradient is \(\rho\hat A\nabla\log\pi\), which grows with \(\rho\), so one exploded ratio produces a huge update.

Sources: too many epochs or too high a learning rate; Adam momentum; dropout; \(\log\pi_{\text{old}}\) from a sampler whose numerics or truncation (top-p) differ from the trainer's; in MoE models, routing that changes after a few updates (Qwen reports about 10% of activated experts changing per update on Qwen3-30B-A3B). Detection: log the maximum and 99th-percentile ratio, clip fraction, old-versus-new approximate KL, and ratio on the first minibatch (must be 1). Fixes: recompute \(\log\pi_{\text{old}}\) in the trainer with the same masks and temperature; disable dropout; fewer or smaller updates; gradient clipping; mask sequences whose mean log-ratio exceeds a threshold (DeepSeek-V3.2's off-policy sequence masking for negative-advantage samples); for MoE, replay the routing (Keep Routing) or use a sequence-level ratio (GSPO).

Deep-dive Trade-off: would you choose PPO with a critic or a critic-free method (RLOO or GRPO) for (a) chat RLHF with a learned reward model and (b) long-CoT RL with a verifier?

Costs. PPO keeps four models (about 36 bytes per parameter of model state for an 8B policy with a same-size critic and RM) against 20 for GRPO with an RM and 16 for a verifier without KL. Critic-free methods spend the saving on \(G\) samples per prompt, which raises generation cost, and prompts whose samples are all correct or all wrong give zero advantage (DAPO's dynamic sampling filters them). PPO can use one sample per prompt.

(a) Chat RLHF, responses of hundreds of tokens, dense scalar RM scores. The critic is easier to train at this length and PPO is the reference method, but Ahmadian et al. found RLOO beat their PPO on TL;DR and HH (e.g. 77.9 versus 67.6 win rate) with less memory. I would start with RLOO or GRPO with KL in the reward or a corrected k3 and reach for PPO if variance or credit assignment is the bottleneck. Watch reward hacking and length bias (page 23). (b) Long CoT with a binary verifier. Critic training is hard and \(\lambda<1\) starves early tokens, so a group baseline is the robust default (with token-level or constant normalization, clip-higher, and \(\beta=0\)). A carefully engineered critic (value pretraining, decoupled and length-adaptive GAE) reportedly wins (VAPO 60.4 versus DAPO 50 on AIME 2024), but that is one group's result on one benchmark and needs expertise and budget. I would decide by measuring critic explained variance early: if it stays low, use the group baseline.

Cheat sheet

  • MDP: \(s_t = (x, y_{<t})\), \(a_t = y_t\), deterministic transitions, reward at EOS (plus per-token KL), \(\gamma = 1\). \(\pi_\theta\) is the LM.
  • Policy gradient: \(\nabla J = \E[\sum_t\nabla\log\pi(a_t|s_t)\,G_t]\); baseline \(b(s_t)\) is free (lemma: \(\E_a[\nabla\log\pi(a|s)] = 0\)); terminal reward gives \(G_t = R\), the bandit gradient.
  • Advantage \(A = Q - V\); in an LLM \(A_t = \delta_t = r_t + V(s_{t+1}) - V(s_t)\) exactly. Optimal scalar baseline \(\E[\|\nabla\log\pi\|^2G]/\E[\|\nabla\log\pi\|^2]\approx V\).
  • GAE: \(\hat A_t = \sum_l(\gamma\lambda)^l\delta_{t+l} = \delta_t + \gamma\lambda\hat A_{t+1}\). \(\lambda=0\): \(\delta_t\); \(\lambda=1\): return minus \(V\). \(\gamma<1\) always biases, \(\lambda<1\) only via critic error. Terminal reward with \(V=0\): \(\hat A_t = \lambda^{T-t}R\).
  • Toy MDP numbers: \(\nabla J = (0.125, 0, 0.125)\); variance 0.094 / 0.0625 / 0.047 for \(b\) = 0 / \(J\) / \(V(s_t)\). GAE 5-token example: \(\hat A_1 = 0.61012\) (\(\lambda=0.95\)), \(0.70\) (\(\lambda=1\)).
  • PPO: \(\rho = \pi_\theta/\pi_{\text{old}}\); \(L = \min(\rho A, \clip(\rho, 1\pm\epsilon)A)\), \(\epsilon = 0.2\). \(A>0\): flat above \(1+\epsilon\); \(A<0\): flat below \(1-\epsilon\); the other sides keep their gradient. Not a hard constraint; first minibatch has \(\rho = 1\).
  • Critic: head on the hidden state at the position that emits \(a_t\); loss \(\tfrac12(V - \hat R)^2\), \(\hat R = \hat A + V_{\text{old}}\); value clipping is contested; VC-PPO: \(\lambda_{\text{critic}}=1\), \(\lambda_{\text{actor}}=0.95\), value pretraining.
  • KL: reward form \(r_t = -\beta(\log\pi_\theta - \log\pi_{\text{ref}})\) (k1, exact gradient); loss form \(\beta k_3\) (GRPO, \(\beta=0.04\)). \(\beta\): 0.02 (InstructGPT), 0.05 (Huang), 0 for verifier long-CoT. Adaptive: \(\beta \leftarrow \beta(1 + 0.1\,\clip(\cdot,\pm0.2))\).
  • Estimators (samples \(\sim\pi_\theta\), \(r = \pi_{\text{ref}}/\pi_\theta\)): \(k_1 = -\log r\) (unbiased, noisy), \(k_2 = \tfrac12\log^2 r\) (biased, low var), \(k_3 = r - 1 - \log r\) (unbiased, \(\ge0\), heavy tail if \(r\gg1\)). As losses: k1 gives 0, k2 gives \(\nabla\KL(\pi\|\pi_{\text{ref}})\), k3 gives \(\nabla\KL(\pi_{\text{ref}}\|\pi)\).
  • Level: credit (per token vs per response), ratio (token \(\rho_t\) vs GSPO \(\rho^{1/|y|}\)), loss normalizer (\(1/|o_i|\) vs token-mean vs constant). Memory per 8B policy: PPO 36 B/param, GRPO+RM 20, verifier no KL 16.
